# 贵州景区旅游产品模型

> 用途：AI根据旅客分析模型（消费水平 × 出行目的）自动匹配推荐景区产品  
> 版本：v1.0  
> 生成时间：2026-06-12  
> 遵守规则：陶总五大反对 + 禁用词语表 + 五步法框架

---

## 一、业务目标

| 目标 | 关键动作 | 衡量标准 |
|------|----------|----------|
| **目标1：产品可被AI识别和调用** | 每个产品定义清晰的消费区间、体力门槛、体验类型、季节适配标签 | 输入旅客画像后，AI能在1秒内完成匹配，准确率≥85% |
| **目标2：匹配结果有说服力** | 产品对比维度标准化，推荐理由可解释、可验证 | 推荐时附带3条客观匹配理由，用户可追问“为什么推荐这个” |
| **目标3：覆盖贵州主力景区80%以上** | 梳理Top 10核心景区，按体验本质分类，不遗漏主力选择 | 产品库覆盖到访人次前10景区，产品类型覆盖全部出行目的 |

## 二、标杆分析（简要）

| 标杆 | 做法提炼 | 可借鉴 |
|------|----------|--------|
| **携程/飞猪产品标签体系** | 每个SKU带"适合人群""游玩强度""消费区间"标准化标签 | 借鉴标签结构，但景区级粒度更粗（不拆到单个SKU） |
| **日本观光厅「访日游客分类模型」** | 按消费水平×旅行目的×兴趣偏好三维匹配推荐区域 | 三维矩阵匹配思路，但压缩为两维（消费×目的）降低复杂度 |
| **新加坡圣淘沙「游客画像-产品映射表」** | 每个产品写明白"适合谁、不适合谁"，直接对应画像 | 借鉴"不适合谁"的反向排除设计，提高匹配精准度 |

**核心借鉴：产品卡片必须同时回答「适合谁」和「不适合谁」，让匹配有双向校验。**

## 三、数据关联（旅客分析模型 → 产品匹配）

| 旅客分析输出 | 数据类型 | 产品模型调用方式 | 自动/人工 |
|-------------|----------|-----------------|-----------|
| 消费水平（经济/舒适/品质/奢华） | 离散标签 | 直接匹配产品卡片的「消费区间」字段 | 自动 |
| 出行目的（打卡/文化/休闲/亲子/冒险） | 离散标签 | 直接匹配产品卡片的「适配目的」字段 | 自动 |
| 体力状况（有限/中等/充沛） | 离散标签 | 匹配「体力门槛」字段，不匹配则降级推荐 | 自动 |
| 停留天数（1-3天/4-7天/8天+） | 数值 | 匹配「建议停留时长」字段，过短则提示体验不足 | 自动 |
| 出行季节 | 时间 | 匹配「最佳季节」字段，非最佳季节给出预警提示 | 自动 |
| 同行人员（独行/情侣/家庭/老人团） | 离散标签 | 匹配「适配人群」字段，老人/儿童触发安全提示 | 自动 |

**目标：自动匹配比例100%，零人工介入。**

## 四、产品模型（核心）

### 4.1 模型定义

**产品模型 = 围绕"让AI给旅客匹配合适产品"这一目的，把贵州景区提炼成可调用、可对比、可验证的标准化原子库。**

**设计原则：**
- 从**旅客视角**出发，不是从景区管理方视角出发
- 每个产品回答三个问题：这是什么体验？适合什么旅客？不适合什么旅客？
- 不堆砌信息，只保留匹配决策必需的关键信息

---

### 4.2 产品分类（按体验本质分，不按行政区划分）

| 产品大类 | 本质特征 | 包含景区 | 典型体验 |
|----------|----------|----------|----------|
| **A类：自然奇观** | 视觉震撼，自然力量，体力消耗中到高 | 黄果树瀑布、荔波小七孔、梵净山、马岭河峡谷、织金洞、赤水丹霞、百里杜鹃 | 壮观、惊叹、拍照、轻度挑战 |
| **B类：文化沉浸** | 人文深度，慢节奏，体验参与感 | 西江千户苗寨、镇远古镇、青岩古镇 | 了解、参与、品味、情感连接 |
| **C类：生态度假** | 放松恢复，环境清幽，低强度 | 荔波（大七孔/茂兰）、赤水竹海、石阡温泉 | 休息、呼吸、慢活、自然疗愈 |

#### A1. 黄果树瀑布（安顺）

| 字段 | 内容 |
|------|------|
| **产品名称** | 黄果树瀑布 |
| **产品大类** | A类：自然奇观 |
| **核心体验** | 亚洲最大瀑布的正面冲击，水帘洞穿行体验，从六个观景台不同角度感受瀑布力量 |
| **体力门槛** | 中等（步行2-3小时，台阶较多，水帘洞需弯腰穿行） |
| **消费区间** | 经济型（门票+基础交通）/ 舒适型（含扶梯）/ 品质型（VIP通道+讲解） |
| **建议停留** | 0.5-1天 |
| **适配出行目的** | 打卡观光、亲子陪伴（儿童≥6岁）、挑战冒险（轻量级） |
| **不适配出行目的** | 纯休闲度假（强度偏高）、文化探索（自然为主，人文单薄） |
| **适配消费水平** | 经济型～品质型（门票基础，弹性空间大） |
| **最佳季节** | 6-10月（水量充沛，气势最大）；3-5月水量较小但清秀；冬季水量小，门票打折 |
| **配套条件** | 贵阳出发2小时车程；景区内有扶梯（省力）；安顺市区住宿经济型为主；餐饮以黔菜为主 |
| **产品画像标签** | 必打卡、贵州名片、视觉冲击、体力中等、性价比高、家庭友好（大龄儿童） |
| **反向排除** | 老人腿脚不便者慎选（台阶多）；带婴幼儿不推荐；追求私密安静者不推荐（游客密集） |

## 五、AI自动匹配规则（动作模型）

### 5.1 匹配动作定义

**事件：旅客画像输入 → 产品推荐输出**

**触发条件：** 旅客分析模型已输出「消费水平」+「出行目的」+「体力状况」+「停留天数」+「同行人员」+「出行季节」

**匹配步骤：**

1. **目的初选**：根据出行目的，从"出行目的匹配速查表"筛选候选产品池（首选+次选）
2. **消费过滤**：从候选池中剔除消费水平弹性上限低于旅客预算的产品
3. **体力校验**：体力状况"有限" → 剔除体力门槛"中等"及以上；"中等" → 可保留"中等"；"充沛" → 全保留
4. **季节校验**：出行季节非产品最佳季节 → 不剔除，但附加预警提示（如"冬季黄果树水量小，建议调整预期"）
5. **人群校验**：同行人员含老人/幼儿 → 剔除梵净山、马岭河；含婴幼儿 → 额外剔除水帘洞类涉水景点
6. **天数组合**：停留天数决定推荐数量：1-3天推荐1-2个核心产品，4-7天推荐3-4个产品，8天+推荐5-6个产品
7. **组合优化**：多个产品推荐时，优先组合不同大类（自然+文化互补），避免同类堆砌；优先地理相邻组合（如黄果树+织金洞=安顺方向；小七孔+西江=黔东南方向）
8. **输出推荐**：Top 3推荐 + 每条推荐理由 + 1条反向排除提醒

**输出格式：**

```
推荐1：【产品名】（匹配度：90%）
- 匹配理由1：消费水平=舒适型，该产品弹性区间完全覆盖
- 匹配理由2：出行目的=亲子陪伴，该产品全年龄友好且有亲水体验
- 匹配理由3：4月出行=该产品最佳季节，水量充沛
- 注意：需携带防滑鞋，谷底栈道有湿滑段

推荐2：【产品名】（匹配度：75%）
...

不推荐：【产品名】
- 原因：体力门槛高，旅客画像中体力状况=有限，不符合
```

**异常处理：**
- 如果经过6步过滤后候选池为空 → 触发"降级匹配"：降低体力要求或消费弹性，附加风险提示
- 如果旅客画像不完整 → 追问缺失字段（"请确认出行季节，部分产品季节性极强"）

**时限：** 单次匹配响应时间 ≤ 1秒
