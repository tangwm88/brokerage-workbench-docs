# 零售业务动作模型重新梳理 v2：从认知功能到操作流程

> 对比分析：v4.1的"触达/诊断/建议/执行" vs 实际可操作的"接收/准备/拜访/登记/跟踪"

---

## 一、问题：v4.1的4个原子动作偏"认知"而非"操作"

v4.1把动作模型收敛为4个：
- 触达（建立联系）
- 诊断（分析评估）
- 建议（方案输出）
- 执行（业务落地）

**问题：**
1. **"诊断"和"建议"是思考过程，不是可执行动作** — 一线人员拿到的是"去拜访客户"，不是"去诊断"和"去建议"
2. **缺少明确的操作流程** — 没有"接收任务"的起点，没有"准备"阶段，没有"跟踪"闭环
3. **"执行"太泛** — 产品配置要双录下单是执行，登记拜访结果也是执行，混在一起

---

## 二、更优解：5个标准操作步骤（从一线实际流程出发）

### 客户经理的一天实际流程：

```
早会 → 接收今日任务单 → 访前准备 → 拜访客户 → 登记结果 → 跟踪反馈
```

无论面对什么客户、什么场景，都是这个流程。

### 5个标准步骤：

| 步骤 | 动作名称 | 核心内容 | 为什么共性 |
|------|---------|---------|-----------|
| **1** | **接收客户服务任务** | 从系统接收任务单，确认客户标签、触发原因、优先级 | 所有人工服务都从任务单开始 |
| **2** | **访前准备** | 调客户数据、看持仓/状态、备沟通要点、备材料 | 所有拜访前都要准备 |
| **3** | **拜访客户** | 面访/电访/企微触达，沟通方案，处理异议 | 所有服务的核心执行环节 |
| **4** | **登记结果** | 记录拜访时间/渠道/内容/客户反馈/下一步计划 | 所有服务必须留痕 |
| **5** | **跟踪反馈** | 设置下次跟进时间、推送承诺材料、更新客户状态 | 所有服务必须闭环 |

### "诊断"和"建议"去哪了？

**内嵌在步骤中，不显式作为独立动作：**

- **诊断 → 内嵌在"访前准备"**
  - 调数据时自动完成：资金诊断+持仓诊断+需求诊断+关系诊断
  - 输出：客户现状摘要（嵌入任务单）
  
- **建议 → 内嵌在"拜访客户"**
  - 沟通要点中包含方案讲解
  - 客户异议处理中体现专业建议
  
- **执行（双录下单等）→ 内嵌在"拜访客户"或作为拜访后的子步骤**
  - 产品配置场景：拜访中完成双录
  - 普通服务场景：无需额外执行

---

## 三、两种方案的对比

| 维度 | v4.1方案（4个认知动作） | 新方案（5个操作步骤） |
|------|----------------------|-------------------|
| **抽象层级** | 认知功能（诊断/建议/执行） | 操作流程（接收/准备/拜访/登记/跟踪） |
| **一线可执行性** | 弱（"去诊断客户"不是标准话术） | 强（"接收任务→准备→拜访→登记→跟踪"是标准SOP） |
| **闭环完整性** | 缺"跟踪" | 有"跟踪反馈" |
| **任务起点** | 不明确 | "接收任务"明确起点 |
| **准备阶段** | 隐含在触达中 | "访前准备"独立步骤 |
| **场景适配** | 每个场景重新定义动作组合 | 所有场景共用同一5步流程，内容不同 |

## 四、场景如何用5步流程表达

### 场景1：首触服务（新客首触）

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"新客首触任务单"：客户标签+开户信息+触发原因 |
| **访前准备** | 调取客户开户资料、风险测评结果、资产情况；准备首触话术（欢迎+了解需求+首单推荐） |
| **拜访客户** | 渠道：企微/电话；内容：自我介绍+了解投资经验+介绍服务+推荐首单低风险产品 |
| **登记结果** | 记录触达时间/渠道/客户反馈/投资需求/是否接受首单推荐 |
| **跟踪反馈** | 7日内跟进首单激活情况；如未激活，二次触达 |

### 场景2：大额亏损关注服务

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"大额亏损关注任务单"：客户标签+亏损数据+触发原因（近3月收益=-22%） |
| **访前准备** | 调取持仓明细、亏损归因分析、集中度风险、历史服务记录；准备关怀话术（禁止承诺回本） |
| **拜访客户** | 渠道：电话/面谈；内容：主动关怀+客观分析亏损原因+推送诊断报告+给优化建议 |
| **登记结果** | 记录触达时间/渠道/客户情绪/是否接受建议/异议内容 |
| **跟踪反馈** | 3日内推送资产优化方案；7日内跟进客户操作情况；持续跟踪状态变化 |

### 场景3：产品配置服务

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"产品配置任务单"：客户标签+适当性结果+配置需求 |
| **访前准备** | 调取客户资产/风险等级/历史配置；准备配置方案书+风险揭示材料+双录设备 |
| **拜访客户** | 渠道：面谈；内容：方案讲解+风险揭示+适当性确认+双录+客户签署 |
| **登记结果** | 记录方案内容+客户确认意见+双录编号+签署文件编号 |
| **跟踪反馈** | 产品成立后推送确认信息；定期跟踪持仓表现；设置下次复盘时间 |

## 五、5步流程的七事件格式（通用模板）

### 步骤1：接收客户服务任务

```
事件名称：接收客户服务任务
触发条件：
  - 条件A：系统自动推送任务单（模型触发）
  - 条件B：团队长手动分配任务
  - 条件C：客户经理主动认领
执行步骤：
  1. 查看任务单详情（客户姓名/标签/触发原因/优先级/时限）
  2. 确认任务可执行性（自身权限/客户归属/时间冲突）
  3. 接受任务，系统记录接收时间
输出标准：
  - 任务接收记录：接收时间/客户经理/任务类型/客户信息
异常处理：
  - 任务分配错误→退回任务，说明原因
  - 时间冲突→申请延期或转交同事
  - 客户已流失/销户→标记失效，归档
时限要求：任务推送后2小时内确认接收
验收标准：任务已接收+客户信息已查看+无冲突
```

### 步骤2：访前准备

```
事件名称：访前准备
触发条件：
  - 条件A：接收任务后默认触发
  - 条件B：拜访前1小时提醒
执行步骤：
  1. 调取客户全景数据（资产/持仓/交易/历史服务记录）
  2. 查看客户分析标签（资金体量/交易倾向/当前状态/生命周期）
  3. 分析客户现状（系统自动输出诊断摘要）
  4. 准备沟通要点（根据场景调用话术模板）
  5. 准备相关材料（方案书/风险揭示书/产品资料）
  6. 确认拜访渠道和时间（企微/电话/面谈）
输出标准：
  - 准备清单：客户摘要/沟通要点/材料清单/拜访计划
异常处理：
  - 客户数据缺失→标记缺失项，基于已有信息准备+拜访中补充
  - 话术模板不匹配→人工调整，记录优化建议
  - 客户临时改期→更新拜访计划
时限要求：拜访前30分钟完成准备
验收标准：客户数据已调取/沟通要点已确认/材料已备齐/渠道时间已确认
```

### 步骤3：拜访客户

```
事件名称：拜访客户
触发条件：
  - 条件A：访前准备完成后按计划执行
  - 条件B：客户临时发起沟通
执行步骤：
  1. 执行触达（按确认的渠道：企微/电话/面谈）
  2. 说明拜访目的（基于任务单触发原因）
  3. 沟通核心内容（讲解方案/处理异议/提供服务）
  4. 确认客户意向（接受/拒绝/犹豫/需再考虑）
  5. 约定下一步（如需：下次拜访时间/需补充材料/客户需做决策）
输出标准：
  - 拜访记录：时间/渠道/时长/核心内容/客户反馈/客户意向/下一步计划
异常处理：
  - 客户拒接/爽约→3日内二次触达（换渠道）
  - 客户情绪激动/投诉→升级团队长/合规部门
  - 客户当场要求业务办理（如产品配置）→按业务规程执行双录/签约
时限要求：按任务单要求（紧急24小时内/常规72小时内）
验收标准：拜访已完成+核心内容已传达+客户意向已确认+下一步已约定
```

### 步骤4：登记结果

```
事件名称：登记结果
触发条件：
  - 条件A：拜访完成后即时触发（默认）
  - 条件B：系统定时提醒补录
执行步骤：
  1. 填写拜访记录（时间/渠道/时长/内容摘要）
  2. 记录客户反馈（态度/意见/异议/需求）
  3. 记录客户意向（接受/拒绝/犹豫/待跟进）
  4. 上传相关附件（录音/截图/签署文件/方案书）
  5. 提交登记，系统归档
输出标准：
  - 完整拜访档案：记录+反馈+意向+附件
异常处理：
  - 忘记登记→系统24小时后提醒补录
  - 记录不完整→系统校验提示补充
  - 客户后续反悔→更新记录，标记变更
时限要求：拜访完成后2小时内完成登记
验收标准：记录完整+反馈清晰+意向明确+附件齐全+已归档
```

### 步骤5：跟踪反馈

```
事件名称：跟踪反馈
触发条件：
  - 条件A：拜访登记后自动生成跟踪计划（默认）
  - 条件B：约定跟进时间到达
  - 条件C：客户状态发生变化（资产/持仓/生命周期）
执行步骤：
  1. 查看跟踪计划（系统根据场景自动生成）
  2. 执行跟踪动作（推送材料/电话回访/面访跟进）
  3. 更新客户状态（标签更新/生命周期变化/需求变化）
  4. 评估服务效果（客户满意度/业务转化率/状态改善）
  5. 闭环确认（服务完成/转入下一周期/升级处理）
输出标准：
  - 跟踪记录：跟踪时间/动作/客户反馈/状态变化/效果评估
异常处理：
  - 客户无响应→3日后再次跟踪，换渠道
  - 客户状态恶化（如亏损扩大）→升级优先级，重新触发服务
  - 跟踪中客户提出新需求→生成新任务单
时限要求：按跟踪计划执行（一般3-7日内首次跟踪）
验收标准：跟踪已执行+状态已更新+效果已评估+已闭环或转入下周期
```

## 六、推荐结论

**采用"5个标准操作步骤"替代"4个认知功能动作"。**

理由：
1. **更贴近一线实际** — 客户经理每天的工作就是"接任务→准备→拜访→登记→跟踪"
2. **更可操作** — 每个步骤都有明确的输入、输出、时限、验收标准
3. **更共性** — 所有场景共用同一5步流程，差异只在每步的具体内容
4. **更闭环** — "跟踪反馈"确保服务有始有终
5. **诊断和建议不消失** — 内嵌在"访前准备"和"拜访客户"中，不显式作为独立动作，但要求不减

---
