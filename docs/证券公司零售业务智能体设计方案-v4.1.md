# 证券公司零售业务智能体设计方案 v4.1

> **面向角色：** 投资者（被服务方）+ 客户经理（执行方）+ 团队长（管理方）
> **核心目标：** 模型自动化服务大部分客户，前台团队服务动作按需叠加
> **设计依据：** 陶总方法论 + 统一参考方法论 + 架构图v2.0 + 禁用词语表
> 版本：v4.1（基于v4.0重构动作模型层）
> 时间：2026-06-19

---

## 一、先定角色和目的

### 1.1 三类角色

| 角色 | 定位 | 核心诉求 | 与模型的关系 |
|------|------|---------|------------|
| **投资者** | 服务接收方 | 获得匹配自身情况的投资服务与产品 | 被模型分析、被服务模型覆盖、接收自动化服务 |
| **客户经理** | 服务执行方 | 高效服务大量客户，重点精力投向高价值/高流失风险客户 | 执行动作模型规定的标准动作，响应模型触发的任务单 |
| **团队长** | 管理组织者 | 穿透团队服务全貌，识别风险与机会，调配资源 | 接收团队级聚合报告，审批异常处理，驱动迭代 |

### 1.2 核心目的

**一句话：让模型自动化覆盖80%客户的标准化服务，客户经理专注处理20%需要人工判断和情感连接的场景。**

```
┌─────────────────────────────────────────────────────────────┐
│  自动化服务层（模型驱动，无需人工介入）                        │
│  ├─ 客户自动分层与标签更新                                    │
│  ├─ 标准化信息推送（市场动态/持仓提醒/产品匹配）              │
│  ├─ 常规投后报告自动生成与发送                                │
│  ├─ 沉睡客户自动唤醒触达                                    │
│  └─ 覆盖客群：80%                                           │
├─────────────────────────────────────────────────────────────┤
│  人工叠加层（客户经理执行，模型触发任务单）                    │
│  ├─ 高价值客户深度服务                                      │
│  ├─ 大额亏损关注与跟踪                                      │
│  ├─ 复杂产品配置方案沟通                                    │
│  ├─ 流失预警客户挽回                                        │
│  └─ 覆盖客群：20%                                           │
└─────────────────────────────────────────────────────────────┘
```

## 二、三层模型体系

### 2.1 模型总览

```
零售业务智能体
├── 第一层：客户分析模型（4个本质维度）
│   ├── 维度1：资金体量
│   ├── 维度2：交易倾向
│   ├── 维度3：当前状态
│   └── 维度4：生命周期
├── 第二层：服务模型（场景化组合）
│   ├── 服务模型A：自动化信息服务（100%自动）
│   ├── 服务模型B：自动化产品匹配服务（100%自动）
│   ├── 服务模型C：人工叠加服务标准（模型触发→客户经理执行）
│   │   ├── 场景1：首触服务（触达+诊断+建议）
│   │   ├── 场景2：定期复盘服务（触达+诊断+建议）
│   │   ├── 场景3：大额亏损关注服务（触达+诊断+建议）
│   │   ├── 场景4：产品配置服务（触达+诊断+建议+执行）
│   │   ├── 场景5：流失挽回服务（触达+诊断+建议）
│   │   └── 场景6：投诉处理服务（触达+诊断+建议+执行）
│   └── 服务模型D：团队管理服务（团队长执行）
└── 第三层：动作模型（4个原子动作，七事件格式）
    ├── 动作1：触达（建立联系）
    ├── 动作2：诊断（分析评估）
    ├── 动作3：建议（方案输出）
    └── 动作4：执行（业务落地）
```

### 2.2 设计原则：先原子、后组合

**v4.0的问题：** 把场景和原子混在同一层——持仓复盘、产品配置、大额亏损关注、流失挽回不是"原子动作"，是场景化的动作组合。每新增场景就要新增动作模型，导致：场景膨胀、动作之间大量重复、不体现"最共性"。

**v4.1的解法：** 第三层只放**最共性的原子动作**（4个），第二层用原子组合表达**所有场景**。

> 无论面对什么客户、什么场景，客户经理的日常工作逃不出这4个动作：触达→诊断→建议→执行。

## 三、第一层：客户分析模型

### 3.1 设计原则
- **4个本质维度**，每个维度3-5档，客户经理能记住、能使用
- **客观量化**，每档有明确的数字边界
- **直接驱动动作**，每个维度变化自动触发对应服务动作
- **系统自动更新**，标签变化由模型自动识别，无需人工维护

### 3.2 维度1：资金体量

**定位：** 客户对券商的综合价值，决定服务等级和资源配置。

| 等级 | 判定标准（月日均，三选一达标） | 服务等级 |
|------|------------------------------|---------|
| **S级** | 资产规模≥1000万，或月均创收≥3000元 | 专属客户经理+团队长关注 |
| **A级** | 资产规模300-1000万，或月均创收500-3000元 | 客户经理一对一维护 |
| **B级** | 资产规模5-300万，或月均创收50-500元 | 标准化自动化服务为主 |
| **C级** | 资产规模<5万，且月均创收<50元 | 批量自动化服务 |

**触发动作：**
- C级→B级（资产增长达标）：自动触发"服务升级通知"
- A级→S级（资产突破1000万）：自动触发"专属服务激活任务单"给团队长
- 任意等级资产连续3月下降超20%：自动触发"流失预警任务单"

### 3.3 维度2：交易倾向

**定位：** 客户的交易习惯和投资方式，决定沟通内容和服务重点。

| 类型 | 判定标准 | 核心特征 |
|------|---------|---------|
| **高频交易型** | 月换手率≥200%，或月交易笔数≥30笔 | 追求短期收益，关注市场热点和个股机会 |
| **中频波段型** | 月换手率50%-200%，或月交易笔数10-29笔 | 有一定择时能力，关注产业趋势和板块轮动 |
| **低频长期型** | 月换手率10%-50%，或月交易笔数1-9笔 | 偏向长期持有，关注企业实际质地和估值 |
| **超低频保守型** | 月换手率<10%，或月交易笔数0笔但资产>0 | 几乎不交易，以现金管理或被动持有为主 |
| **零交易型** | 月交易笔数0笔，且账户无资产 | 未激活或已流失 |

**持仓风格标签（辅助，不独立成维度）：**
- 大盘蓝筹型：蓝筹个股成交占比≥60%
- 成长赛道型：产业大盘成长成交占比≥60%
- 小盘题材型：中小盘成长/题材个股成交占比≥60%
- 红利防御型：红利个股成交占比≥60%
- 可转债型：可转债成交占比≥30%

**触发动作：**
- 低频长期型→高频交易型（交易频率连续2月提升）：自动触发"交易活跃度提升关怀"
- 高频交易型→低频长期型（交易频率连续3月下降）：自动触发"活跃度下降关注"
- 持仓风格标签变化：自动触发"持仓风格变化提醒"

### 3.4 维度3：当前状态

**定位：** 客户当前的收益状况和持仓健康度，决定当前最需要什么服务。

| 状态 | 判定标准（近3个月收益率） | 核心诉求 |
|------|------------------------|---------|
| **大幅盈利** | 收益率>15% | 止盈建议、利润保护、再配置建议 |
| **稳健盈利** | 0<收益率≤15% | 维持策略、产品渗透、提升服务体验 |
| **盈亏平衡** | -5%≤收益率≤0 | 维持信心、市场解读、避免恐慌操作 |
| **小幅亏损** | -15%<收益率<-5% | 亏损归因、持仓诊断、修复建议 |
| **深度亏损** | 收益率≤-15% | 状态关注、深度诊断、资产优化建议 |

**持仓集中度标签（辅助）：**
- 集中型：单一标的持仓占比>50%
- 适度集中：单一标的持仓占比30%-50%
- 分散型：单一标的持仓占比<30%

**触发动作：**
- 大幅盈利→深度亏损（单月跌幅超20%）：自动触发"剧烈波动关怀任务单"给客户经理
- 深度亏损持续3个月未改善：自动触发"高优先级关注任务单"
- 持仓集中度>50%且该标的近月跌幅>10%：自动触发"集中度风险提示"

### 3.5 维度4：生命周期

**定位：** 客户与公司的关系阶段，直接决定服务策略和触发动作。

| 阶段 | 判定标准 | 自动化服务占比 | 人工叠加触发条件 |
|------|---------|--------------|----------------|
| **潜在客户** | 未开户，但在线索池 | 100%自动化（线索培育） | 线索活跃度达标→分配客户经理 |
| **新客** | 开户≤30天 | 90%自动化 | 开户7天未入金→客户经理跟进 |
| **尝鲜客户** | 开户>30天，有首笔交易但近30天无交易 | 80%自动化 | 连续45天无交易→客户经理唤醒 |
| **活跃客户** | 近30天有交易 | 70%自动化 | 资产升级/状态异常→客户经理介入 |
| **沉睡客户** | 资产>0，近90天零交易 | 60%自动化 | 沉睡超180天→客户经理挽回 |
| **忠诚客户** | 开户≥1年+月均资产≥10万+近12个月有交易+累计创收≥500元 | 50%自动化 | 定期专属服务+转介绍激励 |
| **流失客户** | 已销户，或资产=0且连续180天零交易 | 归档/批量挽回 | 高价值流失→客户经理挽回 |
| **回流客户** | 曾经流失/沉睡，近30天重新入金或交易 | 70%自动化 | 回流后30天→客户经理关怀 |

**触发动作（生命周期状态变化自动触发）：**

| 变化 | 自动触发动作 | 任务单对象 |
|------|------------|----------|
| 潜在客户→新客 | 自动发送"开户欢迎+新客引导" | 系统自动化 |
| 新客→尝鲜客户（完成首单） | 自动发送"首单确认+持续服务介绍" | 系统自动化 |
| 活跃客户→沉睡客户 | 自动发送"沉睡唤醒信息"+30天后客户经理任务单 | 系统→客户经理 |
| 活跃客户→忠诚客户 | 自动发送"忠诚客户升级通知"+专属服务介绍 | 系统→客户经理 |
| 任意→流失客户 | 自动归档+高价值客户分配挽回任务单 | 团队长→客户经理 |
| 流失/沉睡→回流客户 | 自动发送"回流欢迎+现状回顾" | 系统自动化 |

## 四、第二层：服务模型

### 4.1 服务模型A：自动化信息服务

**定位：** 由系统全自动执行，无需人工介入，覆盖全部客户。

| 服务项 | 触发条件 | 内容来源 | 发送渠道 | 发送对象 |
|--------|---------|---------|---------|---------|
| 每日市场早报 | 交易日早8:30 | 市场数据+研报摘要 | APP推送/短信 | 全部客户 |
| 持仓异动提醒 | 持仓个股涨跌幅≥5% | 实时行情数据 | APP推送 | 持仓客户 |
| 重大事件提醒 | 持仓个股发布财报/公告 | 公告数据+AI摘要 | APP推送 | 持仓客户 |
| 账户月报 | 每月1日 | 账户数据+AI分析 | APP消息 | 全部客户 |
| 风险等级变化通知 | 风险测评结果变化 | 测评系统 | APP消息+短信 | 对应客户 |
| 产品到期提醒 | 持有产品到期前7天 | 产品数据 | APP消息+短信 | 持仓客户 |
| 生日/节日关怀 | 系统日期匹配 | 模板消息 | 短信/企微 | 对应客户 |

### 4.2 服务模型B：自动化产品匹配服务

**定位：** 基于客户分析模型标签，系统自动推荐匹配产品，客户自助决策。

| 匹配类型 | 触发条件 | 推荐逻辑 | 客户操作 | 合规边界 |
|---------|---------|---------|---------|---------|
| 新客首单推荐 | 新客开户7天内 | 低风险产品（货基/短债）优先 | 客户自助购买 | 仅限R1-R2产品 |
| 存量配置建议 | 每季度+客户资产变化超20% | 基于资金体量+交易倾向+当前状态 | 客户自助查看，一键购买 | 严格适当性匹配 |
| 亏损修复产品推荐 | 当前状态=深度亏损 | 固收+/低波产品为主 | 客户自助查看 | 禁止承诺保本保收益 |
| 高客专属产品 | 资金体量=S级 | 私募/专户/定制产品 | 预约+客户经理确认 | 必须人工确认 |

**合规要求：**
- 所有自动化推荐必须标注"AI生成，仅供参考，投资有风险"
- 涉及高风险产品（R4-R5）的推荐，必须转人工确认后才能触达客户
- 禁止自动化推荐具体个股

### 4.3 服务模型C：人工叠加服务标准（场景化组合）

**定位：** 由模型触发任务单，客户经理按"触达→诊断→建议→执行"的原子动作组合执行，覆盖20%重点客户。

#### 场景1：首触服务（新客首触）

| 元素 | 内容 |
|------|------|
| **触发条件** | 新客开户后24小时 |
| **动作组合** | 触达(建立联系) + 诊断(需求识别) + 建议(首单产品) |
| **触达** | 渠道：企微/电话；目的：建立关系+了解需求 |
| **诊断** | 重点：资金诊断(资产规模) + 需求诊断(风险等级/投资目标) |
| **建议** | 首单低风险产品(R1-R2)，引导激活 |
| **时限** | 开户后72小时内完成首触 |

#### 场景2：定期复盘服务

| 元素 | 内容 |
|------|------|
| **触发条件** | 每季度/客户资产变化超20%/S级客户按月 |
| **动作组合** | 触达(预约) + 诊断(持仓全景) + 建议(配置调整) |
| **触达** | 渠道：企微/面谈；目的：预约复盘时间 |
| **诊断** | 重点：持仓诊断(结构/集中度/盈亏) + 资金诊断(变化趋势) |
| **建议** | 配置调整方案，产品渗透建议 |
| **时限** | 触发后48小时内完成复盘 |

#### 场景3：大额亏损关注与跟踪服务

| 元素 | 内容 |
|------|------|
| **触发条件** | 当前状态=深度亏损，且资产≥5万 |
| **动作组合** | 触达(主动关怀) + 诊断(亏损归因) + 建议(优化方案) |
| **触达** | 渠道：电话/面谈；目的：主动关怀，建立信任 |
| **诊断** | 重点：持仓诊断(集中度风险) + 关系诊断(满意度/信任度) |
| **建议** | 资产优化建议（分散配置+定投计划），禁止承诺回本 |
| **时限** | 触发后24小时内首次触达 |

#### 场景4：产品配置服务

| 元素 | 内容 |
|------|------|
| **触发条件** | 客户点击高客专属产品/复杂产品/标签变化触发 |
| **动作组合** | 触达(邀约) + 诊断(适当性) + 建议(配置方案) + 执行(双录下单) |
| **触达** | 渠道：面谈；目的：邀约讲解方案 |
| **诊断** | 重点：需求诊断(适当性匹配) + 资金诊断(可投资金额) |
| **建议** | 配置方案书，含风险揭示 |
| **执行** | 双录确认，客户签署，交易系统下单 |
| **时限** | 触发后72小时内完成方案讲解 |

#### 场景5：流失挽回服务

| 元素 | 内容 |
|------|------|
| **触发条件** | 生命周期=流失，且历史最高资产≥50万 |
| **动作组合** | 触达(挽回) + 诊断(流失原因) + 建议(挽留方案) |
| **触达** | 渠道：电话/面谈；目的：了解原因，表达挽留诚意 |
| **诊断** | 重点：关系诊断(服务记录/满意度) + 资金诊断(历史价值) |
| **建议** | 针对性挽留方案（费率优惠/专属服务/产品匹配） |
| **时限** | 任务下发后48小时内首次触达 |

#### 场景6：投诉处理服务

| 元素 | 内容 |
|------|------|
| **触发条件** | 客户主动投诉/系统标记异常 |
| **动作组合** | 触达(响应) + 诊断(核实情况) + 建议(处理方案) + 执行(落实反馈) |
| **触达** | 渠道：电话；目的：响应投诉，安抚情绪 |
| **诊断** | 重点：核实投诉事实，定位问题原因 |
| **建议** | 处理方案，明确解决时限 |
| **执行** | 落实处理，反馈客户，归档记录 |
| **时限** | 触发后24小时内响应 |

**任务单格式（通用，所有场景共用）：**

```
任务单编号：XXXX
客户姓名：XXX
客户标签：资金体量=A级 / 交易倾向=低频长期型 / 当前状态=深度亏损 / 生命周期=活跃客户
触发原因：近3个月收益率=-22%，持仓集中度=集中型（单一标的占比65%）
任务类型：大额亏损关注与跟踪服务
动作组合：触达 + 诊断 + 建议
优先级：高
执行人：客户经理XXX
执行步骤：
  1. 【触达】调取客户标签，准备沟通要点，选择渠道，执行触达（时限：触发后24小时）
  2. 【诊断】调取持仓数据，执行四维诊断，输出诊断结论（时限：触达后1小时）
  3. 【建议】基于诊断结论，生成优化方案，向客户讲解（时限：诊断后2小时）
  4. 【记录】记录全流程结果（时限：每个动作后2小时）
沟通要点：
  - 客观展示亏损归因（市场因素60%+集中度风险40%）
  - 推送持仓诊断报告
  - 提供资产优化建议（分散配置+定投计划）
  - 标准风险提示（禁止承诺回本）
输出要求：触达记录+诊断报告+建议方案+客户状态记录+后续跟踪计划
```

## 五、第三层：动作模型（七事件格式）

### 先梳理：客户经理最共性的规定动作

**分析过程：**

客户经理的日常工作中，无论面对什么客户、什么场景，都必须执行的核心动作是什么？

| 场景 | 客户经理实际做了什么 |
|------|-------------------|
| 新客首触 | 联系客户 → 了解资产/需求 → 推荐首单 → 记录 |
| 定期复盘 | 预约客户 → 分析持仓 → 建议调整 → 记录 |
| 大额亏损关注 | 联系客户 → 分析亏损原因 → 给优化建议 → 记录 |
| 产品配置 | 邀约客户 → 评估适当性 → 出配置方案 → 双录下单 → 记录 |
| 流失挽回 | 联系客户 → 了解流失原因 → 给挽留方案 → 记录 |
| 投诉处理 | 联系客户 → 核实情况 → 给处理方案 → 落实 → 记录 |

**共性收敛：**

无论场景如何变化，始终逃不出这4个动作：

1. **触达** — 不管什么场景，第一步都是和客户建立联系
2. **诊断** — 不管面对什么客户，都要先分析评估现状
3. **建议** — 不管诊断出什么，都要给出专业方案
4. **执行** — 客户认可后，协助完成业务落地（部分场景需要）

> **差异在触发条件和侧重点，动作本身是共性的。**

因此，第三层只定义4个原子动作，用七事件格式标准化。所有场景在第二层用这4个原子组合表达。

### 5.1 动作1：触达（建立联系）

```
事件名称：触达（建立联系）
触发条件：
  - 条件A：系统触发任务单（高优先级）
  - 条件B：周期性触达计划（中优先级）
  - 条件C：客户主动发起（最高优先级）
执行步骤：
  1. 调取客户分析标签（工具：客户分析系统 / 时限：触达前30分钟）
  2. 确认触达目的和沟通要点（工具：沟通要点模板 / 时限：触达前15分钟）
  3. 选择触达渠道（工具：企微/电话/面谈 / 决策依据：客户偏好+场景要求）
  4. 执行触达（工具：对应渠道 / 时限：按任务单要求）
  5. 记录触达结果（工具：员工行为语料库 / 时限：触达后2小时）
输出标准：
  - 触达记录：时间/渠道/时长/核心内容/客户反馈/下一步计划
异常处理：
  - 客户拒接→3日后二次触达（换渠道）
  - 客户转户意向→标记流失预警，升级团队长
  - 客户投诉→触发投诉处理流程
时限要求：按任务单要求（紧急24小时/常规72小时）
验收标准：系统留痕完整+客户反馈已记录+下一步计划已明确
```

**场景差异点（触达动作本身不变，变的是触发条件和渠道选择）：**

| 场景 | 触达渠道 | 触达时机 | 触达目的 |
|------|---------|---------|---------|
| 首触 | 企微/电话 | 开户后24小时 | 建立关系+了解需求 |
| 定期复盘 | 企微/面谈 | 按周期 | 预约复盘时间 |
| 大额亏损 | 电话/面谈 | 触发后24小时 | 主动关怀+诊断 |
| 产品配置 | 面谈 | 客户预约后 | 方案讲解+双录 |
| 流失挽回 | 电话/面谈 | 触发后48小时 | 了解原因+挽回 |

### 5.2 动作2：诊断（分析评估）

```
事件名称：诊断（分析评估）
触发条件：
  - 条件A：触达后需了解客户状况（默认触发）
  - 条件B：客户资产/持仓/状态发生重大变化
  - 条件C：定期诊断（每季度/资产变化超20%）
执行步骤：
  1. 调取客户全景数据（工具：账户系统+分析模型 / 时限：30分钟）
  2. 执行资金诊断（资产规模、创收、变化趋势）
  3. 执行持仓诊断（结构、集中度、盈亏、风格）
  4. 执行需求诊断（风险等级、投资目标、服务偏好）
  5. 执行关系诊断（生命周期、活跃度、满意度）
  6. 输出诊断结论（工具：诊断报告模板 / 时限：触达后1小时）
  7. 记录诊断结果（工具：员工行为语料库 / 时限：诊断后2小时）
输出标准：
  - 诊断报告：四维分析结论+关键发现+数据依据+风险提示
异常处理：
  - 数据缺失→标记缺失项，基于已有数据推断+人工补充
  - 客户拒绝提供信息→记录原因，设置下次诊断时间
  - 发现合规风险→立即升级合规部门
时限要求：触达后1小时内完成诊断报告
验收标准：四维诊断完整+数据依据充分+结论明确+已记录
```

**场景差异点（诊断框架不变，变的是侧重点）：**

| 场景 | 诊断侧重点 |
|------|-----------|
| 首触 | 需求诊断（风险等级/投资目标/服务偏好）+ 资金诊断（资产规模） |
| 定期复盘 | 持仓诊断（结构/集中度/盈亏/风格）+ 资金诊断（变化趋势） |
| 大额亏损 | 持仓诊断（集中度风险）+ 关系诊断（满意度/信任度） |
| 产品配置 | 需求诊断（适当性匹配）+ 资金诊断（可投资金额） |
| 流失挽回 | 关系诊断（服务记录/满意度）+ 资金诊断（历史价值） |

### 5.3 动作3：建议（方案输出）

```
事件名称：建议（方案输出）
触发条件：
  - 条件A：诊断完成后自动生成建议（默认触发）
  - 条件B：客户主动要求建议
  - 条件C：持仓复盘/资产配置场景
执行步骤：
  1. 读取诊断结论（工具：诊断报告 / 时限：5分钟）
  2. AI生成建议方案（工具：产品匹配模型+配置模型 / 时限：10分钟）
  3. 客户经理审核方案合规性（工具：工作台 / 时限：15分钟）
  4. 向客户讲解建议方案（工具：面谈/电话 / 时限：30分钟）
  5. 确认客户意向（接受/拒绝/犹豫）
  6. 记录建议结果（工具：员工行为语料库 / 时限：讲解后2小时）
输出标准：
  - 建议方案书：诊断依据+建议内容+产品明细+风险提示+客户意向
异常处理：
  - 客户风险等级与建议不匹配→拒绝建议，重新诊断
  - 客户拒绝建议→记录原因，设置跟进计划
  - 客户犹豫→7日内再次触达，补充信息
  - 涉及R4-R5产品→必须人工确认后才能输出
时限要求：诊断后2小时内完成方案，讲解按客户预约时间
验收标准：适当性匹配合规+风险提示完整+客户意向已记录
```

**场景差异点（建议框架不变，变的是内容）：**

| 场景 | 建议类型 |
|------|---------|
| 首触 | 产品建议（首单低风险产品） |
| 定期复盘 | 配置建议（资产配置比例调整）+ 产品建议 |
| 大额亏损 | 操作建议（分散配置+定投计划）+ 产品建议（固收+/低波） |
| 产品配置 | 配置建议（配置方案书）+ 产品建议（具体产品明细） |
| 流失挽回 | 服务建议（费率优惠/专属服务）+ 产品建议 |

### 5.4 动作4：执行（业务落地）

```
事件名称：执行（业务落地）
触发条件：
  - 条件A：客户接受建议，确认执行（默认触发）
  - 条件B：客户主动发起业务办理
  - 条件C：异常情况需要操作（销户挽留、投诉处理等）
执行步骤：
  1. 确认执行内容（工具：建议方案书 / 时限：5分钟）
  2. 校验适当性与合规（工具：适当性系统 / 时限：10分钟）
  3. 执行业务操作（工具：交易系统/签约系统 / 时限：按业务类型）
    - 交易执行：下单/调仓/申购赎回
    - 签约执行：风险揭示+适当性确认+双录
    - 资料执行：收集/填写/提交
    - 升级执行：投诉升级/合规上报
  4. 确认执行结果（工具：业务系统回执 / 时限：操作后即时）
  5. 记录执行结果（工具：员工行为语料库 / 时限：操作后2小时）
输出标准：
  - 执行确认单：操作内容+合规校验结果+业务回执+客户确认
异常处理：
  - 适当性不匹配→拒绝执行，重新建议
  - 系统故障→记录故障，手工处理+后续补录
  - 客户反悔→按撤销流程处理
  - 涉及资金超限→升级审批
时限要求：客户确认后即时执行，复杂业务不超过24小时
验收标准：合规校验通过+操作留痕完整+业务回执已归档
```

**场景差异点（执行框架不变，变的是操作类型）：**

| 场景 | 执行内容 |
|------|---------|
| 首触 | 一般无执行（建议客户自助下单） |
| 定期复盘 | 一般无执行（建议客户自助调仓） |
| 大额亏损 | 一般无执行（建议客户自助调仓） |
| 产品配置 | 签约执行（双录+适当性确认）+ 交易执行（下单） |
| 投诉处理 | 升级执行（落实处理+反馈客户） |

## 六、自动化与人工叠加的边界设计

### 6.1 自动化服务清单（无需人工）

| 服务项 | 覆盖客群 | 触发条件 | 输出渠道 |
|--------|---------|---------|---------|
| 客户标签自动更新 | 全部客户 | 数据变化（交易/资产/收益） | 系统后台 |
| 市场信息推送 | 全部客户 | 固定周期/事件触发 | APP/短信 |
| 持仓异动提醒 | 持仓客户 | 持仓标的波动达标 | APP推送 |
| 标准化投后报告 | 全部客户 | 固定周期 | APP消息 |
| 沉睡自动唤醒 | 沉睡客户 | 进入沉睡状态 | APP/短信 |
| 基础产品匹配推荐 | 全部客户 | 标签变化/周期触发 | APP消息 |

### 6.2 人工叠加触发条件（必须客户经理介入）

| 触发条件 | 优先级 | 任务单类型 | 动作组合 | 响应时限 |
|---------|--------|-----------|---------|---------|
| 资金体量=S级，任意状态变化 | 最高 | 专属服务任务单 | 触达+诊断+建议 | 24小时 |
| 当前状态=深度亏损，资产≥5万 | 高 | 关注任务单 | 触达+诊断+建议 | 24小时 |
| 生命周期=流失，历史最高资产≥50万 | 高 | 挽回任务单 | 触达+诊断+建议 | 48小时 |
| 客户主动投诉 | 最高 | 投诉处理任务单 | 触达+诊断+建议+执行 | 24小时 |
| 产品配置涉及R4-R5产品 | 高 | 人工确认任务单 | 触达+诊断+建议+执行 | 72小时 |
| 客户提及转户/销户 | 高 | 流失预警任务单 | 触达+诊断+建议 | 24小时 |
| 持仓集中度>50%且标的跌幅>10% | 中 | 风险提示任务单 | 触达+诊断 | 48小时 |
| 生命周期=新客，开户7天未入金 | 中 | 新客跟进任务单 | 触达+诊断+建议 | 72小时 |

### 6.3 三句话法合规节点

| 服务类型 | 判断 | 智能体动作 | 人工介入要求 |
|---------|------|-----------|------------|
| 自动化信息推送 | 可以 | 全自动执行 | 无需人工 |
| 标准化产品推荐（R1-R2） | 可以 | 自动推荐，客户自助决策 | 无需人工 |
| 高风险产品推荐（R4-R5） | 必须确认 | 生成推荐方案→人工审核→客户触达 | 客户经理必须审核 |
| 资产配置方案 | 必须确认 | AI生成方案→人工审核→双录确认→执行 | 客户经理必须审核 |
| 投资建议/个股推荐 | 不 | 直接拒绝，标记原因 | 升级合规处理 |
| 承诺保本保收益 | 不 | 直接拒绝，标记原因 | 升级合规处理 |
| 客户投诉处理 | 必须确认 | 记录投诉→分配人工→处理结果归档 | 必须人工处理 |

## 七、与v4.0的核心变化对照

| 维度 | v4.0 | v4.1 |
|------|------|------|
| **动作模型粒度** | 场景级（6个：客户触达/持仓复盘/产品配置/风险安抚/流失挽回/团队管理） | 原子级（4个：触达/诊断/建议/执行） |
| **场景表达位置** | 第三层动作模型（混淆场景与原子） | 第二层服务模型（场景=原子组合） |
| **扩展性** | 每新增场景需新增动作模型 | 新增场景只需组合原子动作，无需新增动作模型 |
| **重复度** | 每个动作模型都包含"触达→诊断→建议→记录"，大量重复 | 原子动作互不重复，场景按需引用 |
| **角色对齐** | 团队管理动作混入客户经理动作层 | 团队长管理动作单独列出 |
| **七事件格式** | 每个场景写一次，内容冗长 | 4个原子各写一次，场景引用即可 |
| **共性提炼** | 未显式提炼共性 | 显式分析：从角色出发→收敛为4个最共性动作 |
