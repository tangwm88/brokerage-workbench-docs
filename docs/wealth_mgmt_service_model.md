# 证券公司财富管理（零售）业务 完整服务模型

> 版本：v1.0 | 基于陶总原子模型设计方法论
> 编制规则：事件驱动 · 原子可调用 · 触发-执行-验收 · 禁用词语表已过滤

---

## 第一部分：服务模型总结构

### 1.1 三主维度定义

| 主维度 | 定义 | 子维度 | 说明 |
|--------|------|--------|------|
| **服务类型** | 按服务目的划分的事件类别 | 7大类型（获客/分析/匹配/交易/投后/留存/合规） | 每类由若干原子服务动作组成，动作之间无强制线性依赖 |
| **服务层级** | 按服务交付方式划分的能力层级 | 自助层 / 智能层 / 人工层 | 同一服务动作可在不同层级实现，阈值决定切换 |
| **触发机制** | 服务动作被调用的启动条件 | 事件触发 / 周期触发 / 客户主动 | 三类触发条件独立存在，服务动作可配置多触发源 |

### 1.2 子模型层级关系

```
服务模型（顶层）
├── 服务类型维度（7大类）
│   ├── 获客类（3个原子动作）
│   ├── 分析类（4个原子动作）
│   ├── 匹配类（4个原子动作）
│   ├── 交易类（4个原子动作）
│   ├── 投后类（6个原子动作）
│   ├── 留存类（6个原子动作）
│   └── 合规类（3个原子动作）
├── 服务层级维度（3层）
│   ├── 自助层：客户自行操作，系统提供能力
│   ├── 智能层：系统自动触发，AI/规则引擎执行
│   └── 人工层：人工介入，需服务经理操作
└── 触发机制维度（3类）
    ├── 事件触发：系统监测到特定事件或阈值越过
    ├── 周期触发：按固定时间周期执行
    └── 客户主动：客户发起的服务请求
```

### 1.3 与产品模型的调用关系

| 调用方向 | 关系说明 | 具体表现 |
|----------|----------|----------|
| 服务模型 → 产品模型 | 服务动作调用产品卡片获取信息 | 产品适当性校验调用产品风险等级；资产配置调用产品可用清单 |
| 产品模型 → 服务模型 | 产品变更事件触发服务动作 | 产品净值异常波动触发风险预警；产品到期触发续作建议 |
| 双向调用 | 客户分类结果影响服务层级，服务结果更新客户标签 | 分类结果写入客户数据，服务记录反馈至分类系统 |

> **核心原则**：服务模型与产品模型解耦。服务动作通过标准接口调用产品卡片，不依赖产品内部结构。产品模型变更不破坏服务动作定义。

## 第二部分：全部服务类型清单

### 2.1 获客类

| 服务动作 | 服务层级 | 典型触发机制 | 备注 |
|----------|----------|--------------|------|
| 识别客户线索 | 智能层 | 事件触发：外部数据接入（APP行为、活动报名、资产线索） | 阈值：资产>50万或行为频次>3次/周 |
| 引导开户 | 自助层/智能层 | 事件触发：线索识别后自动推送；客户主动：点击开户入口 | 智能层用于高净值线索 |
| 激活首投 | 智能层/人工层 | 事件触发：开户后T+30天未交易；周期触发：开户后T+7天/T+15天提醒 | 人工层用于高净值/超高净值 |

### 2.2 分析类

| 服务动作 | 服务层级 | 典型触发机制 | 备注 |
|----------|----------|--------------|------|
| 识别客户分类 | 智能层 | 事件触发：资产变动>10%或评级变更；周期触发：每季度自动评估 | 输出4类分级：大众/富裕/高净值/超高净值 |
| 分析需求深度 | 人工层 | 客户主动：客户预约深度咨询；事件触发：资产>600万且未做深度分析 | 人工层专属，需预约 |
| 重估风险承受力 | 自助层/智能层 | 周期触发：距上次评估>12个月；事件触发：重大市场波动后 | 自助层推送问卷，智能层自动校验变化 |
| 诊断财务状况 | 智能层 | 事件触发：客户资产结构偏离度>20%；周期触发：每半年 | 输出资产结构诊断报告 |

### 2.3 匹配类

| 服务动作 | 服务层级 | 典型触发机制 | 备注 |
|----------|----------|--------------|------|
| 校验产品适当性 | 智能层 | 事件触发：客户发起交易前；周期触发：客户风险等级变更后 | 强制校验，不通过阻断交易 |
| 生成资产配置方案 | 智能层/人工层 | 客户主动：客户申请方案；事件触发：资产>300万且未配置方案 | 人工层用于高净值/超高净值 |
| 推荐产品组合 | 智能层 | 事件触发：资产配置方案生成后；客户主动：客户浏览推荐页 | 基于方案调用产品模型 |
| 建议组合再平衡 | 智能层/人工层 | 事件触发：组合偏离度>5%或时间>3个月；周期触发：每季度 | 人工层用于高净值 |

### 2.4 交易类

| 服务动作 | 服务层级 | 典型触发机制 | 备注 |
|----------|----------|--------------|------|
| 执行交易指令 | 自助层/智能层 | 客户主动：客户发起交易；事件触发：定投计划触发 | 需校验适当性后方可执行 |
| 处理认购/申购/赎回 | 自助层 | 客户主动：客户操作 | 标准化交易流程 |
| 执行产品转换 | 自助层/智能层 | 客户主动：客户发起；事件触发：产品清盘/转型 | 转换需重新校验适当性 |
| 设置定投计划 | 自助层/智能层 | 客户主动：客户设置；事件触发：方案推荐后客户确认 | 支持智能推荐定投参数 |

### 2.5 投后类

| 服务动作 | 服务层级 | 典型触发机制 | 备注 |
|----------|----------|--------------|------|
| 检视持仓收益 | 自助层/智能层 | 客户主动：客户查看；周期触发：T+1日终自动计算 | 智能层用于异常波动时主动推送 |
| 跟踪产品净值 | 智能层 | 事件触发：净值波动>2%（日）；周期触发：T+1日终更新 | 触发条件可配置 |
| 触发风险预警 | 智能层/人工层 | 事件触发：净值回撤>5%或组合波动>10% | 人工层用于高净值客户专属预警 |
| 生成调仓建议 | 智能层/人工层 | 事件触发：组合偏离>5%或目标达成；周期触发：每季度 | 人工层需服务经理确认后推送 |
| 建议产品到期续作 | 智能层/人工层 | 事件触发：产品到期前T+15天；事件触发：产品清盘通知 | 人工层用于高净值客户 |
| 通知重大事项 | 智能层/人工层 | 事件触发：产品公告/公司公告/监管公告 | 根据客户持仓自动关联 |

### 2.6 留存类

| 服务动作 | 服务层级 | 典型触发机制 | 备注 |
|----------|----------|--------------|------|
| 执行定期回访 | 智能层/人工层 | 周期触发：按客户层级（大众T+90天/富裕T+60天/高净值T+30天） | 人工层用于高净值 |
| 收集服务满意度 | 自助层 | 事件触发：服务动作完成后T+3天；周期触发：每季度 | 问卷形式，3题以内 |
| 触发服务层级升级 | 智能层 | 事件触发：资产连续90天>阈值（富裕300万/高净值600万/超高净值3000万） | 系统自动识别并触发 |
| 预警并挽回流失 | 智能层/人工层 | 事件触发：活跃度下降>50%且持续T+30天；事件触发：资产转出>20% | 人工层用于高净值 |
| 处理投诉 | 人工层 | 客户主动：客户提交投诉；事件触发：投诉工单生成 | 必须人工处理 |
| 推送投资者教育 | 智能层 | 事件触发：客户首次购买某类产品；周期触发：每月1次；客户主动：订阅 | 内容与客户持仓关联 |

### 2.7 合规类

| 服务动作 | 服务层级 | 典型触发机制 | 备注 |
|----------|----------|--------------|------|
| 管理适当性留痕 | 智能层 | 事件触发：每次适当性校验后；事件触发：风险揭示确认后 | 自动生成留痕记录 |
| 确认风险揭示 | 自助层/智能层 | 客户主动：客户阅读并确认；事件触发：产品购买前强制弹窗 | 不确认无法继续交易 |
| 执行反洗钱监控 | 智能层 | 事件触发：大额交易（单笔>50万）；周期触发：每日批处理；事件触发：异常行为模式 | 自动触发可疑交易报告 |

### 卡片1：识别客户分类

| 字段 | 内容 |
|------|------|
| **服务动作名称** | 识别客户分类 |
| **服务类型** | 分析类 |
| **服务层级** | 智能层 |
| **适用客户层级** | 全部（大众/富裕/高净值/超高净值） |
| **触发条件** | ① 事件触发：客户资产总值变动>10%（较上次评估）；② 事件触发：客户完成风险承受能力重估；③ 周期触发：每季度末自动执行；④ 事件触发：客户首次资产入账>50万 |
| **执行步骤** | ① 读取客户资产数据（证券账户+银行账户关联资产）；② 计算客户资产总值（含证券市值、现金余额、在途资金）；③ 对照分类阈值表判定层级；④ 写入客户分类标签并更新生效日期；⑤ 若分类变更，触发关联动作（服务层级升级/回访计划调整） |
| **输出物** | 客户分类结果（JSON格式）：`{customer_id, classification, total_assets, effective_date, source_trigger}` |
| **验收标准** | 客户侧：无直接感知（后台自动完成）；内部侧：分类结果T+0写入数据库；分类准确率>99%（资产计算误差<0.1%）；分类变更触发关联动作率100% |
| **时限要求** | 刚性时限：触发后T+0日终完成；预警阈值：日终批处理前2小时未启动则告警 |
| **异常处理** | 异常① 资产数据缺失：标记待补录，T+1重试；异常② 分类阈值争议：人工复核，T+1给出结果；异常③ 系统批处理失败：次日补跑，记录差异 |
| **关联产品模型** | 产品适当性校验（调用分类结果作为校验输入） |
| **关联客户分类** | 输出自身结果，不依赖前置分类 |

| **验收标准** | 客户侧：方案阅读率>80%（打开即算）；客户确认率>60%；内部侧：方案生成T+0（智能层）/T+3工作日（人工层）；方案合规校验通过率100% |
| **时限要求** | 智能层：T+0生成；人工层：客户申请后T+3工作日；预警阈值：人工层到期前T+1日未完成则升级至主管 |
| **异常处理** | 异常① 产品模型调用失败：使用最近一次有效产品清单，T+1补全；异常② 方案校验不通过：标记原因，重新生成，T+1重试；异常③ 客户拒绝确认：记录原因，T+30天后再次触发 |
| **关联产品模型** | 调用产品可用清单、产品风险等级、产品类别标签；被"产品组合推荐"调用（方案是推荐的前置条件） |
| **关联客户分类** | 需前置"识别客户分类"结果；需前置"重估风险承受力"结果（有效期12个月内） |

| 确认风险揭示 | 执行交易指令 | 强依赖 | 风险揭示确认是交易前置 |

> **说明**：弱依赖表示可独立执行，但关联执行效果更佳；强依赖表示必须先执行A才能执行B。

### 4.3 自助→智能→人工切换条件

| 切换方向 | 触发条件 | 执行机制 |
|----------|----------|----------|
| 自助→智能 | 客户行为触发系统规则（如首次购买某类产品） | 系统自动切换，无感知 |
| 自助→人工 | 客户明确要求人工服务；或系统判定需人工（如资产>600万） | 客户主动或系统强制派单 |
| 智能→人工 | 智能处理失败（如问卷未完成）；或客户不满意智能服务 | 系统自动升级派单，T+1响应 |

| 人工→智能 | 人工服务完成且客户无后续需求；或客户降级 | 人工标记完成，系统恢复 |
| 人工→自助 | 客户主动选择自助服务（如APP操作） | 客户自主切换 |
