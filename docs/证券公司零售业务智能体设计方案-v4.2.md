# 证券公司零售业务智能体设计方案 v4.2

> **面向角色：** 投资者（被服务方）+ 客户经理（执行方）+ 团队长（管理方）
> **核心目标：** 模型自动化服务大部分客户，前台团队服务动作按需叠加
> **设计依据：** 陶总方法论 + 统一参考方法论 + 架构图v2.0 + 禁用词语表
> 版本：v4.2（基于v4.1重构动作模型为操作流程）
> 时间：2026-06-19

---

## 一、先定角色和目的

### 1.1 三类角色

| 角色 | 定位 | 核心诉求 | 与模型的关系 |
|------|------|---------|------------|
| **投资者** | 服务接收方 | 获得匹配自身情况的投资服务与产品 | 被模型分析、被服务模型覆盖、接收自动化服务 |
| **客户经理** | 服务执行方 | 高效服务大量客户，重点精力投向高价值/高流失风险客户 | 执行动作模型规定的标准动作，响应模型触发的任务单 |
| **团队长** | 管理组织者 | 穿透团队服务全貌，识别风险与机会，调配资源 | 接收团队级聚合报告，审批异常处理，驱动迭代 |

### 1.2 核心目的

**一句话：让模型自动化覆盖80%客户的标准化服务，客户经理专注处理20%需要人工判断和情感连接的场景。**

```
┌─────────────────────────────────────────────────────────────┐
│  自动化服务层（模型驱动，无需人工介入）                        │
│  ├─ 客户自动分层与标签更新                                    │
│  ├─ 标准化信息推送（市场动态/持仓提醒/产品匹配）              │
│  ├─ 常规投后报告自动生成与发送                                │
│  ├─ 沉睡客户自动唤醒触达                                    │
│  └─ 覆盖客群：80%                                           │
├─────────────────────────────────────────────────────────────┤
│  人工叠加层（客户经理执行，模型触发任务单）                    │
│  ├─ 高价值客户深度服务                                      │
│  ├─ 大额亏损关注与跟踪                                      │
│  ├─ 复杂产品配置方案沟通                                    │
│  ├─ 流失预警客户挽回                                        │
│  └─ 覆盖客群：20%                                           │
└─────────────────────────────────────────────────────────────┘
```

## 二、三层模型体系

### 2.1 模型总览

```
零售业务智能体
├── 第一层：客户分析模型（4个本质维度）
│   ├── 维度1：资金体量
│   ├── 维度2：交易倾向
│   ├── 维度3：当前状态
│   └── 维度4：生命周期
├── 第二层：服务模型（场景化组合）
│   ├── 服务模型A：自动化信息服务（100%自动）
│   ├── 服务模型B：自动化产品匹配服务（100%自动）
│   ├── 服务模型C：人工叠加服务标准（模型触发→客户经理按5步执行）
│   │   ├── 场景1：首触服务
│   │   ├── 场景2：定期复盘服务
│   │   ├── 场景3：大额亏损关注服务
│   │   ├── 场景4：产品配置服务
│   │   ├── 场景5：流失挽回服务
│   │   └── 场景6：投诉处理服务
│   └── 服务模型D：团队管理服务（团队长执行，单独列出）
└── 第三层：动作模型（5个标准操作步骤，七事件格式）
    ├── 步骤1：接收客户服务任务
    ├── 步骤2：服务准备
    ├── 步骤3：触达客户
    ├── 步骤4：登记结果
    └── 步骤5：跟踪反馈
```

### 2.2 设计原则：先定操作流程，再套场景

**v4.1的问题：** 把动作模型收敛为"触达/诊断/建议/执行"4个认知功能，但"诊断"和"建议"是思考过程，不是可执行动作。一线人员要的是"怎么干"，不是"怎么想"。

**v4.2的解法：** 第三层只放**最标准、最共性的操作流程**（5个步骤），所有场景共用同一流程，差异只在每步的具体内容。

> 无论面对什么客户、什么场景，客户经理的日常工作逃不出这5个步骤：接收任务→准备→触达→登记→跟踪。

## 三、第一层：客户分析模型

### 3.1 设计原则
- **4个本质维度**，每个维度3-5档，客户经理能记住、能使用
- **客观量化**，每档有明确的数字边界
- **直接驱动动作**，每个维度变化自动触发对应服务动作
- **系统自动更新**，标签变化由模型自动识别，无需人工维护

### 3.2 维度1：资金体量

**定位：** 客户对券商的综合价值，决定服务等级和资源配置。

| 等级 | 判定标准（月日均，三选一达标） | 服务等级 |
|------|------------------------------|---------|
| **S级** | 资产规模≥1000万，或月均创收≥3000元 | 专属客户经理+团队长关注 |
| **A级** | 资产规模300-1000万，或月均创收500-3000元 | 客户经理一对一维护 |
| **B级** | 资产规模5-300万，或月均创收50-500元 | 标准化自动化服务为主 |
| **C级** | 资产规模<5万，且月均创收<50元 | 批量自动化服务 |

**触发动作：**
- C级→B级（资产增长达标）：自动触发"服务升级通知"
- A级→S级（资产突破1000万）：自动触发"专属服务激活任务单"给团队长
- 任意等级资产连续3月下降超20%：自动触发"流失预警任务单"

### 3.3 维度2：交易倾向

**定位：** 客户的交易习惯和投资方式，决定沟通内容和服务重点。

| 类型 | 判定标准 | 核心特征 |
|------|---------|---------|
| **高频交易型** | 月换手率≥200%，或月交易笔数≥30笔 | 追求短期收益，关注市场热点和个股机会 |
| **中频波段型** | 月换手率50%-200%，或月交易笔数10-29笔 | 有一定择时能力，关注产业趋势和板块轮动 |
| **低频长期型** | 月换手率10%-50%，或月交易笔数1-9笔 | 偏向长期持有，关注企业实际质地和估值 |
| **超低频保守型** | 月换手率<10%，或月交易笔数0笔但资产>0 | 几乎不交易，以现金管理或被动持有为主 |
| **零交易型** | 月交易笔数0笔，且账户无资产 | 未激活或已流失 |

**持仓风格标签（辅助，不独立成维度）：**
- 大盘蓝筹型：蓝筹个股成交占比≥60%
- 成长赛道型：产业大盘成长成交占比≥60%
- 小盘题材型：中小盘成长/题材个股成交占比≥60%
- 红利防御型：红利个股成交占比≥60%
- 可转债型：可转债成交占比≥30%

**触发动作：**
- 低频长期型→高频交易型（交易频率连续2月提升）：自动触发"交易活跃度提升关怀"
- 高频交易型→低频长期型（交易频率连续3月下降）：自动触发"活跃度下降关注"
- 持仓风格标签变化：自动触发"持仓风格变化提醒"

### 3.4 维度3：当前状态

**定位：** 客户当前的收益状况和持仓健康度，决定当前最需要什么服务。

| 状态 | 判定标准（近3个月收益率） | 核心诉求 |
|------|------------------------|---------|
| **大幅盈利** | 收益率>15% | 止盈建议、利润保护、再配置建议 |
| **稳健盈利** | 0<收益率≤15% | 维持策略、产品渗透、提升服务体验 |
| **盈亏平衡** | -5%≤收益率≤0 | 维持信心、市场解读、避免恐慌操作 |
| **小幅亏损** | -15%<收益率<-5% | 亏损归因、持仓诊断、修复建议 |
| **深度亏损** | 收益率≤-15% | 状态关注、深度诊断、资产优化建议 |

**持仓集中度标签（辅助）：**
- 集中型：单一标的持仓占比>50%
- 适度集中：单一标的持仓占比30%-50%
- 分散型：单一标的持仓占比<30%

**触发动作：**
- 大幅盈利→深度亏损（单月跌幅超20%）：自动触发"剧烈波动关怀任务单"给客户经理
- 深度亏损持续3个月未改善：自动触发"高优先级关注任务单"
- 持仓集中度>50%且该标的近月跌幅>10%：自动触发"集中度风险提示"

### 3.5 维度4：生命周期

**定位：** 客户与公司的关系阶段，直接决定服务策略和触发动作。

| 阶段 | 判定标准 | 自动化服务占比 | 人工叠加触发条件 |
|------|---------|--------------|----------------|
| **潜在客户** | 未开户，但在线索池 | 100%自动化（线索培育） | 线索活跃度达标→分配客户经理 |
| **新客** | 开户≤30天 | 90%自动化 | 开户7天未入金→客户经理跟进 |
| **尝鲜客户** | 开户>30天，有首笔交易但近30天无交易 | 80%自动化 | 连续45天无交易→客户经理唤醒 |
| **活跃客户** | 近30天有交易 | 70%自动化 | 资产升级/状态异常→客户经理介入 |
| **沉睡客户** | 资产>0，近90天零交易 | 60%自动化 | 沉睡超180天→客户经理挽回 |
| **忠诚客户** | 开户≥1年+月均资产≥10万+近12个月有交易+累计创收≥500元 | 50%自动化 | 定期专属服务+转介绍激励 |
| **流失客户** | 已销户，或资产=0且连续180天零交易 | 归档/批量挽回 | 高价值流失→客户经理挽回 |
| **回流客户** | 曾经流失/沉睡，近30天重新入金或交易 | 70%自动化 | 回流后30天→客户经理关怀 |

**触发动作（生命周期状态变化自动触发）：**

| 变化 | 自动触发动作 | 任务单对象 |
|------|------------|----------|
| 潜在客户→新客 | 自动发送"开户欢迎+新客引导" | 系统自动化 |
| 新客→尝鲜客户（完成首单） | 自动发送"首单确认+持续服务介绍" | 系统自动化 |
| 活跃客户→沉睡客户 | 自动发送"沉睡唤醒信息"+30天后客户经理任务单 | 系统→客户经理 |
| 活跃客户→忠诚客户 | 自动发送"忠诚客户升级通知"+专属服务介绍 | 系统→客户经理 |
| 任意→流失客户 | 自动归档+高价值客户分配挽回任务单 | 团队长→客户经理 |
| 流失/沉睡→回流客户 | 自动发送"回流欢迎+现状回顾" | 系统自动化 |

## 四、第二层：服务模型

### 4.1 服务模型A：自动化信息服务

**定位：** 由系统全自动执行，无需人工介入，覆盖全部客户。

| 服务项 | 触发条件 | 内容来源 | 发送渠道 | 发送对象 |
|--------|---------|---------|---------|---------|
| 每日市场早报 | 交易日早8:30 | 市场数据+研报摘要 | APP推送/短信 | 全部客户 |
| 持仓异动提醒 | 持仓个股涨跌幅≥5% | 实时行情数据 | APP推送 | 持仓客户 |
| 重大事件提醒 | 持仓个股发布财报/公告 | 公告数据+AI摘要 | APP推送 | 持仓客户 |
| 账户月报 | 每月1日 | 账户数据+AI分析 | APP消息 | 全部客户 |
| 风险等级变化通知 | 风险测评结果变化 | 测评系统 | APP消息+短信 | 对应客户 |
| 产品到期提醒 | 持有产品到期前7天 | 产品数据 | APP消息+短信 | 持仓客户 |
| 生日/节日关怀 | 系统日期匹配 | 模板消息 | 短信/企微 | 对应客户 |

### 4.2 服务模型B：自动化产品匹配服务

**定位：** 基于客户分析模型标签，系统自动推荐匹配产品，客户自助决策。

| 匹配类型 | 触发条件 | 推荐逻辑 | 客户操作 | 合规边界 |
|---------|---------|---------|---------|---------|
| 新客首单推荐 | 新客开户7天内 | 低风险产品（货基/短债）优先 | 客户自助购买 | 仅限R1-R2产品 |
| 存量配置建议 | 每季度+客户资产变化超20% | 基于资金体量+交易倾向+当前状态 | 客户自助查看，一键购买 | 严格适当性匹配 |
| 亏损修复产品推荐 | 当前状态=深度亏损 | 固收+/低波产品为主 | 客户自助查看 | 禁止承诺保本保收益 |
| 高客专属产品 | 资金体量=S级 | 私募/专户/定制产品 | 预约+客户经理确认 | 必须人工确认 |

**合规要求：**
- 所有自动化推荐必须标注"AI生成，仅供参考，投资有风险"
- 涉及高风险产品（R4-R5）的推荐，必须转人工确认后才能触达客户
- 禁止自动化推荐具体个股

### 4.3 服务模型C：人工叠加服务标准（场景化组合）

**定位：** 由模型触发任务单，客户经理按"接收→准备→触达→登记→跟踪"5步执行，覆盖20%重点客户。

#### 场景1：首触服务（新客首触）

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"新客首触任务单"：客户标签+开户信息+触发原因（开户后24小时未首触） |
| **服务准备** | 调取客户开户资料、风险测评结果、资产情况；准备首触沟通要点（欢迎+了解需求+首单推荐） |
| **触达客户** | 渠道：企微/电话；内容：自我介绍+了解投资经验+介绍服务+推荐首单低风险产品 |
| **登记结果** | 记录触达时间/渠道/客户反馈/投资需求/是否接受首单推荐 |
| **跟踪反馈** | 7日内跟进首单激活情况；如未激活，二次触达 |

#### 场景2：定期复盘服务

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"定期复盘任务单"：客户标签+上次复盘时间+触发原因（季度/资产变化超20%） |
| **服务准备** | 调取客户持仓全景、盈亏数据、集中度、历史服务记录；准备复盘沟通要点 |
| **触达客户** | 渠道：企微/面谈；内容：持仓回顾+盈亏归因+市场解读+配置调整建议 |
| **登记结果** | 记录复盘时间/渠道/客户反馈/是否接受调整建议/异议内容 |
| **跟踪反馈** | 7日内跟进客户是否执行调仓；设置下次复盘时间 |

#### 场景3：大额亏损关注与跟踪服务

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"大额亏损关注任务单"：客户标签+亏损数据+触发原因（近3月收益=-22%） |
| **服务准备** | 调取持仓明细、亏损归因分析、集中度风险、历史服务记录；准备关怀沟通要点（禁止承诺回本） |
| **触达客户** | 渠道：电话/面谈；内容：主动关怀+客观分析亏损原因+推送诊断报告+给优化建议 |
| **登记结果** | 记录触达时间/渠道/客户反馈/情绪状态/是否接受建议 |
| **跟踪反馈** | 3日内推送资产优化方案；7日内跟进客户操作情况；持续跟踪状态变化 |

#### 场景4：产品配置服务

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"产品配置任务单"：客户标签+适当性结果+配置需求（客户点击高客专属产品） |
| **服务准备** | 调取客户资产/风险等级/历史配置；准备配置方案书+风险揭示材料+双录设备 |
| **触达客户** | 渠道：面谈；内容：方案讲解+风险揭示+适当性确认+双录+客户签署 |
| **登记结果** | 记录方案内容/客户确认意见/双录编号/签署文件编号 |
| **跟踪反馈** | 产品成立后推送确认信息；定期跟踪持仓表现；设置下次复盘时间 |

#### 场景5：流失挽回服务

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"流失挽回任务单"：客户标签+历史价值+触发原因（生命周期=流失+历史最高资产≥50万） |
| **服务准备** | 调取客户历史服务记录、资产变化轨迹、投诉记录；准备挽回沟通要点 |
| **触达客户** | 渠道：电话/面谈；内容：了解流失原因+表达挽留诚意+给挽留方案（费率优惠/专属服务） |
| **登记结果** | 记录触达时间/渠道/流失原因/客户态度/挽留结果 |
| **跟踪反馈** | 挽回成功→启动回流客户关怀；挽回失败→归档分析流失原因 |

#### 场景6：投诉处理服务

| 步骤 | 具体内容 |
|------|---------|
| **接收任务** | 系统推送"投诉处理任务单"：投诉内容+客户标签+紧急程度 |
| **服务准备** | 调取投诉相关资料、客户历史记录、类似案例处理方案；准备沟通要点 |
| **触达客户** | 渠道：电话；内容：致歉+核实情况+说明处理方案+明确解决时限 |
| **登记结果** | 记录投诉内容/核实结果/处理方案/客户满意度/解决时限 |
| **跟踪反馈** | 按承诺时限落实处理；处理完成后回访客户确认满意度；归档复盘 |

## 五、第三层：动作模型（5个标准操作步骤，七事件格式）

### 先梳理：客户经理最标准的工作流程

**分析过程：**

客户经理无论面对什么场景，实际工作都是这个流程：

```
接收今日任务单 → 服务准备 → 触达客户 → 登记结果 → 跟踪反馈
```

**共性收敛：**

| 步骤 | 为什么共性 | 为什么逃不掉 |
|------|-----------|-------------|
| **接收任务** | 所有人工服务都从任务单开始 | 没有任务单就不知道服务谁 |
| **服务准备** | 所有触达前都要调数据、备材料 | 裸奔见客户是违规的 |
| **触达客户** | 所有服务的核心执行环节 | 不见客户就不叫服务 |
| **登记结果** | 所有服务必须留痕 | 不留痕无法考核、无法复盘 |
| **跟踪反馈** | 所有服务必须闭环 | 不跟踪等于白做 |

> **诊断和建议不消失，内嵌在步骤中：**
> - "诊断" → 内嵌在"服务准备"（调数据时自动完成诊断摘要）
> - "建议" → 内嵌在"触达客户"（沟通要点中包含方案讲解）

### 5.1 步骤1：接收客户服务任务

```
事件名称：接收客户服务任务
触发条件：
  - 条件A：系统自动推送任务单（模型触发）
  - 条件B：团队长手动分配任务
  - 条件C：客户经理主动认领
执行步骤：
  1. 查看任务单详情（客户姓名/标签/触发原因/优先级/时限）
  2. 确认任务可执行性（自身权限/客户归属/时间冲突）
  3. 接受任务，系统记录接收时间
输出标准：
  - 任务接收记录：接收时间/客户经理/任务类型/客户信息
异常处理：
  - 任务分配错误→退回任务，说明原因
  - 时间冲突→申请延期或转交同事
  - 客户已流失/销户→标记失效，归档
时限要求：任务推送后2小时内确认接收
验收标准：任务已接收+客户信息已查看+无冲突
```

---

### 5.2 步骤2：服务准备

```
事件名称：服务准备
触发条件：
  - 条件A：接收任务后默认触发
  - 条件B：触达前1小时提醒
执行步骤：
  1. 调取客户全景数据（资产/持仓/交易/历史服务记录）
  2. 查看客户分析标签（资金体量/交易倾向/当前状态/生命周期）
  3. 分析客户现状（系统自动输出诊断摘要）
  4. 准备沟通要点（根据场景调用沟通要点模板）
  5. 准备相关材料（方案书/风险揭示书/产品资料）
  6. 确认触达渠道和时间（企微/电话/面谈）
输出标准：
  - 准备清单：客户摘要/沟通要点/材料清单/触达计划
异常处理：
  - 客户数据缺失→标记缺失项，基于已有信息准备+触达中补充
  - 沟通要点模板不匹配→人工调整，记录优化建议
  - 客户临时改期→更新触达计划
时限要求：触达前30分钟完成准备
验收标准：客户数据已调取/沟通要点已确认/材料已备齐/渠道时间已确认
```

---

### 5.3 步骤3：触达客户

```
事件名称：触达客户
触发条件：
  - 条件A：服务准备完成后按计划执行
  - 条件B：客户临时发起沟通
执行步骤：
  1. 执行触达（按确认的渠道：企微/电话/面谈）
  2. 说明触达目的（基于任务单触发原因）
  3. 沟通核心内容（讲解方案/处理异议/提供服务）
  4. 确认客户意向（接受/拒绝/犹豫/需再考虑）
  5. 约定下一步（如需：下次触达时间/需补充材料/客户需做决策）
输出标准：
  - 触达记录：时间/渠道/时长/核心内容/客户反馈/客户意向/下一步计划
异常处理：
  - 客户拒接/爽约→3日内二次触达（换渠道）
  - 客户情绪激动/投诉→升级团队长/合规部门
  - 客户当场要求业务办理（如产品配置）→按业务规程执行双录/签约
时限要求：按任务单要求（紧急24小时内/常规72小时内）
验收标准：触达已完成+核心内容已传达+客户意向已确认+下一步已约定
```

---

### 5.4 步骤4：登记结果

```
事件名称：登记结果
触发条件：
  - 条件A：触达完成后即时触发（默认）
  - 条件B：系统定时提醒补录
执行步骤：
  1. 填写触达记录（时间/渠道/时长/内容摘要）
  2. 记录客户反馈（态度/意见/异议/需求）
  3. 记录客户意向（接受/拒绝/犹豫/待跟进）
  4. 上传相关附件（录音/截图/签署文件/方案书）
  5. 提交登记，系统归档
输出标准：
  - 完整触达档案：记录+反馈+意向+附件
异常处理：
  - 忘记登记→系统24小时后提醒补录
  - 记录不完整→系统校验提示补充
  - 客户后续反悔→更新记录，标记变更
时限要求：触达完成后2小时内完成登记
验收标准：记录完整+反馈清晰+意向明确+附件齐全+已归档
```

### 5.5 步骤5：跟踪反馈

```
事件名称：跟踪反馈
触发条件：
  - 条件A：触达登记后自动生成跟踪计划（默认）
  - 条件B：约定跟进时间到达
  - 条件C：客户状态发生变化（资产/持仓/生命周期）
执行步骤：
  1. 查看跟踪计划（系统根据场景自动生成）
  2. 执行跟踪动作（推送材料/电话回访/面访跟进）
  3. 更新客户状态（标签更新/生命周期变化/需求变化）
  4. 评估服务效果（客户满意度/业务转化率/状态改善）
  5. 闭环确认（服务完成/转入下一周期/升级处理）
输出标准：
  - 跟踪记录：跟踪时间/动作/客户反馈/状态变化/效果评估
异常处理：
  - 客户无响应→3日后再次跟踪，换渠道
  - 客户状态恶化（如亏损扩大）→升级优先级，重新触发服务
  - 跟踪中客户提出新需求→生成新任务单
时限要求：按跟踪计划执行（一般3-7日内首次跟踪）
验收标准：跟踪已执行+状态已更新+效果已评估+已闭环或转入下周期
```

| 客户主动投诉 | 最高 | 投诉处理任务单 | 接收→准备→触达→登记→跟踪 | 24小时 |

### 6.3 三句话法合规节点

| 服务类型 | 判断 | 智能体动作 | 人工介入要求 |
|---------|------|-----------|------------|
| 自动化信息推送 | 可以 | 全自动执行 | 无需人工 |
| 标准化产品推荐（R1-R2） | 可以 | 自动推荐，客户自助决策 | 无需人工 |
| 高风险产品推荐（R4-R5） | 必须确认 | 生成推荐方案→人工审核→客户触达 | 客户经理必须审核 |
| 资产配置方案 | 必须确认 | AI生成方案→人工审核→双录确认→执行 | 客户经理必须审核 |
| 投资建议/个股推荐 | 不 | 直接拒绝，标记原因 | 升级合规处理 |
| 承诺保本保收益 | 不 | 直接拒绝，标记原因 | 升级合规处理 |
| 客户投诉处理 | 必须确认 | 记录投诉→分配人工→处理结果归档 | 必须人工处理 |
