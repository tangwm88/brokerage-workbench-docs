# 贵州饭店客户服务智能体应用分析

> 基于酒店客房产品模型 + 酒店餐饮产品模型 + 景区旅游产品模型
> 场景：客户已选择贵州饭店，智能体全程服务客户

---

## 一、智能体角色定义

### 1.1 角色名称
**贵州饭店客户服务智能体**（简称：贵小智）

### 1.2 角色定位
客户入住前→入住中→离店后的全周期服务助手，不是"回答问题"而是"主动服务"。

### 1.3 核心能力
| 能力 | 说明 | 调用模型 |
|------|------|----------|
| **住前预判** | 预订阶段识别客户分层，提前准备服务 | 酒店客房产品模型 |
| **住中服务** | 入住期间实时响应需求，推荐餐饮/周边 | 酒店餐饮产品模型 + 景区旅游产品模型 |
| **住后跟进** | 离店后收集反馈，优化下次服务 | 全模型交叉验证 |
| **异常处理** | 满位/超时/投诉等异常自动升级 | 运营约束维度触发 |

---

## 二、智能体调用三个模型的逻辑

### 2.1 调用关系图

```
客户输入需求
    ↓
贵小智（客服智能体）
    ├─→ 调用【酒店客房产品模型】→ 识别客户分层 → 匹配客房/服务/预判
    ├─→ 调用【酒店餐饮产品模型】→ 匹配餐饮产品 → 联动客房特权
    └─→ 调用【景区旅游产品模型】→ 推荐周边 → 用时预估+交通方案
    ↓
输出：完整服务方案（客房+餐饮+周边）
```

### 2.2 调用规则

| 调用时机 | 触发条件 | 调用模型 | 输出 |
|----------|----------|----------|------|
| **预订阶段** | 客户下单/咨询 | 酒店客房产品模型 | 客户分层识别、服务预判指令 |
| **入住阶段** | 客户到店/入住中提问 | 酒店客房+餐饮模型 | 实时服务推荐、餐饮预订 |
| **用餐阶段** | 客户询问吃什么/早餐时间 | 酒店餐饮产品模型 | 餐饮推荐、房客特权提醒 |
| **游玩阶段** | 客户询问周边/旅游 | 景区旅游产品模型 | 景区推荐、交通方案、用时预估 |
| **离店阶段** | 客户退房/离店后 | 全模型交叉验证 | 满意度分析、下次服务优化 |

## 三、应用分析（5个服务场景）

### 场景1：客户预订阶段——智能体主动预判

**客户行为**：客户在OTA平台预订了贵州饭店舒适客房1晚。

**智能体调用流程**：

1. **抓取订单信息** → 客户分层识别
   - 客户分层：商务差旅客（单人预订、工作日、1晚）
   - 调用【酒店客房产品模型】→ 客群适配维度 → 商务出差匹配舒适客房

2. **预判服务需求** → 生成服务指令
   - 调用【酒店客房产品模型】→ 服务范围维度 → 商务客需要安静+效率
   - 输出指令：
     - 前台：安排高层安静房（远离电梯），确认早餐时间
     - 客房部：准备办公区用品（便签纸、签字笔）
     - 餐饮部：准备商务套餐菜单（工作餐A/B/C）

3. **主动触达客户**（入住前24小时）
   - 贵小智发送消息：
     > "您预订的是舒适客房，已为您备注安静朝向。请问早餐偏好中式还是西式？明日早餐时间6:30-10:00，商务套餐出餐约30分钟。"

**模型作用**：客房产品模型让客户在到店前就被"识别"和"准备"，不是到店后再问。

---

### 场景2：客户入住阶段——智能体实时服务

**客户行为**：客户到店办理入住，前台识别为预订阶段的商务客。

**智能体调用流程**：

1. **客户到店确认** → 调取预判档案
   - 贵小智自动推送：
     > "欢迎入住贵州饭店。您的房间已安排高层安静朝向，WiFi密码在房卡套内。商务中心在3楼，如需打印/复印可随时前往。"

2. **客户询问"附近有什么吃的"** → 调用餐饮模型
   - 调用【酒店餐饮产品模型】→ 客房联动维度 → 舒适客房享房客折扣
   - 输出推荐：
     > "酒店中餐厅有商务套餐（房客折扣），30分钟出餐。如果您想体验当地，步行5分钟有老字号肠旺面，步行10分钟有商场食街。需要我帮您预订中餐厅吗？"

3. **客户询问"明天有空想逛逛"** → 调用景区模型
   - 调用【景区旅游产品模型】→ 城市缓冲子类 → 黔灵山公园/甲秀楼
   - 输出推荐：
     > "您有半天时间，推荐两个选项：A. 黔灵山公园（打车15分钟，看猴子+划船，用时预估半天）；B. 甲秀楼夜景（打车10分钟，拍照+散步，用时预估1小时）。需要我帮您安排交通吗？"

**模型作用**：三个模型联动，客户一问"吃什么/玩什么"，智能体立即给出绑定客房特权的方案。

---

### 场景3：客户用餐阶段——智能体主动提醒

**客户行为**：客户未询问，到了早餐时间。

**智能体调用流程**：

1. **时间触发** → 早餐提醒
   - 调用【酒店餐饮产品模型】→ 运营约束维度 → 早餐时段6:30-10:00
   - 贵小智8:00推送：
     > "早餐时段6:30-10:00，餐厅在2楼。您住的舒适客房含早餐，直接报房号即可。今日有本地特色：肠旺面、牛肉粉。"

2. **客户反馈"早餐排队"** → 异常处理
   - 调用【酒店餐饮产品模型】→ 运营约束维度 → 等位时间/满位
   - 调用【酒店外餐饮模型】→ 周边快食/特色小吃 → 替代方案
   - 贵小智响应：
     > "早餐目前排队约15人，预计等位20分钟。如果您赶时间，推荐两个方案：A. 酒店大堂吧有快速简餐（咖啡+面包，5分钟）；B. 步行3分钟有便利店，饭团+豆浆即买即走。"

3. **客户晚上询问"有包间吗，6个人"** → 宴席推荐
   - 调用【酒店餐饮产品模型】→ 团体宴席 → 6人适用小型包间
   - 输出：
     > "6人推荐中餐厅小型包间，圆桌+分餐。房客折扣后人均约120元。菜单有黔菜/粤菜可选，需要我帮您预留包间并确认菜单吗？"

**模型作用**：智能体不是被动等客户问，而是主动提醒+异常时给出替代方案。

---

### 场景4：客户游玩阶段——智能体全程协助

**客户行为**：客户决定次日去黄果树瀑布，询问怎么安排。

**智能体调用流程**：

1. **客户表达意向** → 景区推荐
   - 调用【景区旅游产品模型】→ 自然奇观 → 黄果树瀑布
   - 输出基本信息：
     > "黄果树瀑布距离130公里，建议方案：A. 高铁（贵阳北→安顺西，30分钟）+景区接驳车；B. 包车（酒店协助预订，往返约400元）。用时预估1天，最佳游览6-10月。"

2. **智能体主动延伸** → 完整行程规划
   - 调用【酒店餐饮产品模型】→ 周边快食/外卖直达 → 早餐打包
   - 调用【酒店客房产品模型】→ 服务范围 → 延迟退房
   - 输出完整方案：
     > "为您规划明日行程：
     > - 7:00：早餐提前打包（已通知餐饮部）
     > - 7:30：包车出发（已预订，车牌贵A·XXXXX，司机会提前联系）
     > - 10:00-16:00：景区游览（门票已代订，刷身份证入园）
     > - 16:30：返程
     > - 19:00：到酒店，晚餐已预留中餐厅包间（如您需要）
     > 另外，已为您申请延迟退房至14:00，回来可休息。"

3. **客户游玩中临时提问** → 实时支持
   - 客户问"景区里有吃的吗" → 调用【景区旅游产品模型】→ 服务范围 → 景区餐饮
   - 输出：
     > "景区内有简餐（人均30-50），但选择少。建议您在景区门口吃，有当地餐馆（酸汤鱼、农家菜）。如果您不饿，可以回酒店吃，中餐厅已为您留位。"

**模型作用**：三个模型联合输出完整行程，不是只回答一个问题，而是解决一整天的安排。

---

### 场景5：客户离店阶段——智能体跟进优化

**客户行为**：客户退房，智能体触达反馈。

**智能体调用流程**：

1. **退房触发** → 满意度收集
   - 贵小智推送：
     > "感谢您的入住。请问本次体验：早餐是否满意？房间安静程度如何？如需发票，已发送至您邮箱。"

2. **客户反馈"早餐没有当地特色"** → 模型迭代
   - 调用【酒店餐饮产品模型】→ 酒店早餐 → 短板记录
   - 标记：客户分层=商务差旅客，反馈=早餐无属地特色
   - 系统自动更新：该客户下次入住时，早餐主动推荐"今日特色：肠旺面"

3. **客户复住预订** → 档案调用
   - 3个月后客户再次预订，智能体自动调取档案：
     > "欢迎再次选择贵州饭店。上次您反馈早餐希望增加当地特色，本次已安排。另外，您偏好高层安静房，已备注。"

**模型作用**：离店不是结束，是模型学习和下次服务优化的开始。

## 四、智能体与模型的交互架构

### 4.1 数据流

```
客户输入（文字/语音/行为）
    ↓
贵小智（NLP解析）→ 提取意图（住/吃/玩/投诉）
    ↓
模型选择器
    ├─ 意图=住 → 调用酒店客房产品模型
    ├─ 意图=吃 → 调用酒店餐饮产品模型
    ├─ 意图=玩 → 调用景区旅游产品模型
    └─ 意图=综合 → 三模型联动
    ↓
结果组装器 → 融合三个模型输出 → 生成完整服务方案
    ↓
客户输出（自然语言+卡片+预订链接）
```

### 4.2 关键调用规则

| 规则 | 说明 |
|------|------|
| **酒店内优先** | 客户询问餐饮/游玩时，优先推荐酒店内产品，再推荐周边 |
| **客房特权前置** | 任何推荐都先说明"您住的XX客房享XX特权" |
| **异常自动降级** | 酒店内满位/超预算时，自动调用周边模型给出替代 |
| **时间硬约束** | 营业时间/预订要求等运营约束不满足时，直接拒绝并给替代 |
| **客户分层记忆** | 每次交互都记录客户分层，复住时自动调取 |
