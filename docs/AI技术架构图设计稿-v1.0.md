## 各层详细说明

### 第一层：核心大模型底座（最内圈）

#### 1.1 企业自动驾驶大模型
**定位**：公司级核心关系网络与公共能力承载平台

| 核心要素 | 说明 |
|----------|------|
| 账户 | 全量账户体系、资金流向、持仓关系 |
| 资产 | 资产类别、估值、风险敞口、关联穿透 |
| 客户信息 | 个人/机构/企业客户画像、分层标签、行为轨迹 |
| 员工行为 | 员工操作日志、权限轨迹、业绩关联 |
| 合同协议 | 产品合同、服务协议、监管报备文件 |
| 决策流程 | 业务审批节点、决策链路、历史决策记录 |
| 法规制度 | 内部制度、监管规则、合规知识库、处罚案例 |

**能力输出**：
- 关系网络：任意要素间的关联/穿透查询
- 预判式动作驱动：基于事件触发自动准备动作
- 统一语料：全公司数据语义打通
- 身份打通：员工账户与系统账户统一

#### 1.2 企业技能蒸馏大模型
**定位**：业务知识→标准化模型的自动化蒸馏工厂

| 蒸馏能力 | 输出物 |
|----------|--------|
| 业务目标蒸馏 | 《业务目标清单》（经营什么、关键动作、衡量指标） |
| 标杆分析蒸馏 | 《标杆分析表》（找标杆、拆做法、评差距、定借鉴） |
| 数据关联蒸馏 | 《数据关联矩阵》（动作需要什么数据、在哪、怎么拿） |
| 模型定义蒸馏 | 角色体系 + 分析模型（3-5维度） + 动作模型（7事件） |
| 交叉验证/裁判验证 | 《交叉验证报告》+ 模型修正版 |

**核心规则内置**：
- 陶总五大反对（每步自动校验）
- 陶总八步可执行方法论（定目的→定角度→客观分类→提炼主维度→对比蒸馏→标准化建模→场景调用→监督迭代）
- 禁用词语表（自动替换/告警）

#### 1.3 底座公共能力池
- **智能体通信协议**：MCP（Model Context Protocol）+ A2A（Agent-to-Agent）
- **记忆系统**：短期记忆（会话上下文）+ 长期记忆（知识库、历史经验）
- **工具调用白名单**：限定可调用的工具范围，高风险操作审批流
- **工程级提示词管理**：系统提示词（角色/约束/工具）+ 交互提示词（动态上下文）
- **统一身份认证**：员工身份与系统权限统一

### 第二层：标准化业务模型（第二圈）

**定位**：可被AI调用、可被员工执行的标准化技能原子库

每个业务模型包含：

| 模型类型 | 内容 | 示例 |
|----------|------|------|
| **分析模型** | 3-5个本质维度，围绕角色核心诉求 | 投行定增：企业质地、发行条件、合规性、市场窗口、承做能力 |
| **动作模型** | 7事件结构：事件-触发-步骤-输出-异常-时限 | 债券发行：承揽→立项→辅导→申报→审核→发行→持续督导 |
| **通用支撑模型** | 跨业务线复用的基础能力 | 客户身份识别、适当性匹配、合规校验、知识检索 |

**已沉淀模型资产**：
- 投行定增分析模型 v5.0（5维度）
- 债券发行分析模型 v2.0（具体指标版）
- 客户服务分析模型 v3.0（个人/机构客户）
- 资管业务分析模型（5维度：产品需求/策略质量/结构合规/客户匹配/投后风险）
- 交叉验证模型（裁判验证机制）

**模型调用方式**：
- AI直接调用：智能体执行任务时自动匹配模型
- 人工查阅：员工通过工作台查看模型标准
- 场景组合：多个模型组合应对复杂业务场景

### 第三层：应用级智能体（第三圈）

**定位**：面向具体业务场景的超级数字员工，执行规定动作

#### 按业务线划分的智能体矩阵

| 业务线 | 智能体 | 角色定位 | 核心能力 | 合规风险等级 |
|--------|--------|----------|----------|--------------|
| **财富管理** | 财富管家 | 客户专属配置顾问 | 客户画像→SAA配置→方案生成→调仓建议 | 高（投资建议） |
| | 投顾助手 | 投顾AI副驾驶 | 研报解读、组合诊断、话术辅助、合规检查 | 高（投资建议） |
| | 运营精灵 | 客户运营自动化 | 流失预警、触达策略、投教内容、回访外呼 | 中 |
| **投资银行** | 投行承揽雷达 | 项目情报分析 | 行业扫描、企业快筛、上市条件匹配 | 低 |
| | 尽调助手 | 尽调执行辅助 | 底稿整理、关联方穿透、历史处罚匹配 | 中 |
| | 内核预审官 | 内核前置检查 | 完整性扫描、财务勾稽、敏感表述检测 | 高（内核意见） |
| **资产管理** | 资管产品官 | 产品创设+销售支持 | 需求洞察→策略回测→合同初稿→销售准备 | 高（适当性匹配） |
| | 合规守卫 | 合规风控专员 | 全链路合规校验、红线检测、人工升级 | 高（合规审查） |
| **研究** | 研究助手 | 研究员AI副驾驶 | 信息聚合、初稿生成、数据校验、格式规范 | 中 |
| **交易** | 交易能力 | 交易执行支持 | 行情分析、策略信号、风险监测 | 高（交易合规） |
| **资产分析** | 资产分析师 | 基础/债券/股票分析 | 财务分析、估值建模、行业对标 | 中 |

#### 每个智能体的标准配置

| 配置项 | 说明 |
|--------|------|
| 角色定义 | 角色名称 + 目标 + 背景（Role/Goal/Backstory） |
| 规定动作 | 事件-触发-步骤-输出-异常-时限-验收标准 |
| 可调用模型 | 关联的第二层标准化业务模型 |
| 工具清单 | 白名单内的工具（数据库/API/文档/计算） |
| 合规节点 | 三句话法：可以/必须确认/不 |
| 记忆配置 | 短期记忆（会话）+ 长期记忆（知识库） |
| 人机协作界面 | Human-in-the-loop分级机制 |

## 层间数据流与调用关系

```
用户请求 → 应用级智能体（第三层）
              ↓
        调用标准化业务模型（第二层）
              ↓
        查询企业自动驾驶大模型（底座数据）
              ↓
        执行规定动作
              ↓
        输出结果 → 用户
              ↓（如需新模型）
        触发企业技能蒸馏大模型（模型蒸馏）
              ↓
        生成/更新标准化业务模型（第二层迭代）
```

### 典型调用链路示例

**链路1：财富管理客户开户配置**
```
用户（高净值客户）→ 财富管家（第三层）
    ↓ 调用《财富管理分析模型》（第二层）
    ↓ 查询客户画像数据（第一层：企业自动驾驶大模型）
    ↓ 执行动作：KYC→SAA→配置方案
    ↓ 合规校验：合规守卫（第三层）审核
    ↓ 输出：配置方案（需人工确认）→ 客户
```

**链路2：投行新项目立项**
```
用户（投行前台）→ 投行承揽雷达（第三层）
    ↓ 调用《投行定增分析模型》（第二层）
    ↓ 查询企业/行业/合规数据（第一层）
    ↓ 执行：行业扫描+企业快筛+上市条件匹配
    ↓ 输出：项目情报简报（可直接使用）
```

**链路3：新业务线模型蒸馏**
```
用户（业务支持中心）→ 企业技能蒸馏大模型（第一层）
    ↓ 输入：新业务线知识材料
    ↓ 执行五步法：目标→标杆→数据→模型→验证
    ↓ 输出：标准化业务模型（更新至第二层）
    ↓ 应用级智能体自动继承新模型能力（第三层）
```

## 与业务架构图的对应关系

| 业务架构图（前图） | 技术架构图（本图） | 对应关系 |
|-------------------|-------------------|----------|
| 资金大模型（底座） | 企业自动驾驶大模型 + 企业技能蒸馏大模型 | 升级：从"资金"扩展到全公司级自动驾驶+蒸馏能力 |
| 八大业务支持模块 | 第二层标准化业务模型 | 细化：每个业务模块→分析模型+动作模型+通用支撑 |
| 超级数字员工（7个） | 第三层应用级智能体（11个+） | 扩展：更细粒度的角色拆分，每个有完整配置 |
| 客户分层（个人/机构/企业） | 第四层各类角色用户 | 对齐：从客户身份出发，不是从渠道出发 |

## 绘图建议（供设计师参考）

### 视觉风格建议
- **圈层形式**：同心圆或椭圆环，与业务架构图保持一致
- **颜色体系**：
  - 第一层（底座）：深蓝/深灰（稳重、基础）
  - 第二层（模型）：中蓝（标准化、可复用）
  - 第三层（智能体）：亮蓝/橙色（活力、可交互）
  - 第四层（用户）：浅蓝/白色（服务对象、外部）
- **连线方式**：
  - 层内：实线连接（同一层内的协作关系）
  - 层间：虚线箭头（数据流/调用方向）
  - 底座向外：放射状虚线（底座支持所有上层）
