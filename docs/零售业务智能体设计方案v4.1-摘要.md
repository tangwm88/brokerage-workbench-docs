# 《证券公司零售业务智能体设计方案 v4.1》摘要

> 基于用户目标背景重新设计：
> - 面向：投资者 + 客户经理 + 团队长
> - 目标：模型自动化服务80%客户，人工叠加服务20%
> - 时间：2026-06-19

---

## 核心变化（相比v4.0）

### 1. 动作模型从"场景级"重构为"原子级"

| 维度 | v4.0 | v4.1 |
|------|------|------|
| **动作模型** | 6个场景级（客户触达/持仓复盘/产品配置/风险安抚/流失挽回/团队管理） | 4个原子级（触达/诊断/建议/执行） |
| **场景表达** | 第三层（混淆场景与原子） | 第二层（场景=原子组合） |
| **扩展性** | 每新增场景需新增动作模型 | 新增场景只需组合原子 |
| **重复度** | 每个场景都写一遍"触达→诊断→建议" | 原子写一次，场景引用即可 |

### 2. 先原子、后组合的设计逻辑

**分析过程：**

| 场景 | 客户经理实际做了什么 |
|------|-------------------|
| 新客首触 | 联系客户 → 了解资产/需求 → 推荐首单 → 记录 |
| 定期复盘 | 预约客户 → 分析持仓 → 建议调整 → 记录 |
| 大额亏损关注 | 联系客户 → 分析亏损原因 → 给优化建议 → 记录 |
| 产品配置 | 邀约客户 → 评估适当性 → 出配置方案 → 双录下单 → 记录 |
| 流失挽回 | 联系客户 → 了解流失原因 → 给挽留方案 → 记录 |
| 投诉处理 | 联系客户 → 核实情况 → 给处理方案 → 落实 → 记录 |

**共性收敛：**

无论场景如何变化，始终逃不出这4个动作：

1. **触达** — 不管什么场景，第一步都是和客户建立联系
2. **诊断** — 不管面对什么客户，都要先分析评估现状
3. **建议** — 不管诊断出什么，都要给出专业方案
4. **执行** — 客户认可后，协助完成业务落地（部分场景需要）

> **差异在触发条件和侧重点，动作本身是共性的。**

### 3. 三层模型体系（对齐架构图v2.0）

```
第一层：客户分析模型（4个本质维度）
├── 资金体量（S/A/B/C四档，决定服务等级）
├── 交易倾向（高频/中频/低频/超低频/零交易五档）
├── 当前状态（大幅盈利/稳健盈利/盈亏平衡/小幅亏损/深度亏损五档）
└── 生命周期（潜在/新客/尝鲜/活跃/沉睡/忠诚/流失/回流八档）

第二层：服务模型（场景化组合）
├── 自动化信息服务（100%自动）
├── 自动化产品匹配服务（100%自动）
├── 人工叠加服务标准（模型触发→客户经理按原子组合执行）
│   ├── 场景1：首触服务 = 触达 + 诊断 + 建议
│   ├── 场景2：定期复盘服务 = 触达 + 诊断 + 建议
│   ├── 场景3：大额亏损关注服务 = 触达 + 诊断 + 建议
│   ├── 场景4：产品配置服务 = 触达 + 诊断 + 建议 + 执行
│   ├── 场景5：流失挽回服务 = 触达 + 诊断 + 建议
│   └── 场景6：投诉处理服务 = 触达 + 诊断 + 建议 + 执行
└── 团队管理服务（团队长执行，单独列出）

第三层：动作模型（4个原子动作，七事件格式）
├── 动作1：触达（建立联系）
├── 动作2：诊断（分析评估）
├── 动作3：建议（方案输出）
└── 动作4：执行（业务落地）
```

### 4. 原子动作的七事件格式

每个原子动作都包含：触发条件 → 执行步骤 → 输出标准 → 异常处理 → 时限要求 → 验收标准。

**触达动作：**
- 触发：任务单/周期/客户主动
- 步骤：调取标签 → 确认要点 → 选择渠道 → 执行触达 → 记录结果
- 时限：紧急24小时/常规72小时

**诊断动作：**
- 触发：触达后默认/重大变化/定期
- 步骤：调取数据 → 资金诊断 → 持仓诊断 → 需求诊断 → 关系诊断 → 输出结论 → 记录结果
- 时限：触达后1小时

**建议动作：**
- 触发：诊断后默认/客户要求/复盘场景
- 步骤：读取诊断 → AI生成方案 → 审核合规 → 讲解方案 → 确认意向 → 记录结果
- 时限：诊断后2小时

**执行动作：**
- 触发：客户接受/主动办理/异常操作
- 步骤：确认内容 → 校验合规 → 执行业务 → 确认结果 → 记录结果
- 时限：客户确认后即时

### 5. 场景差异在"组合"和"侧重"，不在动作本身

| 场景 | 动作组合 | 诊断侧重 | 建议类型 |
|------|---------|---------|---------|
| 首触 | 触达+诊断+建议 | 需求诊断+资金诊断 | 产品建议（首单低风险） |
| 定期复盘 | 触达+诊断+建议 | 持仓诊断+资金诊断 | 配置建议+产品建议 |
| 大额亏损 | 触达+诊断+建议 | 持仓诊断+关系诊断 | 操作建议+产品建议 |
| 产品配置 | 触达+诊断+建议+执行 | 需求诊断+资金诊断 | 配置建议+产品建议 |
| 流失挽回 | 触达+诊断+建议 | 关系诊断+资金诊断 | 服务建议+产品建议 |

## 与v4.0的关键差异

| 维度 | v4.0 | v4.1 |
|------|------|------|
| **动作模型** | 6个场景级 | 4个原子级 |
| **扩展性** | 新增场景需新增动作模型 | 新增场景只需组合原子 |
| **角色对齐** | 团队管理混入客户经理层 | 团队长单独列出 |
| **共性提炼** | 未显式分析 | 显式分析→收敛为4个原子 |
| **重复度** | 高（每个场景重复写触达诊断建议） | 低（原子写一次，场景引用） |

## 80%自动化 vs 20%人工叠加

**自动化层（无需人工）：**
- 客户标签自动更新
- 市场信息/持仓异动/到期提醒推送
- 标准化投后报告
- 沉睡客户自动唤醒
- 基础产品匹配推荐

**人工叠加层（客户经理按原子动作执行）：**
- 高价值客户定期服务：触达+诊断+建议
- 大额亏损关注：触达+诊断+建议
- 产品配置：触达+诊断+建议+执行
- 流失挽回：触达+诊断+建议
- 投诉处理：触达+诊断+建议+执行

## 三句话法合规节点

| 服务类型 | 判断 | 智能体动作 |
|---------|------|-----------|
| 自动化信息推送 | 可以 | 全自动 |
| 标准化产品推荐（R1-R2） | 可以 | 自动推荐，客户自助决策 |
| 资产配置方案/R4-R5产品 | 必须确认 | AI生成→人工审核→双录→执行 |
| 投资建议/个股推荐 | 不 | 直接拒绝，标记原因 |
| 承诺保本保收益 | 不 | 直接拒绝，标记原因 |
