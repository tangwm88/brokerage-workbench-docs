# 财富管理业务原子模型组合闭环设计

> **定位**：展示财富管理业务线各原子模型如何组合形成"感知→理解→决策→执行→反馈"完整闭环  
> **版本**：v1.0  
> **更新日期**：2026-07-27  
> **参照映射**：报告金融案例"统一客户实体图谱+多层穿透+合规规则本体" → 我们的"客户分类本体+底座关系网络+三句话法合规"

---

## 一、映射关系确认

| 报告金融案例（反洗钱） | 我们的原子模型体系 | 对应说明 |
|----------------------|------------------|---------|
| **统一客户实体图谱** | **I001 个人客户分类本体** | 客户实体的标准化定义，含社会分层/风险/经验/需求/行为五维标签 |
| **多层穿透** | **底座层关系网络 + D005/D008/D010/D012** | 客户→账户→交易→关联方的穿透，由数据原子模型实时感知 |
| **合规规则本体** | **三句话法决策引擎 + A003合规审查 + D004监管政策** | 从规则定义到自动执行的全链路合规 |
| **双层规则体系** | **硬约束/软约束/触发约束/连锁约束** | 本地业务规则+全局合规标准的分层设计 |

### 2.1 闭环参与原子模型清单

| 层级 | 参与模型 | 作用 |
|------|---------|------|
| **数据感知** | D008/D009/D010/D011/D012 | 实时感知客户状态、市场机会、生命周期、产品业绩、竞品动态 |
| **语义理解** | I001个人客户分类本体 + P001产品本体 + S001服务本体 | 统一客户语义、产品语义、服务语义 |
| **推理决策** | R001适当性匹配规则 + R002持仓回撤处置规则 + R003流失预警规则 | 逻辑推理、一致性校验、触发判定 |
| **行动执行** | A002财富管理动力函数 + A005客户运营动力函数 | 跨系统执行、动作编排、权限控制 |
| **反馈更新** | 闭环演化机制 | 执行结果回流、本体实例更新、模型优化 |

    │   <30%: 自动执行档 → 轻量关怀(市场周报/机会摘要) → 自动推送

    │   Step 4: 生成个性化挽留内容(LLM + 画像数据)
    │   Step 5: 决策档判定(自动/推演/必须确认)
    │   Step 6: 人工确认(推演档→客户经理4h SLA / 必须确认档→运营主管8h SLA)
    │   Step 7: 客户触达(APP推送 + 电话预约 + 面访安排)

### 8.2 异常处理矩阵（完整版）

| 异常场景 | 触发条件 | 处理方式 | 升级路径 | 记录要求 |
|---------|---------|---------|---------|---------|
| **API超时** | 调用>3倍超时阈值 | 重试3次→降级人工→标记待处理 | 技术运维 | 全链路日志 |
| **内容生成失败** | LLM返回异常/空值 | 模板内容替代→标记待优化 | 产品经理 | 生成日志 |
| **联系方式失效** | 推送失败/退订 | 查询备用→仍无效标记→客户经理 | 客户经理 | 失效记录 |
| **适当性校验冲突** | 客户等级∉产品要求 | 拒绝匹配→人工复核→记录原因 | 合规部 | 冲突日志 |
| **人工确认超时** | 推演档>4h/必须确认>8h | 自动升级上级→SLA告警 | 部门负责人 | 超时记录 |
| **批量营销投诉** | 投诉率>2% | 暂停批次→内容复盘→合规审核 | 合规部 | 投诉分析 |
| **系统级阻断** | 硬约束触发 | 阻断执行→记录原因→通知相关方 | 自动 | 阻断日志 |
| **数据不一致** | 多源数据冲突 | 主数据源优先→标记差异→人工核查 | 数据治理 | 差异报告 |
| **权限不足** | 操作者无权限 | 拒绝执行→权限申请→审计留痕 | 安全部 | 权限日志 |
| **外部系统故障** | 对接系统不可用 | 降级模式→本地缓存→定时重试 | 技术运维 | 故障记录 |
| **监管突发指令** | 监管政策紧急变更 | 全量扫描→受影响客户通知→规则更新 | 合规部+高管 | 政策留痕 |
| **客户紧急诉求** | 客户致电/到访要求紧急处理 | 即时标记→专属通道→ bypass常规队列 | 客户总监 | 服务记录 |
