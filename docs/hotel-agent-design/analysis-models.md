# 酒店业务分析模型

> **版本**：v1.0
> **日期**：2026-06-10
> **遵循规范**：禁用词语表（不用场景、流程、话术、逻辑、偏好等黑话）
> **设计原则**：先定角色，再写模型，维度跟着角色走。每个模型3-5个本质维度。

---

## 一、客户分析模型（服务接收方视角）

### 1.1 角色定位

**目标角色**：酒店客人
**核心诉求**：获得适合自己的舒适住宿体验

> 无论客人从什么渠道预订（OTA、官网、协议公司、旅行社），本质都是酒店客人。渠道差异由系统处理，服务体验从角色统一出发。

### 1.2 本质维度（3-5个）

| 维度 | 核心问题 | 分析框架 | 判断标准 | 输出指向 |
|------|---------|---------|---------|---------|
| **1. 入住前期待** | 客人预订时想要什么？ | 预订信息 + 历史数据 + 外部标签 | 需求清晰度、特殊需求明确度 | 入住准备动作 |
| **2. 入住中感知** | 客人实际体验如何？ | 服务请求频次、响应时间、满意度、问题记录 | 服务响应是否达标、问题是否解决 | 服务改进动作 |
| **3. 离店后评价** | 客人离开后怎么看？ | 评价内容、复购意愿、推荐意愿、投诉记录 | 整体满意度、复购概率 | 复购促进动作 |

### 1.3 维度详细说明

#### 维度1：入住前期待

**核心问题**：客人预订时想要什么？

**分析框架**：
- 预订信息：入住人数、天数、房型、入住时间、渠道来源
- 历史数据：是否历史会员、过往偏好、入住记录、投诉历史
- 外部标签：OTA标签、协议公司类型、预订行为（提前多久、是否加购早餐、是否要求加床、备注内容）
- 类型判断：AI根据以上信息自动判断客人类型（商务/家庭/情侣/会议/长住/特殊）

**判断标准**：
- 需求清晰：预订信息完整，备注明确 → 入住准备可精准执行
- 需求模糊：预订信息简略，无备注 → 需主动询问，避免默认假设
- 特殊需求：备注有明确需求（无障碍、婴儿床、过敏） → 必须标记为"必须确认"

**输出指向**：
- 入住准备动作：按类型准备对应物品和服务
- 主动询问：对模糊需求，在入住前1-2天主动询问

#### 维度2：入住中感知

**核心问题**：客人实际体验如何？

**分析框架**：
- 服务请求：请求次数、类型、响应时间、解决率
- 主动服务：AI预判的主动服务是否被接受、客人反馈
- 问题记录：投诉、故障、不满、重复请求
- 满意度：实时评分（入住中可推送1-2次简短评价）、行为数据（是否延长入住、是否加购服务）

**判断标准**：
- 体验良好：请求少、响应快、无投诉、评分高 → 维持服务，触发关怀
- 体验一般：有1-2次请求、响应正常、无投诉 → 主动关怀，预防不满
- 体验不佳：请求多、响应慢、有投诉、评分低 → 立即干预，升级处理

**输出指向**：
- 服务改进：针对响应慢、未解决的问题，调整服务动作
- 主动关怀：对体验一般的客人，主动推送关怀（如水果、问候）
- 升级处理：对体验不佳的客人，立即升级给运营组织者

#### 维度3：离店后评价

**核心问题**：客人离开后怎么看？

**分析框架**：
- 评价内容：OTA评分、文字评价、关键词提取（满意点/不满点）
- 复购意愿：是否再次预订、是否加入会员、是否推荐他人
- 投诉记录：离店后投诉、退款要求、社交媒体差评
- 行为数据：离店后是否关注酒店公众号、是否领取优惠

**判断标准**：
- 高价值客人：评价高、复购意愿强、推荐他人 → 重点维护，推送会员权益
- 一般客人：评价中、复购不确定 → 推送优惠，促进复购
- 风险客人：评价低、有投诉、不复购 → 分析原因，针对性改进

**输出指向**：
- 复购促进：对高价值和一般客人，推送个性化优惠和会员权益
- 改进动作：对风险客人，分析不满原因，反馈给对应角色改进
- 经验沉淀：将评价中的共性问题，转化为标准动作改进

### 1.4 模型输出格式

```yaml
客户分析结果:
  客人ID: "G20260610001"
  类型判断: "商务差旅"
  置信度: 92%
  
  维度1_入住前期待:

    特殊需求: "快速入住、发票"
    判断依据: "提前3天预订，备注'商务出行，需发票'，历史入住12次，均为商务类型"
    准备动作:
      - "预登记身份"
      - "准备快速入住通道"
      - "绑定发票模板"
      
  维度2_入住中感知:
    服务请求: 2次（送毛巾、调温度）
    响应时间: 平均8分钟
    投诉记录: 无
    满意度: 4.5/5
    判断: "体验良好"
    动作: "维持服务，离店前主动关怀"
    
  维度3_离店后评价:
    评分: 4.5/5（OTA）
    复购意愿: "高"（历史复购率80%）
    推荐意愿: "是"
    判断: "高价值客人"
    动作: "推送会员权益，邀请加入VIP"
    
  综合建议: "维持当前服务标准，离店前主动关怀，推送复购优惠"
```

## 二、服务质量分析模型（服务交付方视角）

### 2.1 角色定位

**目标角色**：酒店服务人员（前台/客房/餐饮/管家/工程）
**核心诉求**：标准动作执行到位，服务响应及时，客人满意

### 2.2 本质维度（3-5个）

| 维度 | 核心问题 | 分析框架 | 判断标准 | 输出指向 |
|------|---------|---------|---------|---------|
| **1. 动作执行率** | 标准动作做了多少？ | 任务完成数/任务分配数 × 100% | 执行率≥95%为达标 | 绩效评估、培训改进 |
| **2. 响应时效** | 客人等了多久？ | 请求时间→响应时间→完成时间 | 紧急≤5分钟、常规≤30分钟 | 人员调配、流程优化 |
| **3. 客人满意度** | 客人对服务满意吗？ | 服务后评价、投诉率、重复请求率 | 满意度≥4.5/5、投诉率≤2% | 服务改进、奖惩 |
| **4. 异常处理率** | 出问题了怎么处理的？ | 异常次数、升级次数、解决率、重复异常率 | 升级率≤10%、重复异常率≤5% | 培训、流程改进 |

### 2.3 维度详细说明

#### 维度1：动作执行率

**核心问题**：标准动作做了多少？

**分析框架**：
- 任务分配：AI自动分配的任务总数
- 任务完成：按时完成的任务数
- 任务延迟：延迟完成的任务数及延迟时长
- 任务跳过：跳过未完成的任务数及原因

**判断标准**：
- 达标：执行率≥95%，延迟率≤5% → 维持标准
- 注意：执行率90-95%，延迟率5-10% → 分析原因，改进
- 不达标：执行率<90%，延迟率>10% → 立即干预，调整人员或标准

**输出指向**：
- 绩效评估：纳入员工月度/季度绩效
- 培训改进：对执行率低的动作，针对性培训
- 标准调整：如多人同一动作执行率低，考虑标准是否过紧

#### 维度2：响应时效

**核心问题**：客人等了多久？

**分析框架**：
- 紧急请求：安全、医疗、投诉、严重故障 → 响应时间
- 常规请求：送物品、调温度、餐饮 → 响应时间
- 预判服务：AI预判的主动服务 → 触发时机是否恰当

**判断标准**：
- 紧急请求：≤5分钟响应，≤30分钟解决 → 达标
- 常规请求：≤30分钟响应，≤2小时解决 → 达标
- 预判服务：时机恰当，客人接受率≥80% → 达标

**输出指向**：
- 人员调配：响应慢时段，增加人手
- 流程优化：响应慢的环节，简化流程或增加资源
- 预判调整：预判服务接受率低，调整触发时机或内容

#### 维度3：客人满意度

**核心问题**：客人对服务满意吗？

**分析框架**：
- 服务后评价：每次服务完成后可推送简短评价（1-5星）
- 投诉率：投诉次数/服务次数 × 100%
- 重复请求率：同一问题重复请求次数 → 反映问题未解决
- 整体评分：离店时整体评分

**判断标准**：
- 满意：满意度≥4.5/5，投诉率≤2%，重复请求率≤5% → 维持
- 一般：满意度4.0-4.5/5，投诉率2-5%，重复请求率5-10% → 改进
- 不满：满意度<4.0/5，投诉率>5%，重复请求率>10% → 紧急干预

**输出指向**：
- 服务改进：针对不满点，改进服务标准
- 奖惩：满意度高奖励，满意度低培训或调整岗位
- 客人关怀：对不满客人，主动补偿和关怀

#### 维度4：异常处理率

**核心问题**：出问题了怎么处理的？

**分析框架**：
- 异常次数：各类异常（故障、投诉、服务失误）发生次数
- 升级次数：需升级给运营组织者的次数
- 解决率：异常最终解决的比例
- 重复异常率：同一问题重复发生的比例

**判断标准**：
- 良好：升级率≤10%，解决率≥95%，重复异常率≤5% → 维持
- 注意：升级率10-20%，解决率90-95%，重复异常率5-10% → 分析原因
- 不佳：升级率>20%，解决率<90%，重复异常率>10% → 紧急改进

**输出指向**：
- 培训：对常见异常，培训标准处理动作
- 流程改进：对重复异常，改进流程或增加预防机制
- 设备维护：对设备相关异常，加强巡检和预防维护

### 2.4 模型输出格式

```yaml
服务质量分析结果:
  分析周期: "2026-06-01至2026-06-10"
  
  维度1_动作执行率:
    总任务: 1200
    完成: 1150
    延迟: 40
    跳过: 10
    执行率: 95.8%
    延迟率: 3.3%
    判断: "达标"
    动作: "维持标准，关注延迟任务原因"
    
  维度2_响应时效:
    紧急请求: 50次，平均响应3分钟
    常规请求: 800次，平均响应18分钟
    预判服务: 350次，接受率85%
    判断: "达标"
    动作: "维持，预判服务接受率良好"
    
  维度3_客人满意度:
    服务后评价: 4.6/5
    投诉率: 1.5%
    重复请求率: 4%
    判断: "满意"
    动作: "维持，奖励优秀员工"
    
  维度4_异常处理率:
    异常次数: 60
    升级次数: 5（升级率8.3%）
    解决率: 98%
    重复异常率: 3%
    判断: "良好"
    动作: "维持，对重复异常设备加强维护"
    
  综合建议: "服务质量整体达标，维持当前标准，关注延迟任务根因，奖励优秀员工"
```

## 三、客户分层/画像模型（运营组织者视角）

### 3.1 角色定位

**目标角色**：运营组织者（值班经理/运营主管）
**核心诉求**：知道哪些客人是重点，哪些需要特别关注，资源怎么分配

### 3.2 本质维度（3-5个）

| 维度 | 核心问题 | 分析框架 | 判断标准 | 输出指向 |
|------|---------|---------|---------|---------|
| **1. 客户价值** | 这个客人值多少？ | 历史消费、消费频次、平均客单价、推荐价值 | 高价值/一般价值/低价值 | 资源分配、关怀优先级 |
| **2. 客户活跃度** | 这个客人多久来一次？ | 入住频次、间隔时间、预订提前期、渠道活跃度 | 活跃/一般/沉睡 | 复购促进、唤醒策略 |
| **3. 客户风险** | 这个客人会不会出问题？ | 投诉历史、退款要求、特殊需求复杂度、社会影响力 | 高风险/中风险/低风险 | 预防措施、升级准备 |
| **4. 客户潜力** | 这个客人未来能贡献多少？ | 消费增长趋势、类型变化（商务→家庭→会议）、会员升级潜力 | 高潜力/一般潜力/低潜力 | 培育策略、会员升级 |

### 3.3 维度详细说明

#### 维度1：客户价值

**核心问题**：这个客人值多少？

**分析框架**：
- 历史消费：累计消费金额、平均客单价、最高单次消费
- 消费频次：年入住次数、间隔时间、连续入住天数
- 推荐价值：推荐他人入住次数、被推荐人消费金额
- 综合价值：消费金额 × 频次 × 推荐价值系数

**判断标准**：
- 高价值：综合价值排名前20% → 重点维护，优先资源
- 一般价值：综合价值排名20-60% → 常规维护，适度关怀
- 低价值：综合价值排名后40% → 基础服务，不过度投入

**输出指向**：
- 资源分配：高价值客人优先分配好房间、快速响应、专属关怀
- 关怀优先级：高价值客人优先安排关怀动作（如升级、水果、问候）
- 会员权益：高价值客人优先邀请加入高级会员

#### 维度2：客户活跃度

**核心问题**：这个客人多久来一次？

**分析框架**：
- 入住频次：年入住次数、月均入住次数
- 间隔时间：两次入住的平均间隔
- 预订提前期：提前多久预订（临时/提前/计划）
- 渠道活跃度：是否关注公众号、是否使用APP、是否参与活动

**判断标准**：
- 活跃：年入住≥6次，间隔≤2个月，渠道活跃 → 维持，增加粘性
- 一般：年入住3-5次，间隔2-6个月，渠道一般 → 促进，推送优惠
- 沉睡：年入住<3次，间隔>6个月，渠道不活跃 → 唤醒，推送优惠+关怀

**输出指向**：
- 复购促进：对一般客人，推送个性化优惠和会员权益
- 唤醒策略：对沉睡客人，推送限时优惠和关怀，激活复购
- 粘性增强：对活跃客人，增加专属权益和个性化服务

#### 维度3：客户风险

**核心问题**：这个客人会不会出问题？

**分析框架**：
- 投诉历史：投诉次数、投诉类型、投诉处理结果
- 退款要求：退款次数、退款金额、退款原因
- 特殊需求复杂度：需求种类、需求变化频率、需求满足难度
- 社会影响力：社交媒体粉丝数、是否KOL/网红、是否有公开评价习惯

**判断标准**：
- 高风险：投诉≥3次，或退款≥2次，或KOL/网红，或需求复杂且频繁变化 → 重点预防，升级准备
- 中风险：投诉1-2次，或退款1次，或需求较复杂 → 适度关注，主动关怀
- 低风险：无投诉，无退款，需求简单 → 常规服务，不过度关注

**输出指向**：
- 预防措施：对高风险客人，提前准备应对方案（如房间预留、服务升级）
- 升级准备：对高风险客人，入住时即通知运营组织者关注
- 服务调整：对需求复杂的客人，提前安排管家一对一服务

#### 维度4：客户潜力

**核心问题**：这个客人未来能贡献多少？

**分析框架**：
- 消费增长趋势：近3次消费是否增长、消费类型是否扩展（从单房型到套房、从单人到团队）
- 类型变化：是否从单一类型向多类型扩展（如商务客人开始带家人度假）
- 会员升级潜力：当前会员等级、距离下一等级差多少、升级后消费预期
- 企业/团队潜力：是否企业员工、是否可能带来团队预订、是否有会议需求

**判断标准**：
- 高潜力：消费增长趋势明显，类型扩展，企业背景 → 重点培育，主动推荐
- 一般潜力：消费稳定，类型单一，无企业背景 → 维持，适度推荐
- 低潜力：消费下降，类型单一，无扩展迹象 → 基础服务，不主动推荐

**输出指向**：
- 培育策略：对高潜力客人，主动推荐新服务（如会议、团队、长住）
- 会员升级：对高潜力客人，推送会员升级优惠和权益
- 企业合作：对有企业背景的客人，主动推荐企业协议和团队服务

### 3.4 模型输出格式

```yaml
客户分层画像:
  客人ID: "G20260610001"
  姓名: "张XX"
  
  维度1_客户价值:
    历史消费: "¥48,000"
    年入住: 12次
```

## 四、模型间关系

```
客户分析模型（客人视角）
    ↓ 输出客人体验状态
服务质量分析模型（员工视角）
    ↓ 输出服务质量状态
客户分层画像模型（管理者视角）
    ↓ 输出资源分配策略
运营决策（人员调配、关怀策略、促销策略）
```

**关系说明**：
- 客户分析模型关注"客人体验"，输出客人的期待、感知、评价
- 服务质量分析模型关注"服务执行"，输出员工动作的执行情况
- 客户分层画像模型关注"资源分配"，输出客人的价值、活跃度、风险、潜力
- 三个模型共同支撑运营决策：谁需要优先服务、谁需要关怀、谁需要唤醒、谁需要预防

## 五、检查清单

### 5.1 角色层
- [x] 客户分析模型目标角色：酒店客人（服务接收方）
- [x] 服务质量分析模型目标角色：酒店服务人员（服务交付方）
- [x] 客户分层画像模型目标角色：运营组织者（管理/决策层）
- [x] 每个模型有明确的核心诉求（一句话说清）
- [x] 每个模型的维度服务于角色核心诉求

### 5.2 维度层
- [x] 客户分析模型：3个维度（入住前期待、入住中感知、离店后评价）
- [x] 服务质量分析模型：4个维度（动作执行率、响应时效、客人满意度、异常处理率）
- [x] 客户分层画像模型：4个维度（客户价值、客户活跃度、客户风险、客户潜力）
- [x] 每个维度都有核心问题、分析框架、判断标准、输出指向
- [x] 维度之间无逻辑重叠
- [x] 维度之间无逻辑矛盾

### 5.3 视角层
- [x] 客户分析模型从客人视角出发（期待、感知、评价）
- [x] 服务质量分析模型从员工视角出发（执行、时效、满意度、异常）
- [x] 客户分层画像模型从管理者视角出发（价值、活跃度、风险、潜力）
- [x] 摒弃了渠道差异（所有渠道来源统一为"酒店客人"）
- [x] 语言讲人话，无术语（不用"场景""流程""逻辑""话术""偏好"）

### 5.4 验证层
- [x] 模型内部维度自洽（每个维度独立、互补、不矛盾）
- [x] 模型间衔接清晰（客人体验→服务执行→资源分配→运营决策）
- [x] 输出有动作指向（每个维度分析后都有下一步动作）
- [x] 角色边界清晰（不越权、不遗漏）
