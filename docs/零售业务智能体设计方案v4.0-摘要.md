# 《证券公司零售业务智能体设计方案 v4.0》生成完成

> 基于用户目标背景重新设计：
> - 面向：投资者 + 客户经理 + 团队长
> - 目标：模型自动化服务80%客户，人工叠加服务20%
> - 时间：2026-06-18

---

## 核心变化（相比v3.0）

### 1. 先定角色，再写模型

| 角色 | 定位 | 与模型的关系 |
|------|------|------------|
| **投资者** | 被服务方 | 接收自动化服务，响应人工触达 |
| **客户经理** | 执行方 | 执行动作模型触发的任务单 |
| **团队长** | 管理方 | 穿透团队全貌，调配资源 |

### 2. 三层模型体系（对齐架构图v2.0）

```
第一层：客户分析模型（4个本质维度）
├── 资金体量（S/A/B/C四档，决定服务等级）
├── 交易倾向（高频/中频/低频/超低频/零交易五档）
├── 当前状态（大幅盈利/稳健盈利/盈亏平衡/小幅亏损/深度亏损五档）
└── 生命周期（潜在客户/新客/尝鲜/活跃/沉睡/忠诚/流失/回流八档）

第二层：服务模型（四种服务类型）
├── 自动化信息服务（市场早报/异动提醒/月报，100%自动化）
├── 自动化产品匹配（基于标签自动推荐，客户自助决策）
├── 人工叠加服务（任务单驱动客户经理执行）
└── 团队管理服务（团队长看板+统计+预警）

第三层：动作模型（七事件格式）
├── 客户触达动作
├── 持仓复盘动作
├── 产品配置动作
├── 风险安抚动作
├── 流失挽回动作
└── 团队管理动作
```

### 3. 80%自动化 vs 20%人工叠加

**自动化层（无需人工）：**
- 客户标签自动更新
- 市场信息/持仓异动/到期提醒推送
- 标准化投后报告
- 沉睡客户自动唤醒
- 基础产品匹配推荐

**人工叠加触发条件（客户经理介入）：**
- S级客户状态变化 → 24小时内专属服务
- 深度亏损客户 → 24小时内安抚
- 高价值流失客户 → 48小时内挽回
- R4-R5产品配置 → 必须人工审核
- 客户投诉 → 必须人工处理

### 4. 客户分析维度从28个压缩到4个

v3.0：财富层级7档+投资行为19个子类+价值分层7档+收益状态8档 = 28个
v4.0：资金体量+交易倾向+当前状态+生命周期 = 4个本质维度

其他分类作为子属性，不独立成维度。

### 5. 生命周期维度直接驱动动作

每个生命周期状态变化自动触发对应动作：
- 新客完成首单 → 自动发送持续服务介绍
- 活跃→沉睡 → 自动唤醒+30天后客户经理任务单
- 任意→流失 → 自动归档+高价值客户分配挽回

### 6. 三句话法合规节点具体化

| 服务类型 | 判断 | 动作 |
|---------|------|------|
| 自动化信息推送 | 可以 | 全自动 |
| 低风险产品推荐 | 可以 | 自动推荐 |
| 高风险产品/配置方案 | 必须确认 | AI生成→人工审核→客户触达 |
| 投资建议/个股推荐 | 不 | 直接拒绝 |
| 承诺保本保收益 | 不 | 直接拒绝 |
