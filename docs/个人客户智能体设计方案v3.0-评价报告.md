# 《服务个人客户智能体设计方案 v3.0》评价报告

> 评价依据：陶总方法论 + 统一参考方法论 + 架构图v2.0 + 禁用词语表
> 评价时间：2026-06-18

---

## 一、总体判断

**这份方案的价值在于：素材丰富、阈值具体、有分类意识。**

**核心问题是：模型体系没有先定好，五大模型是按"业务目标"而非"模型类型"划分，导致角色混乱、维度堆砌、流程化痕迹重，与已有的方法论体系存在结构性错位。**

用户的优化建议（先定客户分析模型、服务模型、员工动作标准模型三层，再向下分子模型）方向完全正确，本质上是在向架构图v2.0的第二层（标准化业务模型）对齐。

---

## 二、优点

### 1. 阈值和分类标准写得具体

财富层级7档、投资行为5档、价值分层7档、收益状态8档，每一档都有明确的数字边界。例如：
- 高频交易：月换手率≥200%，月交易笔数≥30笔
- 深度亏损：收益率≤-20%
- 中产层：房产等效价值300-800万，可投资金融资产50-300万

这种写法符合陶总"客观描述"的要求，不是拍脑袋，是可验证的。

### 2. 产品匹配有明确的适配规则

私募产品销售服务模型按波动率分为四档（极低/中低/中高/极高），每档明确了：
- 代表策略类型
- 特点描述
- 适合客群标签（收益状态+风险等级+财富层级+投资行为）
- 推荐门槛

这比"根据客户风险承受能力推荐合适产品"这种空话强得多。

### 3. 意识到了"员工动作"需要单独成模型

模型五专门讲员工动作，包含了触达、服务、营销、安抚、纪要五个标准动作，且有留痕要求和达标标准。说明作者知道"分析完了要有人执行"，不是只建空中楼阁。

## 三、六视角缺点分析

### 视角一：陶总方法论视角

#### 问题1：每个模型开头都是"讲意义、讲作用"，违反陶总第一条反对

原文每个模型的固定格式：
- "解决什么问题：帮助证券公司..."
- "服务什么目标：对个人客户进行分析分类..."
- "输出什么结果：可调用的客户分析分类模型..."

陶总5月30日原话："讲不好的，是说有哪功能？有哪样作用？有哪样意义？……全部是这，就是一堆废话。"

**陶总要看的不是"模型有什么用"，而是"主模型是啥？什么维度？子模型怎么构建？"**

#### 问题2：模型一到模型四本质上是"信息系统视角"，违反陶总第五条反对

模型一从"房产等效价值、可投资金融资产、家庭年收入、学历、职业类型、通讯地址类型"六个系统字段出发划分客户。

陶总5月30日："我抽离那个时代，我不管你那些信息系统是怎么样，我根本不管你那些东西。我只围绕你这个角色来构建这个东西。"

**现在的分类是从系统里有什么数据出发，不是从"前台员工服务客户时需要知道什么"出发。**

#### 问题3：模型三（新客户发展）是典型的"流程化、线性化"，违反陶总第二条反对

模型三的结构：
- 新客首日引导（T+0）
- 新客首周培育（T+1至T+7）
- 新客首月转化（T+8至T+30）
- 新客首季沉淀（T+31至T+90）

陶总5月27日："这个都是流程性的，哦，查询，然后又选，这些都是叫流程，懂不懂？就是我所讨厌的那种流程，线性思维。"

**时间轴推进不是模型。模型是把可复用的标准、技能、维度沉淀下来，场景来了再调用。**

#### 问题4：角色混乱，违反陶总第三条反对

模型二"存量客户升华服务和增值服务模型"里同时出现了：
- 对客户的服务（给客户推事件提醒、情绪指标）
- 对员工的动作（"通知客户+推送机构点评摘要"）
- 对系统的分析（"估值分位评估""产业链结构图谱"）

陶总5月27日："角色是混乱的。"客户目标、员工动作、企业目标不能混在一个叙述里。

---

### 视角二：统一参考方法论视角（角色-模型关系）

#### 问题1：没有先定角色

整个v3.0方案30,000+字，没有出现一个明确的角色定义。没有说：
- "这个客户分析模型是给财富顾问用的"
- "这个存量增值服务模型是给客户分析助理调用的"
- "这个员工动作模型是给一线客户经理执行的"

统一参考方法论："先定角色，再写模型，维度跟着角色走。"

**没有角色锚点，维度必然失控。**

#### 问题2：客户分析模型维度堆砌到28个，远超3-5个本质维度

模型一（客户分析分类模型）包含：
- 财富层级：7档
- 投资行为：交易频率5档 + 产业6类 + 个股风格8类 = 19个子分类
- 客户价值：7档
- 收益状态：8档

总计28个分类维度。

统一参考方法论："每角色3-5个本质维度。"不是系统里有什么字段就堆什么字段。

**前台员工不可能记住28个标签去服务客户。维度越多，落地越难。**

#### 问题3：模型二（存量增值服务）的六个子模型，没有说清楚谁调用、什么时候调用

内在价值模型、事件模型、情绪模型、量价模型、研究员模型、产业链模型——这六个子模型之间是什么关系？

- 是客户分析助理同时调用六个？
- 还是根据客户类型选择性调用？
- 触发条件是什么？
- 输出给谁？

统一参考方法论要求："每个模型必须输出下一步动作。"现在这六个子模型更像六个独立的信息分析工具，没有说清楚调用关系和动作闭环。

---

### 视角三：架构图v2.0视角（四层同心圆对齐）

#### 问题1：v3.0自己定了"五大模型"，没有对齐已有的三层模型体系

架构图v2.0第二层明确分为：
- 产品模型（有什么）
- 服务模型（怎么服务）
- 动作模型（具体怎么做）

v3.0的五大模型：
- 模型一：客户分析分类 → 这更像是"分析能力"，不是"产品/服务/动作"
- 模型二：存量增值服务 → 混杂了服务标准和动作标准
- 模型三：新客户发展 → 时间轴流程
- 模型四：产品销售增长 → 产品匹配规则
- 模型五：员工动作 → 接近动作模型，但混杂了服务能力、服务渠道、服务流程

**五大模型和三层模型体系对不上号，导致后续无法接入智能体调用框架。**

#### 问题2：模型一（客户分析）的定位与架构图冲突

架构图v2.0中，"客户分析"是第三层"客户分析助理"的核心能力，不是第二层"标准化业务模型"。

v3.0把客户分析当成了第二层模型，但实际上客户分析是助理调用多个模型（产品模型+服务模型+动作模型）后的输出能力，不是独立的一层模型。

#### 问题3：模型四（产品销售增长）本质上是"产品模型"的子集

私募四档波动率匹配、公募三类、固收三类——这些都是在描述"金融产品本身的属性+适配规则"，应该归入"产品模型"。

但在v3.0里它成了一个独立的"销售增长模型"，把产品属性、客户分类、销售动作混在了一起。

### 视角四：禁用词语表视角

v3.0多处使用禁用词，需系统替换：

| 禁用词 | 出现位置 | 推荐替换 |
|--------|----------|----------|
| **基本面** | 模型二·内在价值模型："基于企业基本面数据" | 企业实际质地 / 财务实际状况 |
| **偏好** | 模型一·投资行为分析："分析客户交易偏好" | 交易倾向 / 选择方向 |
| **流程** | 模型五·员工服务标准动作："服务流程标准" | 工作协同方式 |
| **话术** | 模型五·客户沟通驱动："话术模板" | 沟通要点 |
| **话术** | 模型五·服务能力标准："标准开场/回访/风险提示/收尾话术" | 沟通要点 |
| **匹配分数/评分** | 模型二·研究员模型："置信度评分1-5分" | 置信度评级 / 可信程度 |
| **客户画像** | 模型三·新客发展："客户基础画像报告" | 客户分析 |
| **场景** | 多处出现："面向具体功能场景""应用场景" | 应用 / 用途 |
| **逻辑** | 多处出现："估值修复逻辑""产业逻辑" | 规律 / 运行规则 |
| **行业** | 多处出现："细分行业""行业景气" | 产业 |

### 视角五：落地可执行视角

#### 问题1：研究员对抗模型过于复杂，落地成本极高

模型二·研究员模型的设计：
- 多头研究员构建5维论据链
- 空头研究员构建5维论据链
- 三轮对抗（事实数据对抗→逻辑链交叉验证→核心假设攻防）
- 博弈裁决（韧性比+加权得分+假设稳定性）

一个客户持仓可能有5-20只个股，每只个股都要走这个流程？

**实际执行中，这个模型要么跑不通（计算量太大），要么输出太慢（客户等不及），要么沦为摆设（员工不会用）。**

#### 问题2：产业链模型数据获取难度极大

产业链模型要求追踪：
- 上下游景气度
- 关键原材料/核心零部件价格
- 产业链毛利率分布
- 替代技术/竞争格局

这些数据的实时获取、标准化处理、动态更新，对大多数券商来说都是基础设施缺口。

**模型设计得再漂亮，数据拿不到就是空中楼阁。**

#### 问题3：员工动作模型的达标标准过于理想化

例如：
- "S级客户周触达率100%"
- "面谈后24小时内完成纪要+客户确认率≥90%"
- "产品推荐匹配率100%+适当性确认率100%"

一个客户经理管300个客户，S级客户可能有30个，每周100%触达意味着每天平均要触达4-5个S级客户，每次触达包含准备、沟通、记录，实际可行吗？

### 视角六：模型体系结构视角（与用户建议的对照）

用户的优化建议："模型体系先定好，先分客户分析模型、服务模型、员工动作标准模型，客户分析模型和服务模型再分子模型。"

**这个建议完全正确，本质上是在做一件事：把v3.0的"五大模型"重新归档到架构图v2.0的三层模型体系里。**

对照表：

| v3.0原有模型 | 问题 | 建议归档位置 |
|-------------|------|------------|
| 模型一：客户分析分类 | 维度堆砌，无角色锚点 | 归入"客户分析助理"的能力框架，由助理调用底层数据模型 |
| 模型二：存量增值服务 | 六个子模型混杂服务/动作/分析 | 拆分：服务标准入"服务模型"，调用条件入"动作模型" |
| 模型三：新客户发展 | 时间线性流程 | 拆解为"新客激活动作模型"（触发-步骤-输出-异常-时限） |
| 模型四：产品销售增长 | 产品属性+客户匹配+销售动作混杂 | 产品属性入"产品模型"，匹配规则入"动作模型" |
| 模型五：员工动作 | 混杂服务能力/渠道/流程/合规 | 纯化为"动作模型"，服务能力/渠道/合规归入"服务模型" |

## 四、优化建议

### 建议1：先定三层模型体系，再向下拆分子模型

按架构图v2.0重新划分：

```
第二层：标准化业务模型
├── 产品模型（金融产品本身的标准化描述）
│   ├── 子模型：个人客户可投产品库（公募/私募/固收/两融/衍生品）
│   └── 子模型：产品-客户适配规则（风险等级×财富层级×投资倾向）
├── 服务模型（服务过程的标准化描述）
│   ├── 子模型：新客激活服务标准（触达频次/内容/渠道）
│   ├── 子模型：存量客户服务标准（分层服务等级/响应时效）
│   ├── 子模型：产品销售服务标准（适当性要求/风险提示/留痕规范）
│   └── 子模型：投诉与安抚服务标准（触发条件/处理步骤/升级规则）
└── 动作模型（具体业务动作的标准化描述）
    ├── 子模型：客户触达动作（触发条件/步骤/输出/时限）
    ├── 子模型：持仓复盘动作（触发条件/步骤/输出/时限）
    ├── 子模型：产品配置动作（触发条件/步骤/输出/时限）
    └── 子模型：风险安抚动作（触发条件/步骤/输出/时限）
```

### 建议2：客户分析28个维度压缩到3-5个本质维度

不是系统里有什么字段就堆什么字段，而是问："一线员工服务客户时，本质上需要知道什么？"

建议压缩为3个核心维度：
1. **资金体量**（资产规模+创收贡献 → 决定服务等级）
2. **交易倾向**（交易频率+持仓风格 → 决定沟通内容）
3. **当前状态**（收益状态+活跃状态 → 决定触发动作）

其他28个分类作为这三个维度的子属性，不独立成维度。

### 建议3：存量增值服务六个子模型按"可调用的原子"重组

不是六个平行的分析工具，而是按"触发条件→调用哪个子模型→输出什么→下一步动作"重组：

| 触发条件 | 调用子模型 | 输出 | 下一步动作 |
|---------|-----------|------|----------|
| 客户持仓个股估值分位<20% | 内在价值模型 | 低估标签 | 触达动作：建议关注 |
| 持仓个股发布财报 | 事件模型 | 超预期/符合/低于预期 | 触达动作：推送摘要 |
| 恐慌指数≤20 | 情绪模型 | 极度恐慌标签 | 触达动作：建议关注买入机会 |
| 客户要求个股研判 | 研究员模型 | 多空裁决报告 | 触达动作：推送报告 |

### 建议4：研究员模型大幅简化

从"两轮研究员+三轮对抗+博弈裁决"简化为：
- 输入：客户持仓个股
- 处理：AI生成看多/看空论据摘要（基于公开数据）
- 输出：多空观点对比卡片（3条看多+3条看空+数据来源）
- 动作：推送给客户/员工，不做裁决

**把"裁决权"留给客户和员工，AI只负责信息整理。**

### 建议5：新员工动作模型纯化为"动作模型"格式

每个动作按七事件格式写：

```
事件名称：客户触达
  触发条件：客户标签=深度亏损 且 资产规模≥5万
  执行步骤：
    1. 调取客户分析报告（工具：客户分析助理/时限：5分钟）
    2. 确认沟通要点（工具：沟通要点模板/时限：10分钟）
    3. 执行触达（工具：企微/电话/面谈/时限：30分钟）
    4. 记录触达结果（工具：系统录入/时限：触达后2小时）
  输出标准：触达记录+客户反馈
  异常处理：客户拒接→3日后二次触达；客户转户→标记流失预警
  时限要求：触发后48小时内完成首次触达
  验收标准：系统留痕完整+客户反馈已记录
```

服务能力标准、服务渠道标准、服务流程标准、合规规范标准——这四块归入"服务模型"，不在动作模型里重复写。

## 五、结论

v3.0是一份**素材丰富但结构失衡**的方案。它的阈值、分类标准、产品匹配规则写得具体，有落地意识；但它的模型体系没有先定好，导致五大模型之间存在角色混乱、维度堆砌、流程化痕迹重、与现有方法论体系错位等问题。

**核心修改方向：按"客户分析模型→服务模型→动作模型"三层体系重新归档，压缩维度到3-5个本质维度，把时间线性流程拆成可独立调用的动作原子，把研究员模型等复杂设计大幅简化。**

用户的优化建议抓住了要害：体系先定好，再往下拆。这个方向完全正确。
