# 证券公司零售业务智能体模型包 v4.3

> **面向角色：** 投资者（被服务方）+ 客户经理（执行方）+ 团队长（管理方）
> **核心目标：** 模型自动化服务大部分客户，前台团队服务动作按需叠加
> **设计依据：** 陶总方法论 + 统一参考方法论 + 七维产品模型 + 完整服务模型 + 客户分类模型
> **版本：** v4.3（基于v4.2整合七维产品模型、12张服务卡片、客户分类模型、完整调用链路）
> **时间：** 2026-06-21

## 一、先定角色和目的

### 1.1 三类角色

| 角色 | 定位 | 核心诉求 | 与模型的关系 |
|------|------|---------|------------|
| **投资者** | 服务接收方 | 获得匹配自身情况的投资服务与产品 | 被模型分析、被服务模型覆盖、接收自动化服务 |
| **客户经理** | 服务执行方 | 高效服务大量客户，重点精力投向高价值/高流失风险客户 | 执行动作模型规定的标准动作，响应模型触发的任务单 |
| **团队长** | 管理组织者 | 穿透团队服务全貌，识别风险与机会，调配资源 | 接收团队级聚合报告，审批异常处理，驱动迭代 |

### 1.2 核心目的

**一句话：让模型自动化覆盖80%客户的标准化服务，客户经理专注处理20%需要人工判断和情感连接的场景。**

```
┌─────────────────────────────────────────────────────────────┐
│  自动化服务层（模型驱动，无需人工介入）                        │
│  ├─ 客户自动分层与标签更新（5维度）                          │
│  ├─ 标准化信息推送（市场动态/持仓提醒/产品匹配）              │
│  ├─ 常规投后报告自动生成与发送                              │
│  ├─ 沉睡客户自动唤醒触达                                    │
│  ├─ 自动化产品匹配（七维引擎驱动）                           │
│  └─ 覆盖客群：80%                                           │
├─────────────────────────────────────────────────────────────┤
│  人工叠加层（客户经理执行，模型触发任务单）                    │
│  ├─ 高价值客户深度服务                                      │
│  ├─ 大额亏损关注与跟踪                                      │
│  ├─ 复杂产品配置方案沟通                                    │
│  ├─ 流失预警客户挽回                                        │
│  ├─ 投诉处理                                              │
│  └─ 覆盖客群：20%                                           │
└─────────────────────────────────────────────────────────────┘
```

## 二、模型总览与完整调用链路

### 2.1 三层模型体系总览

```
零售业务智能体
├── 第一层：客户分析模型（5个本质维度）
│   ├── 维度1：资金体量 + 社会分层（大众/富裕/高净值/超高净值）
│   ├── 维度2：交易倾向
│   ├── 维度3：当前状态
│   ├── 维度4：生命周期
│   └── 维度5：需求目的（随时取用/保值储备/长期增值/风险对冲）
│       └── 与产品模型投资目的维度直接映射
├── 第二层：服务模型（场景化组合）
│   ├── 服务模型A：自动化信息服务（100%自动）
│   ├── 服务模型B：自动化产品匹配服务（100%自动，七维产品模型驱动）
│   │   ├── 底层引擎：七维产品模型（3主维度+4扩展维度）
│   │   ├── 调用层：自然语言解析 → 意图识别 → 要素映射
│   │   └── 输出层：产品卡片（18要素）
│   ├── 服务模型C：人工叠加服务标准（模型触发→客户经理按5步执行）
│   │   ├── 操作骨架：5步标准流程（接收→准备→触达→登记→跟踪）
│   │   └── 具体内容：12张服务卡片（触发条件/执行步骤/输出物/验收标准/时限/异常处理）
│   └── 服务模型D：团队管理服务（团队长执行，单独列出）
└── 第三层：动作模型（5个标准操作步骤，七事件格式）
    ├── 步骤1：接收客户服务任务
    ├── 步骤2：服务准备
    ├── 步骤3：触达客户
    ├── 步骤4：登记结果
    └── 步骤5：跟踪反馈
```

### 2.2 完整调用链路

```
客户自然语言/行为
        ↓
【自然语言解析层】
  客户口语 → 意图识别 → 要素映射
        ↓
【第一层：客户分析模型（5维度）】
  资金体量+社会分层 / 交易倾向 / 当前状态 / 生命周期 / 需求目的
        ↓
【第二层：服务模型（触发对应服务卡片）】
  ├── 服务模型A：自动化信息服务（系统全自动）
  ├── 服务模型B：自动化产品匹配（七维产品模型匹配引擎）
  │     客户分析输出 → 七维坐标筛选 → 产品卡片（18要素）→ 推荐结果
  └── 服务模型C：人工叠加服务（12张服务卡片触发判断）
        ↓
【第三层：动作模型（5步执行）】
  步骤1：接收任务 → 步骤2：服务准备 → 步骤3：触达客户 → 步骤4：登记结果 → 步骤5：跟踪反馈
        ↓
【输出交付】
  客户侧：产品推荐/服务通知/方案书/关怀触达
  内部侧：任务完成记录/客户标签更新/服务日志归档
```

### 2.3 各层调用关系矩阵

| 调用方向 | 输入 | 输出 | 触发条件 | 调用方式 |
|---------|------|------|---------|---------|
| 客户输入 → 客户分析模型 | 自然语言/交易行为/资产数据 | 5维度标签 | 实时/日终批处理 | 自然语言解析 + 数据自动计算 |
| 客户分析模型 → 产品模型 | 5维度标签（投资目的/风险承受/持有周期/资金体量/流动性需求） | 匹配产品清单（18要素卡片） | 标签变化/客户主动查询/周期触发 | 结构化参数调用/自然语言调用 |
| 产品模型 → 服务模型 | 产品匹配结果/客户持仓变化 | 服务动作触发指令 | 产品匹配完成/持仓异常/到期提醒 | 事件驱动 |
| 服务模型 → 动作模型 | 任务单（客户信息/触发原因/优先级/时限） | 5步执行记录 | 服务模型判定需人工介入 | 任务单推送 |
| 动作模型 → 客户分析模型 | 服务结果/客户反馈 | 客户标签更新 | 服务完成/客户状态变化 | 数据回写 |

## 三、第一层：客户分析模型（5维度）

### 3.1 设计原则
- **5个本质维度**，每个维度3-5档，客户经理能记住、能使用
- **客观量化**，每档有明确的数字边界
- **直接驱动动作**，每个维度变化自动触发对应服务动作
- **系统自动更新**，标签变化由模型自动识别，无需人工维护
- **维度5（需求目的）与产品模型投资目的直接映射**，确保客户分析到产品推荐零断点

### 3.2 维度1：资金体量 + 社会分层

**定位：** 客户对券商的综合价值，决定服务等级和资源配置。社会分层作为资金体量的补充说明，建立与产品模型准入门槛的直接映射。

| 等级 | 判定标准（月日均，三选一达标） | 社会分层 | 服务等级 |
|------|------------------------------|---------|---------|
| **S级** | 资产规模≥1000万，或月均创收≥3000元 | 超高净值 | 专属客户经理+团队长关注 |
| **A级** | 资产规模300-1000万，或月均创收500-3000元 | 高净值 | 客户经理一对一维护 |
| **B级** | 资产规模5-300万，或月均创收50-500元 | 富裕 | 标准化自动化服务为主，人工按需叠加 |
| **C级** | 资产规模<5万，且月均创收<50元 | 大众 | 批量自动化服务 |

**社会分层与产品模型准入门槛映射：**

| 社会分层 | 可调用产品起投范围 | 身份要求 | 复杂产品接受度 | 默认服务层级 |
|---------|------------------|---------|--------------|------------|
| 大众 | ≤1万 | 无 | 低（简单产品） | 自助层+智能层 |
| 富裕 | 1-100万 | 无 | 中 | 智能层为主 |
| 高净值 | 100万+或合格投资者 | 合格投资者 | 高可选 | 智能层+人工层 |
| 超高净值 | 定制 | 专业投资者/定制 | 高+定制 | 人工层为主 |

**触发动作：**
- C级→B级（资产增长达标）：自动触发"服务升级通知"
- B级→A级（资产突破300万）：自动触发"高净值服务激活任务单"给客户经理
- A级→S级（资产突破1000万）：自动触发"专属服务激活任务单"给团队长
- 任意等级资产连续3月下降超20%：自动触发"流失预警任务单"

### 3.3 维度2：交易倾向

**定位：** 客户的交易习惯和投资方式，决定沟通内容和服务重点。

| 类型 | 判定标准 | 核心特征 |
|------|---------|---------|
| **高频交易型** | 月换手率≥200%，或月交易笔数≥30笔 | 追求短期收益，关注市场热点和个股机会 |
| **中频波段型** | 月换手率50%-200%，或月交易笔数10-29笔 | 有一定择时能力，关注产业趋势和板块轮动 |
| **低频长期型** | 月换手率10%-50%，或月交易笔数1-9笔 | 偏向长期持有，关注企业实际质地和估值 |
| **超低频保守型** | 月换手率<10%，或月交易笔数0笔但资产>0 | 几乎不交易，以现金管理或被动持有为主 |
| **零交易型** | 月交易笔数0笔，且账户无资产 | 未激活或已流失 |

**持仓风格标签（辅助，不独立成维度）：**
- 大盘蓝筹型：蓝筹个股成交占比≥60%
- 成长赛道型：产业大盘成长成交占比≥60%
- 小盘题材型：中小盘成长/题材个股成交占比≥60%
- 红利防御型：红利个股成交占比≥60%
- 可转债型：可转债成交占比≥30%

**触发动作：**
- 低频长期型→高频交易型（交易频率连续2月提升）：自动触发"交易活跃度提升关怀"
- 高频交易型→低频长期型（交易频率连续3月下降）：自动触发"活跃度下降关注"
- 持仓风格标签变化：自动触发"持仓风格变化提醒"

### 3.4 维度3：当前状态

**定位：** 客户当前的收益状况和持仓健康度，决定当前最需要什么服务。

| 状态 | 判定标准（近3个月收益率） | 核心诉求 |
|------|------------------------|---------|
| **大幅盈利** | 收益率>15% | 止盈建议、利润保护、再配置建议 |
| **稳健盈利** | 0<收益率≤15% | 维持策略、产品渗透、提升服务体验 |
| **盈亏平衡** | -5%≤收益率≤0 | 维持信心、市场解读、避免恐慌操作 |
| **小幅亏损** | -15%<收益率<-5% | 亏损归因、持仓诊断、修复建议 |
| **深度亏损** | 收益率≤-15% | 状态关注、深度诊断、资产优化建议 |

**持仓集中度标签（辅助）：**
- 集中型：单一标的持仓占比>50%
- 适度集中：单一标的持仓占比30%-50%
- 分散型：单一标的持仓占比<30%

**触发动作：**
- 大幅盈利→深度亏损（单月跌幅超20%）：自动触发"剧烈波动关怀任务单"给客户经理
- 深度亏损持续3个月未改善：自动触发"高优先级关注任务单"
- 持仓集中度>50%且该标的近月跌幅>10%：自动触发"集中度风险提示"

### 3.5 维度4：生命周期

**定位：** 客户与公司的关系阶段，直接决定服务策略和触发动作。

| 阶段 | 判定标准 | 自动化服务占比 | 人工叠加触发条件 |
|------|---------|--------------|----------------|
| **潜在客户** | 未开户，但在线索池 | 100%自动化（线索培育） | 线索活跃度达标→分配客户经理 |
| **新客** | 开户≤30天 | 90%自动化 | 开户7天未入金→客户经理跟进 |
| **尝鲜客户** | 开户>30天，有首笔交易但近30天无交易 | 80%自动化 | 连续45天无交易→客户经理唤醒 |
| **活跃客户** | 近30天有交易 | 70%自动化 | 资产升级/状态异常→客户经理介入 |
| **沉睡客户** | 资产>0，近90天零交易 | 60%自动化 | 沉睡超180天→客户经理挽回 |
| **忠诚客户** | 开户≥1年+月均资产≥10万+近12个月有交易+累计创收≥500元 | 50%自动化 | 定期专属服务+转介绍激励 |
| **流失客户** | 已销户，或资产=0且连续180天零交易 | 归档/批量挽回 | 高价值流失→客户经理挽回 |
| **回流客户** | 曾经流失/沉睡，近30天重新入金或交易 | 70%自动化 | 回流后30天→客户经理关怀 |

**触发动作（生命周期状态变化自动触发）：**

| 变化 | 自动触发动作 | 任务单对象 |
|------|------------|----------|
| 潜在客户→新客 | 自动发送"开户欢迎+新客引导" | 系统自动化 |
| 新客→尝鲜客户（完成首单） | 自动发送"首单确认+持续服务介绍" | 系统自动化 |
| 活跃客户→沉睡客户 | 自动发送"沉睡唤醒信息"+30天后客户经理任务单 | 系统→客户经理 |
| 活跃客户→忠诚客户 | 自动发送"忠诚客户升级通知"+专属服务介绍 | 系统→客户经理 |
| 任意→流失客户 | 自动归档+高价值客户分配挽回任务单 | 团队长→客户经理 |
| 流失/沉睡→回流客户 | 自动发送"回流欢迎+现状回顾" | 系统自动化 |

### 3.6 维度5：需求目的（新增）

**定位：** 客户投这笔钱是为了解决什么问题。与产品模型"投资目的"维度形成一一映射，确保客户分析到产品推荐链路无断点。

| 分类 | 定义 | 时间特征 | 核心目标 | 典型客户表达 | 映射产品模型投资目的 |
|---|---|---|---|---|---|
| **随时取用** | 可能随时需要支取的资金 | 0-3个月 | 本金绝对安全+即时到账 | "放着随时用的""应急备用""日常周转" | 随时取用 |
| **保值储备** | 一段时期内不动用，但要保住本金并小幅增值 | 3个月-3年 | 本金保护+跑赢通胀 | "不想亏本金""稳一点""比存款强就行" | 保值储备 |
| **长期增值** | 长期不用的资金，追求资产增值 | 3年以上 | 长期增值，承受短期波动 | "想多赚点""长线投资""养老/教育储备" | 长期增值 |
| **风险对冲** | 为特定风险做准备的支出 | 长期缴费或一次性 | 风险转移+确定性给付 | "给孩子留笔钱""怕生病""养老保障" | 风险对冲 |

**与产品模型投资目的映射对照表：**

| 客户分析模型（维度5） | 产品模型（主维度1） | 匹配规则 | 典型产品方向 |
|---------------------|-------------------|---------|------------|
| 随时取用 | 随时取用 | 直接相等 | 货币基金、现金管理、国债逆回购、同业存单指数基金 |
| 保值储备 | 保值储备 | 直接相等 | 短债基金、固收理财、收益凭证、政信信托、定期存款 |
| 长期增值 | 长期增值 | 直接相等 | 混合基金、股票基金、指数基金、私募、FOF |
| 风险对冲 | 风险对冲 | 直接相等 | 年金险、重疾险、寿险、增额终身寿险 |

**触发动作：**
- 需求目的变化（如保值储备→长期增值）：自动触发"资产配置方案重检任务单"
- 客户未明确需求目的（自然语言模糊）：触发"需求确认"智能对话，引导客户明确分类
- 多目的并存（如部分资金保值+部分长期增值）：触发"分账户配置建议"，分别调用产品模型

### 3.7 五维度综合映射与产品模型调用参数

客户分析模型5维度输出直接作为产品模型输入参数：

| 客户分析维度 | 输出值 | 映射产品模型参数 | 调用规则 |
|------------|-------|----------------|---------|
| 资金体量+社会分层 | S/A/B/C + 大众/富裕/高净值/超高净值 | `investable_amount` + `compliance_tags` + `complexity_tolerance` | 资金体量→可投金额上限；社会分层→复杂程度上限 |
| 交易倾向 | 高频/中频/低频/超低频/零交易 | 辅助判断 `complexity_tolerance` | 高频型→可接受中高复杂度；零交易型→仅低复杂度 |
| 当前状态 | 大幅盈利/稳健盈利/盈亏平衡/小幅亏损/深度亏损 | 触发服务模型卡片，调整风险敞口 | 深度亏损→降低风险特征上限；大幅盈利→可提高风险敞口 |
| 生命周期 | 8个阶段 | 服务层级+回访周期 | 忠诚客户→人工层比例提升；新客→智能层为主 |
| 需求目的 | 随时取用/保值储备/长期增值/风险对冲 | `investment_purpose` | 直接相等映射 |

**完整调用参数示例：**

```
customer_id = "C20240001"
资金体量 = "A级" → investable_amount = 800000（取中值）
社会分层 = "高净值" → compliance_tags = ["合格投资者"], complexity_tolerance = "高"
交易倾向 = "低频长期型" → 辅助：complexity_tolerance = "高"（低频型可接受复杂产品）
当前状态 = "深度亏损" → 风险敞口调整：max_volatility下调至10%（原可承受15%）
生命周期 = "活跃客户" → service_layer = "智能层为主"

#### 4.2.2 自然语言调用层

产品模型支持自然语言查询，系统通过意图识别将口语化表达映射为结构化要素。

**解析流程：**

```
1. 意图识别层
   - 提取关键词："随时取""保本""稳""多赚""高收""长期""保险""私募"
   - 情感倾向：积极（想多赚）/ 保守（不想亏）/ 中性（问问看）

2. 要素映射层
   - 投资目的映射：
     "随时用""应急""备用" → 随时取用
     "不想亏""稳一点""保本""比存款强" → 保值储备
     "多赚""增值""长线""养老""教育" → 长期增值
     "保险""生病""身故""传承" → 风险对冲

   - 风险特征映射：
     "安全第一""不能亏""保本" → Ⅰ型（波动<2%）
     "稳一点""小幅波动""不想亏本金" → Ⅱ型（波动2%-5%）
     "能承受波动""想多赚点" → Ⅲ型（波动5%-15%）
     "追高点收益""较大回撤" → Ⅳ型（波动15%-25%）
     "高收益""不在意短期亏""长期看好" → Ⅴ型（波动>25%）

   - 持有周期映射：
     "随时""活期""可能随时用" → 0-3月
     "半年""一年""明年要用" → 3-12月
     "两三年""三五年" → 1-3年/3-7年
     "养老""孩子上大学""长期" → 超长期

3. 校验确认层
   - 若自然语言中未明确某要素，系统追问确认
   - 若多个要素冲突（如"想多赚但不想亏"），标记为需人工确认
```

**自然语言调用示例对照表：**

| 客户自然语言表达 | 意图识别 | 要素映射结果 | 匹配产品方向 |
|---|---|---|---|
| "想买点随时能取的，安全第一的" | 高流动性+保本 | 投资目的=随时取用，风险特征=Ⅰ型，持有周期=活期 | 货币基金、现金管理、国债逆回购 |
| "不想亏本金，比存款强点就行，放半年" | 保本+小幅增值+半年期 | 投资目的=保值储备，风险特征=Ⅱ型，持有周期=6个月 | 短债基金、固收理财、收益凭证 |
| "能承受点波动，想多赚点，放两三年" | 增值+中度波动+中期 | 投资目的=长期增值，风险特征=Ⅲ型，持有周期=24个月 | 混合基金、FOF、固收+资管 |
| "想追高点收益，能承受较大回撤，长期持有" | 高收益+大波动+长期 | 投资目的=长期增值，风险特征=Ⅳ型，持有周期=60个月 | 偏股混合基金、股票基金、股票多头私募 |
| "给孩子存点教育金，十几年后用的" | 长期储备+教育目的 | 投资目的=长期增值，风险特征=Ⅲ型，持有周期=超长期 | FOF定投、年金险、指数基金定投 |

| "有100万闲钱，想配点私募" | 大额+另类投资 | 投资目的=长期增值，风险特征=Ⅳ-Ⅴ型，持有周期=长期，合规标签=合格投资者 | 股票多头私募、CTA、私募股权 |

  R11: 准入门槛匹配 → 起投≤50万，身份要求⊆合规标签

  - 触达记录：时间/渠道/时长/核心内容/客户反馈/客户意向/下一步计划
异常处理：

验收标准：触达已完成+核心内容已传达+客户意向已确认+下一步已约定
```

## 七、三句话法合规节点

### 7.1 三句话法定义

| 判断 | 含义 | 智能体动作 |
|------|------|-----------|
| **可以** | 该动作可由系统自动执行，无需人工审核 | 全自动执行 |
| **必须确认** | 该动作需AI生成后，由人工审核确认，方可触达客户 | AI生成→人工审核→客户触达 |
| **不** | 该动作禁止执行，直接拒绝并标记原因 | 直接拒绝，标记原因，转合规处理 |

### 7.2 关键节点嵌入

#### 7.2.1 自动化产品推荐（R1-R2产品）→ 可以 → 全自动

| 节点 | 判定 | 执行链路 | 人工介入要求 |
|------|------|---------|------------|
| R1（货币基金/现金管理） | 可以 | 客户分析模型→七维产品模型→产品卡片18要素→直接推送客户 | 无需人工 |
| R2（短债基金/固收理财/本金保障型收益凭证） | 可以 | 客户分析模型→七维产品模型→产品卡片18要素→直接推送客户 | 无需人工 |
| 自然语言查询匹配R1-R2 | 可以 | 自然语言解析→意图识别→要素映射→七维筛选→产品卡片→直接推送 | 无需人工 |
| 存量配置建议（仅含R1-R2） | 可以 | 周期触发→客户分析→七维筛选→产品卡片→直接推送 | 无需人工 |

**合规要求：**
- 所有自动化推荐必须标注"AI生成，仅供参考，投资有风险"
- 产品卡片必须完整展示18要素（重点展示风险特征：波动幅度/极端损失/本金安全）
- 禁止在自动推送中出现"推荐""建议买入"等导向性表述，使用"匹配到以下产品""基于您的需求筛选"

#### 7.2.2 高风险产品推荐（R4-R5产品）→ 必须确认 → AI生成→人工审核→客户触达

| 节点 | 判定 | 执行链路 | 人工介入要求 |
|------|------|---------|------------|
| R4（偏股混合/股票基金/行业指数基金） | 必须确认 | AI生成推荐方案→客户经理审核（步骤2服务准备）→确认后触达客户 | 客户经理必须审核方案、确认适当性 |
| R5（私募股权/场外期权/高杠杆结构化） | 必须确认 | AI生成推荐方案→客户经理审核→团队长复核（资金体量=S级）→确认后触达客户 | 客户经理+团队长双重审核 |
| 复杂产品（雪球/结构化/衍生品） | 必须确认 | AI生成推荐方案→客户经理审核→签署复杂产品风险揭示书→确认后触达 | 必须人工讲解+签署专项揭示书 |
| 涉及合格投资者/专业投资者产品 | 必须确认 | AI生成推荐方案→校验合规标签→客户经理审核身份材料→确认后触达 | 必须审核身份认证材料 |

**合规要求：**
- AI生成推荐方案后，系统锁定输出，等待人工审核标记
- 客户经理审核时需确认：客户5维度标签准确性/适当性匹配/客户当前状态是否适合推荐
- 审核通过后系统解锁，方可触达客户
- 审核拒绝需标记原因，反馈至客户分析模型（调整标签或降低推荐风险等级）

#### 7.2.3 投资建议/承诺保本 → 不 → 直接拒绝，标记原因

| 节点 | 判定 | 智能体动作 | 标记原因 | 后续处理 |
|------|------|-----------|---------|---------|
| 客户要求"推荐一只肯定会涨的股票" | 不 | 直接拒绝，返回合规提示 | 标记：具体个股推荐请求 | 系统记录，推送投资者教育（卡片12），可转人工层沟通投资理念 |
| 客户要求"保证不亏本金" | 不 | 直接拒绝，返回合规提示 | 标记：保本承诺请求 | 系统记录，推送风险揭示内容，触发合规部门关注 |
| 客户要求"预测明天哪只基金涨停" | 不 | 直接拒绝，返回合规提示 | 标记：收益预测/承诺请求 | 系统记录，推送投资者教育（卡片12） |
| 客户要求"内幕消息" | 不 | 直接拒绝，返回合规提示，标记异常 | 标记：异常信息请求 | 系统记录，触发合规预警，必要时上报 |
| AI生成内容中出现"保底收益""稳赚""必涨" | 不 | 系统自动拦截，拒绝输出，标记内部异常 | 标记：AI输出含禁用承诺表述 | 系统记录，反馈模型训练团队，人工复核后重新生成 |
| 客户经理在触达中承诺保本/保收益 | 不 | 系统监听（录音/文字）识别，实时阻断 | 标记：人工违规承诺 | 系统记录，触发合规告警，升级团队长处理 |

**合规要求：**
- 所有"不"判定必须记录：客户ID、请求内容、拒绝时间、标记原因、后续处理动作
- 拒绝响应必须包含：合规提示语（"根据监管规定，我们无法提供..."）+ 替代服务引导（"我们可以为您提供..."）
- 触发人工层时，任务单需标注"合规敏感，注意用语"

### 7.3 三句话法在产品模型调用链路中的位置

```
客户输入
    │
    ├──→ 自然语言解析

    │
    ▼

    │
    ▼
七维产品模型筛选
    │
    ├──→ 输出产品均为R1-R2 → 【可以】→ 全自动输出产品卡片18要素 → 客户触达
    │
    ├──→ 输出产品含R3 → 【可以】→ 全自动输出+附加风险揭示 → 客户触达

```
