## 一、资产总览与三层架构

### 1.1 核心理念

本资产库参照本体智能（Ontology Intelligence）方法论，将证券业务原子模型从"数据+业务"二元结构升级为**语义层-决策层-行动层**三层架构：

| 层级 | 定义 | 核心问题 | 对应原模型 |
|------|------|---------|-----------|
| **语义层** | 定义"是什么"——统一业务含义和规则 | 对象、属性、关系、约束 | D系列数据本体 + E/I/P/S业务本体 |
| **决策层** | 定义"做什么"——生成智能决策 | 逻辑推理、一致性校验、触发条件、业务操作 | 因果推演引擎 + 三句话法决策档 |
| **行动层** | 定义"怎么做"——驱动业务流程 | API接口、工作流、动作编排、权限控制 | A系列动作模型 + 动力函数 |

### 1.2 本体四类核心要素

每个原子模型均包含四类形式化要素：

```
┌────────────────────────────────────────┐
│           证券业务原子模型卡片           │
├────────────────────────────────────────┤
│ 对象(Object)     → 业务实体抽象          │
│ 属性(Attribute)  → 特征/状态/指标描述    │
│ 关系(Relationship)→ 业务关联定义        │
│ 规则与约束(Rule) → 逻辑边界与行为规范    │
└────────────────────────────────────────┘
```

#### D001 企业财报监测本体

```

│ 本体编号：D001                                                │
│ 本体名称：企业财报监测本体                                     │

  ├── 行业对比对象(IndustryBenchmark)
  │     ├── 同业均值(PeerAverage)

              ──触发──► A001债券承揽动作 (融资需求信号)
              ──触发──► A004风控处置动作 (杠杆预警)

【规则与约束】
硬约束(Hard Constraint): 审计意见为"否定"或"无法表示" → 自动冻结承销项目
软约束(Soft Constraint): 资产负债率>70% → 标记"杠杆偏高" → 纳入关注清单
触发约束(Trigger Constraint): 营收连续两季负增长 → 触发债券发行可行性复核
连锁约束(Chain Constraint): 审计意见非标准 → 联动D007舆情风险监测 → 升级复核
```

## 三、决策层：推理与规则引擎

> 决策层构建企业业务的标准化决策逻辑体系，将分散在各业务环节、不同系统中的碎片化处置规则与业务判断逻辑，整合为可量化、可复用、可追溯的统一决策规则集。

### 3.1 决策层核心要素

决策层由四类核心要素构成：

| 要素 | 定义 | 证券场景示例 |
|------|------|------------|
| **逻辑推理** | 基于语义层概念关系与业务规则推导隐含结论 | 由客户资产等级+风险等级推导适投产品范围 |
| **一致性校验** | 自动检测知识库中的不一致性与逻辑矛盾 | 客户风险等级C1却持仓R4产品 → 冲突告警 |
| **触发条件** | 定义规则激活的具体条件 | 净值回撤超阈值5% → 触发投后服务 |
| **业务操作** | 规则触发后的具体处置动作 | 自动推送安抚话术/生成换仓方案/冻结交易 |

### 3.2 三句话法决策引擎


### 3.3 决策规则示例

**规则R001：债券发行可行性自动评估**

```
规则名称: 债券发行可行性自动评估
触发条件: D001监测到企业财报发布
输入对象: E001企业客户分类本体

逻辑推理:
  IF 财务健康度 ∈ {优, 良} 
     AND 资产负债率 < 70%
     AND 审计意见 = "标准无保留"
     AND 近一年无评级下调(D002)
  THEN 发行可行性 = "可行"
       触发 A001债券承揽动作 → 推送融资需求简报
  ELSE IF 财务健康度 = "一般"
          AND 资产负债率 60%~75%
  THEN 发行可行性 = "条件可行"
       触发 A001 → 推送关注要点清单 → 推演档(人工确认)
  ELSE 
       发行可行性 = "暂不建议"
       标记原因 → 归入观察清单

一致性校验:
  - 校验: 企业性质=城投 → 地区属性须匹配城投分类
  - 校验: 融资需求=债券 → 产业属性不能为金融(需走金融债路径)
```

**规则R002：适当性匹配自动校验**

```
规则名称: 适当性匹配自动校验
触发条件: 客户表达投资意向 / 产品推荐场景
输入对象: I001个人客户分类本体 + P001产品本体

逻辑推理:
  IF 客户风险等级 ∈ 产品风险要求
     AND 客户资产 ≥ 产品资产门槛
     AND 客户投资经验 ≥ 产品经验要求
     AND 适当性测评在有效期内(<1年)
  THEN 匹配结果 = "通过"
       决策档 = "必须确认"(投资建议书)
  ELSE IF 客户风险等级 ∉ 产品风险要求
  THEN 匹配结果 = "拒绝"
       决策档 = "直接拒绝"
       AI拒绝理由: "客户风险等级C{level}低于产品要求"
  ELSE IF 适当性测评过期
  THEN 匹配结果 = "暂停"
       触发动作: 强制重新测评 → 测评通过后重新匹配

一致性校验:
  - 校验: 同一客户同一产品不能重复匹配通过(防刷单)
  - 校验: 私募产品 → 客户须为合格投资者(资产≥300万或收入≥50万)
```

**规则R003：信用交易风险前置预警**

```
规则名称: 信用交易风险前置预警
触发条件: D003市场利率波动 + D007舆情风险 + D001企业财报 三重数据叠加
输入对象: 信用交易持仓本体(扩展)

逻辑推理:
  综合风险评分 = w1×利率风险 + w2×舆情风险 + w3×财务风险
  
  IF 综合风险评分 > 阈值(70分)
     AND 客户维保比例趋势推演(3日) < 130%
  THEN 风险等级 = "高危"
       触发 A004风控处置动作
       决策档 = "推演推荐"
       AI自动生成三套预案:
         (A) 提前补仓: 计算补仓金额 → 推送APP → 客户确认扣款
         (B) 部分平仓: 推荐平仓标的+数量 → 客户确认
         (C) 转仓标的: 推荐低风险替代标的 → 投资顾问审核
  ELSE IF 综合风险评分 > 阈值(50分)
  THEN 风险等级 = "关注"
       触发 A004 → 客户经理通知 → 客户关怀

一致性校验:
  - 校验: 维保比例计算须包含T+1在途交易
  - 校验: 预警触发须排除已冻结账户
```

## 四、行动层：执行算子与编排

> 行动层构建企业业务的自动化执行能力，将业务意图拆解为可跨系统联动、可闭环落地的自动化执行动作流。

### 4.1 行动层核心要素

| 要素 | 定义 | 证券场景示例 |
|------|------|------------|
| **API接口** | 跨系统能力调用通道 | 交易系统下单API、CRM客户查询API、风控系统冻结API |
| **工作流** | 多步骤业务流程编排 | 债券发行全流程: 承揽→尽调→内核→申报→反馈→发行 |
| **动作编排** | 原子动作的动态组合 | 持仓回撤场景: 安抚话术→三套方案→客户选择→执行→归档 |
| **权限控制** | 执行动作的操作边界 | 投资顾问可操作"必须确认"档，客户经理仅可操作"推演推荐"档 |

### 4.2 动力函数（Action Function）

参照Palantir Foundry动力层设计，将动作模型升级为可执行的动力函数。

#### A001 债券承揽动力函数

```
┌─────────────────────────────────────────────────────────────┐
│ 函数编号：A001                                                │
│ 函数名称：债券承揽动力函数                                     │
│ 所属域：投资银行                                               │

【函数定义】
function bond_underwriting_action(trigger_source, enterprise_entity):
  
  【输入参数】
  - trigger_source: 触发源(D001/D002/人工)
  - enterprise_entity: E001企业客户分类本体实例
  
  【执行步骤】
  Step 1: 数据获取
    - 调用API: CRM.get_client_profile(enterprise_entity.id)
    - 调用API: D001.get_latest_report(enterprise_entity.id)
    - 调用API: D002.get_rating_history(enterprise_entity.id)
  
  Step 2: 推理决策
    - 执行规则R001: 债券发行可行性自动评估
    - IF 可行性="可行" → 决策档="推演推荐"
    - ELSE → 中止流程，记录原因
  
  Step 3: 内容生成
    - 调用LLM: 生成《融资需求简报》(模板+数据填充)
    - 内容须包含: 企业概况/融资需求测算/发行窗口建议/初步方案框架
  
  Step 4: 人工确认
    - 推送至: 债券承揽人员企业微信
    - 等待确认: 24小时SLA
    - IF 确认 → 执行Step 5
    - IF 拒绝/超时 → 记录原因，升级至部门负责人
  
  Step 5: 客户触达
    - 调用API: SMS.send(enterprise_entity.contact, 简报摘要)
    - 调用API: CRM.create_follow_up_task(enterprise_entity.id, "电话沟通", SLA=48h)
  
  Step 6: 执行反馈
    - 记录: 触达时间/客户响应/后续动作
    - 更新: E001企业客户分类本体(交互记录)
    - 触发: D006项目进度异常本体(立项节点)
```

## 五、闭环演化机制

> 本体智能的核心价值在于构建"知识感知→推理决策→执行反馈→知识更新"的闭合学习回路，使AI系统具备持续自演化能力。

### 5.1 闭环架构

```
                    ┌─────────────────────┐
                    │     知识感知层       │
                    │  (D001~D012数据本体) │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │     语义对齐         │
                    │ (对象/属性/关系映射)  │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │     推理决策层       │
                    │  (规则引擎+三句话法)  │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │     行动执行层       │
                    │  (A001~A005动力函数)  │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │     执行反馈         │
                    │ (结果/效果/异常回流)  │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │     知识更新         │
                    │ (本体实例化+规则优化) │
                    └─────────────────────┘
```

### 5.2 演化规则

**规则演化**
- 触发: 同一规则连续误报>10次/月 → 自动标记 → 人工复核 → 规则调优
- 触发: 新监管政策发布(D004) → 规则库自动扫描 → 受影响规则标记 → 48小时内更新

**本体演化**
- 触发: 新业务线上线 → 需求分析 → 本体扩展 → 交叉验证 → 版本发布
- 触发: 业务概念定义争议 → 概念变更评审 → 业务影响评估 → 版本管理

**模型演化**
- 触发: 客户分类准确率<85% → 模型重训练 → A/B测试 → 灰度发布
- 触发: 流失预测模型AUC<0.75 → 特征工程优化 → 多模型融合 → 效果验证

```
   - 意图识别: "持仓查询+业绩关切"
   - 调用I001: 获取客户分类标签
   - 调用持仓系统: 获取持仓列表
   
2. 决策层-推理决策:
   - 匹配规则: D011产品业绩预警规则
   - 判定: 客户持仓某基金回撤8%，接近阈值
   - 决策档: "推演推荐"(三套方案)
   
3. 行动层-执行输出:
   - 调用A002财富管理动力函数
   - 生成: 安抚话术+市场说明+三套方案
   - 推送: 客户经理确认后触达客户
   - 启动: D005行为监测(48小时窗口)
```

### 7.2 新增本体流程

1. **需求提出**: 业务线提交《本体需求说明书》
2. **五步蒸馏**: 目标→标杆→数据→模型→验证
3. **本体建模**: 按"对象+属性+关系+规则"四要素输出本体卡片
4. **陶总五大反对校验**:
   - 是否讲模型本身而非仅讲意义？
   - 是否流程化线性化拆解？
   - 角色/目标是否清晰？
   - 是否拍脑袋/甩锅AI？
   - 是否技术自说自话？
5. **交叉验证**: 独立裁判审核
6. **版本发布**: 纳入资产库，版本号递增

### 7.3 合规要求

所有本体调用须遵守智能体合规三句话法：

| 档位 | 判断 | 适用事项 | 本体动作 |
|------|------|---------|---------|
| **可以** | 内部数据分析、本体调用日志、触发记录、系统标记 | AI全自动执行，后台记录备查 |
| **推演推荐** | 资产配置建议、换仓方案、挽留策略、运营方案 | AI推演→人工确认→执行 |
| **必须确认** | 投资建议书、适当性匹配、风险等级调整、合规审查 | AI生成→人工逐条审核→确认后对外 |
| **直接拒绝** | 承诺保本、代客下单、突破风险等级、无资质建议 | AI直接拒绝→标记原因→升级合规 |
