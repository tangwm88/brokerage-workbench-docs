# 业务模型规定动作设计方法论与示例

> **版本**：v1.0
> **日期**：2026-06-03
> **定位**：为业务分析模型配套设计可执行的规定动作
> **核心原则**：分析模型判断"是什么"，规定动作判断"做什么"

---

## 一、方法论：怎么设计规定动作

### 1.1 两个模型的关系

| | 业务分析模型 | 规定动作模型 |
|---|---|---|
| **回答的问题** | 这个项目/客户"是什么"情况？ | 接下来"做什么"？ |
| **核心产出** | 维度分析 + 判断结论 | 动作清单 + 执行步骤 |
| **谁用** | 角色的分析决策依据 | 角色的执行操作手册 |
| **调用时机** | 需要判断的时候 | 事件触发的时候 |
| **输出形式** | 分析结果 + 下一步建议 | 标准步骤 + 输出物 + 异常处理 |

**关键衔接**：业务分析模型的"下一步建议"就是规定动作模型的"触发条件"。

### 1.2 设计六步法

```
Step 1: 识别业务事件
  └─ 什么事件启动这一套动作？（线索录入/立项通过/材料完成/...）
  
Step 2: 定义响应角色
  └─ 哪些角色需要同步响应？（客户经理/组织者/质控内核/产品支持）
  
Step 3: 设计标准动作
  └─ 每个角色做什么？（触发条件 → 执行步骤 → 输出物 → 异常处理 → 时限要求）
  
Step 4: 定义同步机制
  └─ 各角色动作谁先谁后？谁等谁？能不能并行？
  
Step 5: 设定完成标准
  └─ 怎么算这套动作做完了？（所有角色完成且无异常）
  
Step 6: 设计超时预警
  └─ 多久没做完要提醒谁？（超时限50%预警，100%升级）
```

### 1.3 动作设计模板

每个角色的每个动作，必须包含以下五要素：

```markdown
### 动作名称：XXX

**触发条件**：什么情况下启动这个动作？
**执行步骤**：
1. 步骤1（可执行，不模糊）
2. 步骤2
3. 步骤3
**输出物**：做完后产出什么？（必须可检查）
**异常处理**：
- 异常A：什么情况 → 怎么处理 → 升级给谁
- 异常B：...
**时限要求**：X小时内/当日内/X个工作日内
```

### 1.4 设计原则

| 原则 | 要求 | 反面示例 | 正面示例 |
|------|------|---------|---------|
| **触发明确** | 动作由什么事件启动，写得清清楚楚 | "需要的时候" | "债券发行意向确认后24小时内" |
| **步骤可执行** | 每个步骤是一个具体动作，不是态度 | "认真评估" | "调用偿债能力分析模型，录入发行人近3年财报" |
| **输出可检查** | 做完后产出什么，一目了然 | "形成初步判断" | "输出《立项评估表》，含5维度判断结论" |
| **异常有预案** | 出问题了怎么办，提前写好 | "视情况而定" | "评级数据缺失→标记'待补充'→通知客户经理补录→限2个工作日内" |
| **时限刚性** | 每个动作有 deadline，超期预警 | "尽快完成" | "T+1个工作日内完成，超期50%自动预警组织者" |

## 二、示例：投行债券发行业务规定动作模型

> **配套文档**：《投行债券发行业务分析模型-v2.0》
> **角色体系**：沿用定增模型角色体系
>   - 业务团队：客户经理
>   - 业务支持中心：组织者、质控内核、产品支持

### 整体动作链路

```
线索录入 → 立项评估 → 方案设计 → 材料准备 → 申报复核 → 发行承销 → 发行后督导
   ↑___________________________________________________________↓
                          （发现新需求，循环）
```

---

### 事件1：债券发行线索录入

**事件定义**：发现客户有债券发行意向或系统识别潜在债券融资需求
**触发条件**：
- 客户经理录入债券发行线索
- 或客户服务智能体识别客户债券融资需求
- 或公开市场信息触发（如：发行人公告拟融资）
**事件等级**：常规

#### 响应角色与动作

| 角色 | 动作 | 时限 |
|------|------|------|
| 客户经理 | 线索核实与初步触达 | 2个工作日内 |
| 组织者 | 线索登记与资源预判 | 1个工作日内 |

#### 客户经理：线索核实与初步触达

**触发条件**：收到债券发行线索
**执行步骤**：
1. 查询客户基本信息（已发行债券余额、主体评级、近期财务概况）
2. 判断线索来源可靠性（客户直接表达/第三方传闻/市场传闻）
3. 选择触达方式（电话/微信/正式拜访），优先联系已知关键人
4. 首次沟通确认3个事实：
   - 是否有真实融资需求（还是随便问问）
   - 拟融资规模大概区间
   - 计划发行时间窗口
5. 记录沟通结果，更新线索状态
**输出物**：
- 《线索跟进记录》（含沟通时间、对象、方式、客户反馈）
- 线索状态更新：[待核实]/[意向确认]/[暂无意向]/[需持续培育]
**异常处理**：
- 客户关键人无法触达 → 尝试经办人/董秘 → 仍无法触达 → 标记"触达困难" → 组织者协调资源
- 客户否认有融资需求 → 标记"暂无意向" → 纳入培育池 → 季度回访
- 客户反馈信息与线索不符（如规模差异大） → 记录差异 → 更新线索信息 → 重新评估
**时限要求**：2个工作日内完成首次触达

#### 组织者：线索登记与资源预判

**触发条件**：收到债券发行线索
**执行步骤**：
1. 登记线索到投行经营看板（客户名称、预计规模、预计时间、来源）
2. 预判资源需求：
   - 是否需要特定产业团队支持
   - 是否需要特定区域团队支持
   - 预计占用承销额度
3. 检查是否有历史项目冲突（同一客户是否有在执行的同类项目）
4. 判断线索优先级（高/中/低）
**输出物**：
- 《线索登记台账》更新
- 资源预判结论：[需专项支持]/[常规跟进]/[暂不投入]
**异常处理**：
- 发现历史项目冲突（如：同一客户已有在审债券项目） → 标记冲突 → 通知客户经理确认是否为新增需求 → 如为新增，评估是否合并
- 预计规模超大（超过团队当前承销能力） → 标记"需协调" → 启动资源调配流程
**时限要求**：1个工作日内完成登记与预判

### 事件2：立项评估启动

**事件定义**：客户确认有债券发行意向，启动正式立项评估
**触发条件**：
- 客户经理确认客户有真实债券发行意向
- 客户已提供初步发行参数（规模/期限/用途）
- 或客户正式发出服务邀请（RFP）
**事件等级**：重点

#### 响应角色与动作

| 角色 | 动作 | 时限 | 依赖 |
|------|------|------|------|
| 客户经理 | 启动债券业务分析模型评估 | 3个工作日内 | 事件1完成 |
| 质控内核 | 预评估质量把关 | 2个工作日内 | 客户经理提交评估申请 |
| 产品支持 | 政策环境初判 | 2个工作日内 | 事件1完成 |

#### 客户经理：启动债券业务分析模型评估

**触发条件**：客户确认债券发行意向，已获取初步参数
**执行步骤**：
1. 收集基础数据：
   - 发行人近3年审计报告（调用财务数据API）
   - 已发行债券余额（查询中债登/上清所）
   - 主体评级报告（查询评级机构官网/Wind）
   - 拟发行参数（规模/期限/资金用途）——客户经理录入
2. 调用债券业务分析模型v2.0，完成5维度分析：
   - 维度1：偿债能力（核心）→ 现金流覆盖率/资产负债率/利息覆盖倍数
   - 维度2：发行方案 → 规模/期限/利率/还本付息
   - 维度3：市场窗口 → 利率环境/同类型发行/投资者需求
   - 维度4：资金用途 → 项目真实性/资金分配/效益测算
   - 维度5：增信合规 → 评级/增信/历史合规
3. 整理分析结果，形成初步判断：
   - 通过项、注意项、不通过项清单
   - 核心障碍（如有）
   - 是否建议立项
4. 提交立项评估申请（含5维度分析报告）
**输出物**：
- 《债券发行立项评估表》（含5维度分析结果）
- 初步立项建议：[建议立项]/[谨慎推进]/[建议暂缓]
- 如为[建议暂缓]，需列明触发条件（如：等评级上调/等现金流改善）
**异常处理**：
- 财务数据缺失（如：未披露年报） → 标记"数据缺失" → 要求客户提供 → 限3个工作日内补全 → 超时自动预警
- 核心指标不通过（如：现金流覆盖率<1.0） → 记录不通过项 → 不禁止立项但需列明风险 → 提交质控内核重点审查
- 发行人处于被调查/处罚状态 → 标记"重大合规风险" → 立即停止评估 → 提交组织者判断是否继续
**时限要求**：3个工作日内完成评估并提交

#### 质控内核：预评估质量把关

**触发条件**：客户经理提交立项评估申请
**执行步骤**：
1. 审查5维度分析的数据来源是否可靠（系统API/客户提供/手工整理）
2. 核查关键计算是否正确（现金流覆盖率/利息覆盖倍数/累计债券余额）
3. 检查是否有重大合规风险遗漏：
   - 发行人近3年处罚记录
   - 当前被调查状态
   - 历史违约/展期记录
4. 判断分析结论是否客观（有无过度乐观/悲观）
5. 输出预评估意见
**输出物**：
- 《预评估意见》
  ├─ 数据质量：[可靠]/[需核实]/[不可靠]
  ├─ 计算核查：[正确]/[有误，已修正]
  ├─ 合规筛查：[通过]/[注意]/[不通过]
  ├─ 结论判断：[同意]/[需补充分析]/[不同意]
  └─ 重点关注事项清单（如有）
**异常处理**：
- 发现数据造假嫌疑 → 标记"数据异常" → 要求独立数据源复核 → 提交组织者启动专项核查
- 发现重大合规遗漏（如：客户未披露的被调查信息） → 标记"重大合规风险" → 退回客户经理补充 → 同步组织者
**时限要求**：2个工作日内完成预评估

#### 产品支持：政策环境初判

**触发条件**：债券发行线索确认后
**执行步骤**：
1. 查询当前监管政策环境：
   - 该类债券（公司债/企业债/ABS等）最新监管要求
   - 近期同类项目审核通过率/平均周期
   - 是否有窗口指导或限制类政策
2. 判断发行人所属产业是否属于支持/限制/禁止类
3. 初步判断申报可行性（政策层面）
**输出物**：
- 《政策环境初判》
  ├─ 政策环境：[支持]/[中性]/[收紧]
  ├─ 同类项目近期通过率：XX%
  ├─ 产业分类：[支持类]/[审慎类]/[限制类]
  └─ 申报可行性：[可行]/[需谨慎]/[建议观望]
**异常处理**：
- 该产业近期审核明显收紧 → 标记"政策风险" → 建议暂缓申报 → 同步组织者
- 监管政策近期有重大变化 → 标记"政策变化" → 更新内部政策库 → 通知所有相关项目组
**时限要求**：2个工作日内完成初判

#### 同步机制

```
线索确认
    │
    ├─→ 客户经理（3日）启动5维度评估 ──┐
    │                                    │
    ├─→ 产品支持（2日）政策环境初判 ────┤
    │                                    ├─→ 客户经理提交立项申请
    └─→ 组织者（1日）登记与预判 ────────┘
                                         │
                                         ▼
                              质控内核（2日）预评估把关
                                         │
                                         ▼
                              组织者判断：立项/补充/暂缓
```

#### 完成标准

- **立项通过**：5维度主要指标通过 + 质控内核同意 + 政策环境可行 → 进入事件3（方案设计）
- **需补充**：某维度数据不足或判断有争议 → 退回客户经理补充 → 限3个工作日内
- **暂缓立项**：核心指标不通过或政策环境收紧 → 标记"培育" → 季度复检

### 事件3：发行方案设计

**事件定义**：立项评估通过，进入发行方案设计阶段
**触发条件**：
- 组织者批准立项
- 客户已确认启动项目
- 已获取发行人基本财务数据和发行意向参数
**事件等级**：重点

#### 响应角色与动作

| 角色 | 动作 | 时限 | 依赖 |
|------|------|------|------|
| 产品支持 | 设计发行方案 | 5个工作日内 | 立项通过 |
| 客户经理 | 协调客户确认方案参数 | 并行 | 立项通过 |
| 组织者 | 发行窗口初步判断 | 3个工作日内 | 产品支持提交方案初稿 |

#### 产品支持：设计发行方案

**触发条件**：立项评估通过，进入方案设计
**执行步骤**：
1. 基于债券分析模型v2.0维度2（发行方案）细化设计：
   - 规模：结合累计债券余额/净资产约束，确定发行规模区间
   - 期限：结合资金使用周期、偿债高峰分析，确定期限建议
   - 利率：基于主体评级、同评级近期发行利率、信用利差，给出建议区间
   - 还本付息：设计还本节奏，匹配发行人现金流
2. 基于维度4（资金用途）审核募投项目：
   - 项目是否已完成备案/审批
   - 资金分配比例是否合理
   - 项目效益测算（IRR vs 利率+3%）
3. 基于维度5（增信合规）评估增信需求：
   - 是否需要担保/抵押/质押
   - 增信措施的可执行性
4. 形成《发行方案建议书》初稿
**输出物**：
- 《发行方案建议书》
  ├─ 发行规模建议：XX亿元（区间：XX-XX亿）
  ├─ 发行期限建议：X年（备选：X年/X年）
  ├─ 票面利率建议区间：X.XX%-X.XX%
  ├─ 还本付息方式：到期一次还本/分期还本（具体节奏）
  ├─ 资金用途分配：项目XX亿/补流XX亿
  ├─ 增信安排：无/由XX提供担保/以XX资产抵押
  └─ 方案可行性自评：[可行]/[需调整]
**异常处理**：
- 累计债券余额接近40%红线 → 建议压缩规模或偿还存量 → 与客户协商 → 如客户坚持原规模 → 标记"余额风险" → 组织者判断
- 主体评级低于AA → 利率建议区间显著偏高 → 建议增信措施 → 如客户不接受增信 → 标记"利率风险"
- 募投项目备案未完成 → 标记"备案缺失" → 建议先完成备案 → 或调整资金用途为补流（比例受限）
**时限要求**：5个工作日内完成方案初稿

#### 客户经理：协调客户确认方案参数

**触发条件**：立项通过
**执行步骤**：
1. 向客户索取/确认发行参数：
   - 拟发行规模（精确到亿元）
   - 资金用途明细（项目清单/补流金额）
   - 可接受的期限范围
   - 是否需要增信、可提供什么增信
2. 协调客户与产品支持沟通（如需要面对面讨论方案）
3. 收集客户对初稿方案的反馈
4. 推动客户确认方案框架
**输出物**：
- 《客户方案确认记录》
  ├─ 客户提供的发行参数
  ├─ 客户对方案初稿的反馈（同意/修改意见）
  └─ 方案确认状态：[已确认]/[待修改]/[需协商]
**异常处理**：
- 客户拒绝提供关键参数（如资金用途） → 标记"信息缺失" → 说明监管要求 → 如仍拒绝 → 标记"合规风险" → 组织者判断
- 客户坚持明显不可行的方案（如：评级AA-坚持按AAA利率定价） → 记录客户要求 → 产品支持出具风险提示 → 客户签字确认
**时限要求**：与产品支持方案设计并行，5个工作日内完成客户确认

#### 组织者：发行窗口初步判断

**触发条件**：产品支持提交方案初稿
**执行步骤**：
1. 分析当前市场利率环境（10年期国债收益率近期趋势）
2. 查询近1个月同评级债券发行情况（规模/利率/认购倍数）
3. 判断当前是否为有利发行窗口
4. 评估团队承销能力是否匹配项目规模
**输出物**：
- 《发行窗口初步判断》
  ├─ 利率环境：[下行]/[稳定]/[上行]
  ├─ 同评级发行活跃度：[活跃]/[一般]/[清淡]
  ├─ 窗口判断：[有利]/[中性]/[不利]
  └─ 建议申报时间：立即/1个月内/观望
**异常处理**：
- 窗口判断为"不利"（如利率快速上行） → 建议推迟申报 → 与客户协商 → 如客户坚持立即申报 → 标记"窗口风险"
- 项目规模超过团队当前承销能力 → 标记"能力缺口" → 启动内部协调或联合承销
**时限要求**：3个工作日内完成

立项通过
    │
    ├─→ 产品支持（5日）设计发行方案 ──────┐
    │                                      │

    │                                      ├─→ 方案初稿+客户确认
    └─→ 组织者（3日，产品提交后）窗口判断 ─┘
                                         │
                                         ▼
                              方案评审会（客户经理+产品支持+组织者）
                                         │
                                         ▼
                              方案定稿 → 进入事件4（材料准备）
```

### 事件4：申报材料准备

**事件定义**：发行方案确认，开始制作申报全套材料
**触发条件**：
- 发行方案经客户确认
- 方案评审会通过
**事件等级**：重点

#### 响应角色与动作

| 角色 | 动作 | 时限 | 依赖 |
|------|------|------|------|
| 客户经理 | 协调尽职调查与材料收集 | 10个工作日内 | 方案确认 |
| 产品支持 | 制作募集说明书等申报文件 | 10个工作日内 | 方案确认 |
| 合规审查 | 适当性与合规初审 | 5个工作日内 | 产品支持提交初稿 |

#### 客户经理：协调尽职调查与材料收集

**触发条件**：发行方案确认
**执行步骤**：
1. 启动尽职调查程序：
   - 制定尽调清单（财务/法律/业务/募集资金用途）
   - 协调客户准备基础材料（营业执照、章程、近3年审计报告、评级报告等）
2. 收集募投项目相关材料：
   - 项目备案/核准/批复文件
   - 可行性研究报告
   - 环评/土地/规划等前置文件（如需）
3. 收集增信材料（如有）：
   - 担保函/担保人财务资料
   - 抵押/质押资产评估报告
4. 协调律师、会计师进场
5. 跟进材料收集进度，每日更新《材料收集进度表》
**输出物**：
- 《尽调工作底稿》
- 《材料收集进度表》（含已收/未收/缺失清单）
- 关键材料扫描件归档
**异常处理**：
- 客户拖延提供材料 → 第3日发送催办函 → 第5日升级为客户经理上级催办 → 第7日提交组织者协调
- 募投项目备案未完成 → 标记"前置条件缺失" → 评估是否可改为补充流动资金 → 如不可改 → 暂停材料准备
- 担保人资质不足（如：担保人自身资产负债率过高） → 标记"增信不足" → 建议更换担保人或增加抵押 → 客户确认
**时限要求**：10个工作日内完成尽调和基础材料收集

#### 产品支持：制作募集说明书等申报文件

**触发条件**：发行方案确认
**执行步骤**：
1. 编制募集说明书：
   - 发行人基本情况
   - 财务数据引用（核对来源、确保准确）
   - 募集资金用途说明
   - 偿债保障措施
   - 风险因素披露
2. 编制发行公告/承销协议等法律文件
3. 引用数据质量检查（交叉核对Wind/审计报告/评级报告）
4. 格式合规检查（符合交易所/银行间市场格式要求）
**输出物**：
- 《募集说明书》初稿
- 《发行公告》初稿
- 《承销协议》初稿
- 数据引用核对表
**异常处理**：
- 募集说明书引用数据与审计报告不一致 → 标记"数据冲突" → 以审计报告为准 → 修改说明书 → 记录差异原因
- 风险因素披露不充分（少于监管要求条目） → 标记"披露不足" → 补充风险条目 → 合规审查确认
**时限要求**：10个工作日内完成初稿

#### 合规审查：适当性与合规初审

**触发条件**：产品支持提交募集说明书初稿
**执行步骤**：
1. 审查发行人合规状态：
   - 是否具备发行该类债券的法定条件
   - 近3年是否有重大违规记录
   - 决策程序是否完整（董事会/股东会决议）
2. 审查募集说明书合规性：
   - 信息披露是否充分
   - 风险因素是否完整
   - 募集资金用途是否合规
3. 审查适当性：
   - 投资者适当性安排是否符合要求
**输出物**：
- 《合规初审意见》
  ├─ 发行人合规状态：[合规]/[需关注]/[不合规]
  ├─ 募集说明书审查：[通过]/[需修改]/[不通过]
  ├─ 需修改事项清单（如有）
  └─ 适当性审查：[通过]/[需补充]
**异常处理**：
- 发行人不符合法定发行条件 → 标记"法定障碍" → 暂停申报 → 评估是否有补救路径
- 发现新增合规风险（如：近期新增处罚） → 标记"新增风险" → 更新风险披露 → 质控内核复核
**时限要求**：5个工作日内完成初审

#### 同步机制

方案确认
    │
    ├─→ 客户经理（10日）尽调+材料收集 ──────┐
    │                                         │
    ├─→ 产品支持（10日）制作申报文件 ─────────┤
    │                                         ├─→ 材料齐全+文件初稿
    └─→ 合规审查（5日，初稿提交后）初审 ─────┘
                                              │
                                              ▼
                                   材料齐全审查会
                                              │
                                              ▼
                                   [齐全] → 进入事件5（申报复核）
                                   [缺失] → 退回补充（限5个工作日）
```

### 事件5：监管申报前复核

**事件定义**：全套申报材料准备完成，提交监管申报前的内部复核
**触发条件**：
- 募集说明书定稿
- 尽调底稿齐全
- 合规初审通过
**事件等级**：重大

#### 响应角色与动作

| 角色 | 动作 | 时限 | 依赖 |
|------|------|------|------|
| 质控内核 | 项目质量分析与材料完整性检查 | 5个工作日内 | 全套材料齐备 |
| 合规审查 | 合规风险复核与申报条件检查 | 3个工作日内 | 质控内核提交质量报告 |
| 组织者 | 重大风险判断与签字决策 | 3个工作日内 | 质控+合规报告齐备 |
| 客户经理 | 签字前准备与利益冲突排查 | 并行 | 全套材料齐备 |

#### 质控内核：项目质量分析

**触发条件**：全套申报材料齐备
**执行步骤**：
1. 执行项目质量分析模型（参照定增模型模型L）：
   - 材料完整性检查（对照申报清单逐项核对）
   - 数据质量检查（财务数据引用准确性、计算正确性）
   - 规律质量检查（说明书前后规律一致性、章节衔接）
   - 风险可控性评估（偿债能力分析是否客观、风险揭示是否充分）
2. 独立复核5维度分析结论（重新计算关键指标）
3. 出具质控报告
**输出物**：
- 《质控报告》
  ├─ 材料完整性：[完整]/[缺失X项]
  ├─ 数据质量：[通过]/[有误X处]
  ├─ 规律质量：[通过]/[需修改X处]
  ├─ 风险可控性：[可控]/[需关注]/[不可控]
  ├─ 5维度复核结论：[一致]/[有差异，差异说明]
  └─ 项目质量评级：[A]/[B]/[C]/[D]
**异常处理**：
- 发现数据重大错误（如：现金流覆盖率计算错误导致结论反转） → 标记"数据错误" → 退回产品支持修正 → 重新复核
- 项目质量评级为C或D → 标记"质量不达标" → 提交组织者判断是否继续推进
**时限要求**：5个工作日内完成

#### 合规审查：合规风险复核

**触发条件**：质控内核提交质量报告后
**执行步骤**：
1. 复核发行人申报条件（法定条件逐项检查）
2. 复核决策程序完整性：
   - 董事会决议是否已获取
   - 股东会决议是否已获取（如需）
   - 授权签字人是否合规
3. 复核信息披露充分性
4. 复核利益冲突（承销商与发行人是否存在关联关系）
5. 出具合规复核意见
**输出物**：
- 《合规复核意见》
  ├─ 申报条件：[满足]/[不满足，具体缺失]
  ├─ 决策程序：[完整]/[缺失，具体缺失]
  ├─ 信息披露：[充分]/[不充分，需补充]
  ├─ 利益冲突：[无冲突]/[有冲突，已披露/需处理]
  └─ 合规总体判断：[通过]/[需整改]/[不通过]
**异常处理**：
- 申报条件不满足（如：净资产低于法定要求） → 标记"法定障碍" → 不通过 → 退回
- 利益冲突未披露 → 标记"利益冲突" → 要求补充披露 → 如无法消除 → 提交组织者判断是否回避
**时限要求**：3个工作日内完成

#### 组织者：重大风险判断与签字决策

**触发条件**：质控报告+合规复核意见齐备
**执行步骤**：
1. 综合审阅质控报告和合规复核意见
2. 判断重大风险：
   - 偿债能力是否真实可靠（是否有粉饰嫌疑）
   - 发行窗口是否合适（错过窗口的风险）
   - 项目质量评级是否可接受
3. 评估团队执行能力（是否有足够精力做好这个项目）
4. 做出签字决策
**输出物**：
- 《签字决策》
  ├─ 重大风险判断：[可控]/[需关注]/[不可控]
  ├─ 执行能力评估：[充足]/[紧张]/[不足]
  ├─ 签字决策：[同意申报]/[需补充条件]/[不同意申报]
  └─ 如为"需补充条件"，列明具体条件
**异常处理**：
- 重大风险判断为"不可控" → 不批准申报 → 记录原因 → 通知客户经理
- 执行能力不足 → 标记"资源缺口" → 协调资源或推迟申报
**时限要求**：3个工作日内完成决策

#### 客户经理：签字前准备

**触发条件**：全套材料齐备
**执行步骤**：
1. 完成利益冲突排查（个人及关联方）
2. 确认尽调工作底稿齐全并签字
3. 确认已履行适当性义务
4. 准备签字页
**输出物**：
- 《利益冲突排查表》（本人签字）
- 《尽职调查声明》（签字）
- 《适当性义务履行确认》
**异常处理**：
- 发现利益冲突 → 如实披露 → 组织者判断是否回避
**时限要求**：与质控/合规复核并行，5个工作日内完成

#### 同步机制

```
材料齐备
    │
    ├─→ 质控内核（5日）项目质量分析 ──────┐
    │                                       │
    ├─→ 客户经理（5日）签字前准备 ──────────┤
    │                                       ├─→ 质量报告+签字材料
    └─→ 合规审查（3日，质控提交后）复核 ───┘
                                             │
                                             ▼
                                  组织者（3日）重大风险判断
                                             │
                                             ▼
                                  [同意申报] → 正式申报监管
                                  [需补充] → 退回补充（限5日）
                                  [不同意] → 终止，记录原因
```

### 事件6：发行定价与承销

**事件定义**：监管审核通过，进入发行阶段，完成定价、簿记建档和承销
**触发条件**：
- 监管审核通过（交易所/银行间市场）
- 取得发行批文
**事件等级**：重大

#### 响应角色与动作

| 角色 | 动作 | 时限 | 依赖 |
|------|------|------|------|
| 客户经理 | 投资者路演与需求摸底 | 批文取得后10个工作日内 | 批文取得 |
| 产品支持 | 定价建议与簿记建档 | 路演后5个工作日内 | 路演完成 |
| 组织者 | 发行窗口监测与资源调配 | 并行 | 批文取得 |

#### 客户经理：投资者路演与需求摸底

**触发条件**：取得发行批文
**执行步骤**：
1. 制定路演计划（对象、时间、方式）
2. 组织投资者路演（一对多/一对一）
3. 收集投资者需求意向（认购规模/利率要求）
4. 汇总需求摸底结果
**输出物**：
- 《路演记录》
- 《投资者需求汇总》（意向认购规模/利率区间分布）
**异常处理**：
- 投资者需求严重不足（意向认购<发行规模50%） → 标记"需求不足" → 建议调整利率或推迟发行 → 提交组织者判断
- 主要投资者要求利率远超预期 → 标记"利率压力" → 建议重新定价 → 客户协商
**时限要求**：10个工作日内完成路演

#### 产品支持：定价建议与簿记建档

**触发条件**：路演完成，需求摸底结果齐备
**执行步骤**：
1. 基于路演需求分析定价区间：
   - 投资者需求分布
   - 同评级近期发行利率
   - 当前市场利率环境
2. 向客户提交定价建议
3. 客户确认票面利率
4. 启动簿记建档
5. 完成配售
**输出物**：
- 《定价建议书》
- 《簿记建档结果》
- 《配售方案》
**异常处理**：
- 簿记认购不足 → 标记"认购不足" → 启动余额包销（如协议约定） → 或推迟发行
- 簿记认购远超预期 → 优化配售结构 → 确保核心投资者获配
**时限要求**：5个工作日内完成

#### 组织者：发行窗口监测与资源调配

**触发条件**：取得发行批文后持续监测
**执行步骤**：
1. 每日监测市场利率变化
2. 判断最佳发行时机（窗口判断）
3. 协调内部资源（如余额包销资金准备）
**输出物**：
- 《发行窗口日报》（利率变化/同类型发行情况/窗口判断）
**异常处理**：
- 市场利率突然大幅上行 → 标记"窗口恶化" → 建议推迟定价 → 客户协商
**时限要求**：持续监测，关键决策当日完成

### 事件7：发行后督导

**事件定义**：债券成功发行，进入后续督导期
**触发条件**：
- 债券发行成功
- 募集资金到账
**事件等级**：常规

#### 响应角色与动作

| 角色 | 动作 | 时限 | 依赖 |
|------|------|------|------|
| 客户经理 | 募集资金使用跟踪与定期回访 | 持续 | 发行完成 |
| 合规审查 | 信息披露监督与合规检查 | 持续 | 发行完成 |

#### 客户经理：募集资金使用跟踪与定期回访

**触发条件**：债券发行成功
**执行步骤**：
1. 募集资金到账确认
2. 按季度跟踪募集资金使用情况：
   - 是否按募集说明书约定用途使用
   - 使用进度是否符合计划
3. 定期回访客户（至少每半年一次）：
   - 经营状况变化
   - 偿债能力变化
   - 新融资需求
4. 记录督导情况
**输出物**：
- 《募集资金使用跟踪表》（季度更新）
- 《定期回访记录》
**异常处理**：
- 发现募集资金挪用 → 标记"资金挪用" → 要求客户纠正 → 如拒不纠正 → 合规审查介入 → 必要时启动债券持有人会议
- 客户偿债能力显著恶化 → 标记"偿债风险上升" → 提交组织者 → 启动风险处置预案
**时限要求**：季度跟踪，半年回访

#### 合规审查：信息披露监督与合规检查

**触发条件**：债券发行成功
**执行步骤**：
1. 监督定期信息披露（年报/半年报中债券相关内容）
2. 监督重大事项披露（如：可能影响偿债能力的重大事件）
3. 检查募集资金使用情况披露
4. 督导期结束前的合规检查
**输出物**：
- 《信息披露监督记录》
- 《合规检查报告》（年度）
**异常处理**：
- 发现信息披露遗漏 → 提醒发行人补充披露 → 记录
- 发行人触发违约风险事件 → 标记"违约预警" → 启动应急处置
**时限要求**：持续监督，年度出检查报告

## 三、动作执行检查清单

| 事件 | 检查项 | 谁检查 | 什么时候 |

## 五、与债券分析模型的衔接

| 分析模型维度 | 在哪个事件中被调用 | 谁调用 | 输出如何使用 |
|-------------|-------------------|--------|-------------|
| 维度1：偿债能力 | 事件2（立项评估） | 客户经理 | 判断能不能还得起，决定立项/暂缓 |
| 维度2：发行方案 | 事件3（方案设计） | 产品支持 | 确定规模/期限/利率/还本付息 |
| 维度3：市场窗口 | 事件3+事件6 | 组织者+产品支持 | 判断申报时机和定价区间 |
| 维度4：资金用途 | 事件2+事件3 | 客户经理+产品支持 | 验证项目真实性，设计资金分配 |
| 维度5：增信合规 | 事件2+事件5 | 质控内核+合规审查 | 评估合规风险，判断是否可签字 |

**衔接原则**：
- 分析模型输出"判断结论"，动作模型根据结论决定"做什么"
- 如维度1判断"不通过"（现金流覆盖率<1.0），动作模型不终止项目，而是标记风险→升级组织者→决定继续/暂停
- 如维度5发现新增处罚，动作模型触发"合规审查"→重新评估→更新风险披露
