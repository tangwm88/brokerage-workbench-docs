# 零售业务动作标准原子模型 + AI驱动支持卡片

> 基于v4.2员工标准动作体系，定义原子模型并展示AI对每个动作的驱动和支持
> 版本：v1.0
> 时间：2026-06-19

---

## 一、什么是动作标准原子模型

**定义：** 把每个动作拆解为"人的职责+AI的驱动+AI的支持"三部分，明确人和AI的边界，让AI成为员工的助手而不是替代者。

**设计原则：**
- **人做判断和决策** — 客户意向判断、方案选择、合规把关
- **AI做数据处理和生成** — 调数据、写报告、推方案、做提醒
- **人机协同** — AI准备好一切，人负责最后一步执行

### 卡片1：接收客户服务任务

```
┌─────────────────────────────────────────────────────────┐
│  动作1：接收客户服务任务                                  │
│  定位：所有人工服务的起点                                  │
├─────────────────────────────────────────────────────────┤
│  【员工职责】                                             │
│  □ 查看任务单详情（客户/标签/触发原因/优先级/时限）        │
│  □ 确认任务可执行性（自身权限/客户归属/时间冲突）          │
│  □ 决定接受、退回或申请转交                               │
├─────────────────────────────────────────────────────────┤
│  【AI驱动】                                               │
│  ◆ 自动触发任务单                                         │
│    - 模型识别客户状态变化 → 自动生成任务单                  │
│    - 周期触达计划到期 → 自动推送提醒                       │
│    - 客户主动发起 → 即时生成任务单                         │
│  ◆ 智能优先级排序                                         │
│    - 按客户等级(S/A/B/C) + 紧急程度自动排序                │
│    - 高优先级标红置顶                                     │
│  ◆ 智能分配建议                                           │
│    - 按客户经理负荷/客户关系/历史服务匹配度推荐分配         │
├─────────────────────────────────────────────────────────┤
│  【AI支持】                                               │
│  ◆ 客户信息摘要卡片                                       │
│    - 一键展示客户核心标签、近期变化、历史服务记录           │
│  ◆ 冲突检测                                               │
│    - 自动检测时间冲突/权限冲突/客户归属冲突并预警           │
│  ◆ 任务统计看板                                           │
│    - 今日待办/本周进度/超时预警                           │
├─────────────────────────────────────────────────────────┤
│  【人机边界】                                             │
│  AI做：生成任务单、排优先级、检测冲突、推荐分配             │
│  人做：确认接收、判断可执行性、决定接受/退回/转交           │
├─────────────────────────────────────────────────────────┤
│  【输出物】                                               │
│  - 任务接收记录：接收时间/客户经理/任务类型/客户信息        │
│  - 客户信息摘要卡片                                       │
└─────────────────────────────────────────────────────────┘
```

**不同客户等级的AI差异：**

| 客户等级 | AI触发逻辑 | AI分配策略 | 时限提醒 |
|---------|-----------|-----------|---------|
| **S级** | 资产任何变化即时触发 | 优先分配给专属客户经理 | 即时推送+短信 |
| **A级** | 季度+状态变化触发 | 按关系匹配分配 | 2小时内提醒 |
| **B级** | 半年+产品到期触发 | 按负荷均衡分配 | 4小时内提醒 |
| **C级** | 年度+系统批量触发 | 批量任务池分配 | 不单独提醒 |

| **A级** | 标准数据+持仓+历史 | 标准配置方案+产品组合 | 中度个性化（风险/收益偏好） |
| **B级** | 标签+持仓摘要 | 标准化产品推荐 | 轻度个性化（生命周期/状态） |
| **C级** | 基础标签 | 模板化推荐 | 无个性化，批量处理 |

## 五、实施要点

### 5.1 系统建设优先级

| 优先级 | 功能模块 | 说明 |
|--------|---------|------|
| **P0** | 客户数据聚合+诊断摘要 | 服务准备的核心基础 |
| **P0** | 任务单系统+优先级排序 | 接收任务的核心基础 |
| **P1** | 实时辅助+合规预警 | 触达客户的核心辅助 |
| **P1** | 自动登记+标签更新 | 登记结果的核心自动化 |
| **P2** | 跟踪计划+效果评估 | 跟踪反馈的智能化 |
| **P2** | 管理工作台 | 团队长的管理工具 |

### 5.2 人机边界红线

**AI绝对不能做的：**
- ❌ 代替客户做投资决策
- ❌ 代替员工做合规判断
- ❌ 向客户承诺收益或保本
- ❌ 无人工审核直接发送投资建议

**AI辅助但人必须确认的：**
- ⚠️ 产品配置方案（AI生成→人审核→客户触达）
- ⚠️ 高风险产品推荐（R4-R5必须人工确认）
- ⚠️ 客户投诉处理（必须人工处理）

**AI可以全自动做的：**
- ✅ 数据调取和聚合
- ✅ 诊断摘要生成
- ✅ 基础标签更新
- ✅ 市场信息推送
- ✅ 任务提醒和跟踪计划
