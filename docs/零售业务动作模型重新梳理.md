# 零售业务动作模型重新梳理

> 目标：从角色出发，提炼最共性的规定动作，再套七事件格式

---

## 一、问题：v4.0第三层的问题

v4.0把**场景**和**原子动作**混在了同一层：

```
v4.0第三层（6个动作模型）
├── 客户触达动作      ← 勉强算原子
├── 持仓复盘动作      ← 这是场景（诊断+建议的组合）
├── 产品配置动作      ← 这是场景（诊断+建议+执行的组合）
├── 重点关注动作      ← 这是场景（触达+诊断+建议的组合）
├── 流失挽回动作      ← 这是场景（触达+诊断+建议的组合）
└── 团队管理动作      ← 另一个角色的动作
```

**问题：** 持仓复盘、产品配置、重点关注、流失挽回不是"原子动作"，是场景化的动作组合。放在第三层导致：
- 场景膨胀（每新增一个场景就要新增一个动作模型）
- 动作之间大量重复步骤（都要先触达、都要诊断、都要记录）
- 不体现"最共性"

---

## 二、重新梳理：从角色出发

### 2.1 谁执行动作？

| 角色 | 是否执行动作 | 动作类型 |
|------|------------|---------|
| **投资者** | 否 | 被服务方，接收服务 |
| **客户经理** | **是** | **核心执行方，所有规定动作的执行者** |
| **团队长** | 是（少量） | 管理方，审批/分配/监督 |

### 2.2 客户经理的核心目的是什么？

> **高效服务客户、创造收入、维护关系**

围绕这个目的，客户旅程中**无论面对什么客户、什么场景**，都必须执行的**共性动作**是什么？

---

## 三、最共性的4个原子动作

经过收敛，零售客户经理**所有场景**都逃不出这4个动作：

### 动作1：触达（建立联系）

**定位：** 所有服务的第一步。无论什么情况，先和客户建立联系。

**共性体现：**
- 新客首触要触达
- 定期维护要触达
- 大额亏损要触达
- 流失挽回要触达
- 产品配置要触达
- **所有场景的第一步都是触达**

**关键决策点（不同场景的差异点）：**
| 场景 | 触达渠道 | 触达时机 | 触达目的 |
|------|---------|---------|---------|
| 新客首触 | 企微/电话 | 开户后24小时 | 建立关系+了解需求 |
| 定期维护 | 企微/面谈 | 按周期 | 保持关系温度 |
| 大额亏损 | 电话/面谈 | 触发后24小时 | 主动关怀+诊断 |
| 流失挽回 | 电话/面谈 | 触发后48小时 | 了解原因+挽回 |
| 产品配置 | 面谈 | 客户预约后 | 方案讲解+双录 |

> **差异点在触发条件和渠道选择，动作本身（建立联系）是共性的。**

---

### 动作2：诊断（分析评估）

**定位：** 了解客户当前状况，是给出建议的前提。

**共性体现：**
- 首触时要诊断客户资产/风险/需求
- 定期维护要诊断客户持仓变化
- 大额亏损要诊断亏损归因
- 产品配置要诊断适当性匹配
- 流失挽回要诊断流失原因
- **所有场景都需要先诊断**

**诊断对象（共性框架，不因场景改变）：**
1. **资金诊断**：资产规模、创收贡献、变化趋势
2. **持仓诊断**：结构、集中度、盈亏、风格
3. **需求诊断**：风险等级、投资目标、服务偏好
4. **关系诊断**：生命周期阶段、活跃度、满意度

> **差异点在诊断的侧重点（首触重需求，亏损重归因，配置重适当性），诊断框架是共性的。**

---

### 动作3：建议（方案输出）

**定位：** 基于诊断结果，给出专业方案。

**共性体现：**
- 首触后建议首单产品
- 定期维护后建议配置调整
- 大额亏损后建议优化方案
- 产品配置时给出配置方案
- 流失挽回时给出挽留方案
- **所有场景诊断后都要给建议**

**建议类型（共性框架）：**
1. **产品建议**：推荐匹配的产品（基金/投顾/固收等）
2. **配置建议**：资产配置比例调整
3. **操作建议**：定投计划、止盈止损、调仓
4. **服务建议**：升级服务等级、转介绍权益

> **差异点在建议内容，输出动作本身是共性的。**

---

### 动作4：执行（业务落地）

**定位：** 客户认可方案后，协助完成业务操作。

**共性体现：**
- 产品推荐后协助下单
- 配置方案后协助调仓
- 签约时的双录、资料收集
- 异常处理时的操作（销户挽留、投诉升级等）
- **所有建议被接受后都要执行**

**执行内容（共性框架）：**
1. **交易执行**：下单、调仓、申购赎回
2. **签约执行**：风险揭示、适当性确认、双录
3. **资料执行**：资料收集、表单填写、提交审核
4. **升级执行**：投诉升级、合规上报、团队长介入

> **差异点在执行的具体业务，执行动作本身是共性的。**

---

### 动作5：记录（语料沉淀）— 嵌入动作，不独立

**定位：** 每个动作完成后必须留痕，但不是独立动作，嵌入每个动作的最后一步。

**记录内容（共性）：**
- 触达记录：时间/渠道/时长/内容/客户反馈
- 诊断记录：分析结论/关键发现/数据依据
- 建议记录：方案内容/客户反应/是否接受
- 执行记录：操作结果/业务单据/合规留痕

## 四、场景 vs 原子的关系

```
第二层：服务模型（场景化组合）
├── 首触服务 = 触达(新客) + 诊断(需求) + 建议(首单) + 记录
├── 定期复盘服务 = 触达(周期触发) + 诊断(持仓) + 建议(调整) + 记录
├── 大额亏损关注服务 = 触达(主动) + 诊断(归因) + 建议(优化) + 记录
├── 产品配置服务 = 触达(邀约) + 诊断(适当性) + 建议(方案) + 执行(双录) + 记录
├── 流失挽回服务 = 触达(挽回) + 诊断(原因) + 建议(方案) + 记录
└── ...（新增场景只需组合原子，不新增动作模型）

第三层：动作模型（原子动作，七事件格式）
├── 动作1：触达动作（建立联系）
├── 动作2：诊断动作（分析评估）
├── 动作3：建议动作（方案输出）
└── 动作4：执行动作（业务落地）
```

## 五、4个原子动作的七事件格式草案

### 动作1：触达动作

```
事件名称：触达（建立联系）
触发条件：
  - 条件A：系统触发任务单（高优先级）
  - 条件B：周期性触达计划（中优先级）
  - 条件C：客户主动发起（最高优先级）
执行步骤：
  1. 调取客户分析标签（工具：客户分析系统 / 时限：触达前30分钟）
  2. 确认触达目的和沟通要点（工具：沟通要点模板 / 时限：触达前15分钟）
  3. 选择触达渠道（工具：企微/电话/面谈 / 决策依据：客户偏好+场景要求）
  4. 执行触达（工具：对应渠道 / 时限：按任务单要求）
  5. 记录触达结果（工具：员工行为语料库 / 时限：触达后2小时）
输出标准：
  - 触达记录：时间/渠道/时长/核心内容/客户反馈/下一步计划
异常处理：
  - 客户拒接→3日后二次触达（换渠道）
  - 客户转户意向→标记流失预警，升级团队长
  - 客户投诉→触发投诉处理流程
时限要求：按任务单要求（紧急24小时/常规72小时）
验收标准：系统留痕完整+客户反馈已记录+下一步计划已明确
```

### 动作2：诊断动作

```
事件名称：诊断（分析评估）
触发条件：
  - 条件A：触达后需了解客户状况（默认触发）
  - 条件B：客户资产/持仓/状态发生重大变化
  - 条件C：定期诊断（每季度/资产变化超20%）
执行步骤：
  1. 调取客户全景数据（工具：账户系统+分析模型 / 时限：30分钟）
  2. 执行资金诊断（资产规模、创收、变化趋势）
  3. 执行持仓诊断（结构、集中度、盈亏、风格）
  4. 执行需求诊断（风险等级、投资目标、服务偏好）
  5. 执行关系诊断（生命周期、活跃度、满意度）
  6. 输出诊断结论（工具：诊断报告模板 / 时限：触达后1小时）
  7. 记录诊断结果（工具：员工行为语料库 / 时限：诊断后2小时）
输出标准：
  - 诊断报告：四维分析结论+关键发现+数据依据+风险提示
异常处理：
  - 数据缺失→标记缺失项，基于已有数据推断+人工补充
  - 客户拒绝提供信息→记录原因，设置下次诊断时间
  - 发现合规风险→立即升级合规部门
时限要求：触达后1小时内完成诊断报告
验收标准：四维诊断完整+数据依据充分+结论明确+已记录
```

### 动作3：建议动作

```
事件名称：建议（方案输出）
触发条件：
  - 条件A：诊断完成后自动生成建议（默认触发）
  - 条件B：客户主动要求建议
  - 条件C：持仓复盘/资产配置场景
执行步骤：
  1. 读取诊断结论（工具：诊断报告 / 时限：5分钟）
  2. AI生成建议方案（工具：产品匹配模型+配置模型 / 时限：10分钟）
  3. 客户经理审核方案合规性（工具：工作台 / 时限：15分钟）
  4. 向客户讲解建议方案（工具：面谈/电话 / 时限：30分钟）
  5. 确认客户意向（接受/拒绝/犹豫）
  6. 记录建议结果（工具：员工行为语料库 / 时限：讲解后2小时）
输出标准：
  - 建议方案书：诊断依据+建议内容+产品明细+风险提示+客户意向
异常处理：
  - 客户风险等级与建议不匹配→拒绝建议，重新诊断
  - 客户拒绝建议→记录原因，设置跟进计划
  - 客户犹豫→7日内再次触达，补充信息
  - 涉及R4-R5产品→必须人工确认后才能输出
时限要求：诊断后2小时内完成方案，讲解按客户预约时间
验收标准：适当性匹配合规+风险提示完整+客户意向已记录
```

### 动作4：执行动作

```
事件名称：执行（业务落地）
触发条件：
  - 条件A：客户接受建议，确认执行（默认触发）
  - 条件B：客户主动发起业务办理
  - 条件C：异常情况需要操作（销户挽留、投诉处理等）
执行步骤：
  1. 确认执行内容（工具：建议方案书 / 时限：5分钟）
  2. 校验适当性与合规（工具：适当性系统 / 时限：10分钟）
  3. 执行业务操作（工具：交易系统/签约系统 / 时限：按业务类型）
    - 交易执行：下单/调仓/申购赎回
    - 签约执行：风险揭示+适当性确认+双录
    - 资料执行：收集/填写/提交
    - 升级执行：投诉升级/合规上报
  4. 确认执行结果（工具：业务系统回执 / 时限：操作后即时）
  5. 记录执行结果（工具：员工行为语料库 / 时限：操作后2小时）
输出标准：
  - 执行确认单：操作内容+合规校验结果+业务回执+客户确认
异常处理：
  - 适当性不匹配→拒绝执行，重新建议
  - 系统故障→记录故障，手工处理+后续补录
  - 客户反悔→按撤销流程处理
  - 涉及资金超限→升级审批
时限要求：客户确认后即时执行，复杂业务不超过24小时
验收标准：合规校验通过+操作留痕完整+业务回执已归档
```

## 六、与v4.0的对比

| 维度 | v4.0（6个动作模型） | 重新梳理（4个原子动作） |
|------|-------------------|----------------------|
| **粒度** | 场景级（持仓复盘/产品配置/流失挽回） | 原子级（触达/诊断/建议/执行） |
| **扩展性** | 每新增场景需新增动作模型 | 新增场景只需组合原子动作 |
| **重复度** | 每个动作模型都包含"触达→诊断→建议→记录" | 原子动作互不重复，场景按需组合 |
| **角色对齐** | 混入了团队管理动作 | 客户经理4个+团队长另列 |
| **七事件格式** | 每个场景写一次，内容冗长 | 4个原子各写一次，场景引用即可 |

## 七、下一步

1. **确认这4个原子动作是否完整**：触达/诊断/建议/执行，是否覆盖了客户经理所有工作？
2. **团队长动作**：团队长的管理动作是否也收敛为3-4个原子？（看板查看/任务分配/异常审批/复盘培训）
3. **场景组合表**：把v4.0中所有场景（首触/复盘/配置/关注/挽回/管理）用原子动作重新组合表达
4. **输出格式**：确认后把4个原子动作的七事件格式写完整，作为第三层动作模型
