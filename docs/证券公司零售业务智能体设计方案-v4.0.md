# 证券公司零售业务智能体设计方案 v4.0

> **面向角色：** 投资者（被服务方）+ 客户经理（执行方）+ 团队长（管理方）
> **核心目标：** 模型自动化服务大部分客户，前台团队服务动作按需叠加
> **设计依据：** 陶总方法论 + 统一参考方法论 + 架构图v2.0 + 禁用词语表
> 版本：v4.0（基于v3.0重构）
> 时间：2026-06-18

---

## 一、先定角色和目的

### 1.1 三类角色

| 角色 | 定位 | 核心诉求 | 与模型的关系 |
|------|------|---------|------------|
| **投资者** | 服务接收方 | 获得匹配自身情况的投资服务与产品 | 被模型分析、被服务模型覆盖、接收自动化服务 |
| **客户经理** | 服务执行方 | 高效服务大量客户，重点精力投向高价值/高流失风险客户 | 执行动作模型规定的标准动作，响应模型触发的任务单 |
| **团队长** | 管理组织者 | 穿透团队服务全貌，识别风险与机会，调配资源 | 接收团队级聚合报告，审批异常处理，驱动迭代 |

### 1.2 核心目的

**一句话：让模型自动化覆盖80%客户的标准化服务，客户经理专注处理20%需要人工判断和情感连接的场景。**

```
┌─────────────────────────────────────────────────────────────┐
│  自动化服务层（模型驱动，无需人工介入）                        │
│  ├─ 客户自动分层与标签更新                                    │
│  ├─ 标准化信息推送（市场动态/持仓提醒/产品匹配）              │
│  ├─ 常规投后报告自动生成与发送                                │
│  ├─ 沉睡客户自动唤醒触达                                    │
│  └─ 覆盖客群：80%                                           │
├─────────────────────────────────────────────────────────────┤
│  人工叠加层（客户经理执行，模型触发任务单）                    │
│  ├─ 高价值客户深度服务                                      │
│  ├─ 大额亏损情绪安抚与信任重建                              │
│  ├─ 复杂产品配置方案沟通                                    │
│  ├─ 流失预警客户挽回                                        │
│  └─ 覆盖客群：20%                                           │
└─────────────────────────────────────────────────────────────┘
```

## 二、三层模型体系

### 2.1 模型总览

```

├── 第一层：客户分析模型（4个本质维度）

│   └── 服务模型D：团队管理服务
└── 第三层：动作模型（七事件格式）
    ├── 动作模型1：客户触达动作
    ├── 动作模型2：持仓复盘动作

    ├── 动作模型5：流失挽回动作
    └── 动作模型6：团队管理动作
```

## 三、第一层：客户分析模型

### 3.1 设计原则

- **4个本质维度**，每个维度3-5档，客户经理能记住、能使用
- **客观量化**，每档有明确的数字边界
- **直接驱动动作**，每个维度变化自动触发对应服务动作
- **系统自动更新**，标签变化由模型自动识别，无需人工维护

### 3.2 维度1：资金体量

**定位：** 客户对券商的综合价值，决定服务等级和资源配置。

| 等级 | 判定标准（月日均，三选一达标） | 服务等级 |
|------|------------------------------|---------|
| **S级** | 资产规模≥1000万，或月均创收≥3000元 | 专属客户经理+团队长关注 |
| **A级** | 资产规模300-1000万，或月均创收500-3000元 | 客户经理一对一维护 |
| **B级** | 资产规模5-300万，或月均创收50-500元 | 标准化自动化服务为主 |
| **C级** | 资产规模<5万，且月均创收<50元 | 批量自动化服务 |

**触发动作：**
- C级→B级（资产增长达标）：自动触发"服务升级通知"
- A级→S级（资产突破1000万）：自动触发"专属服务激活任务单"给团队长
- 任意等级资产连续3月下降超20%：自动触发"流失预警任务单"

### 3.3 维度2：交易倾向

**定位：** 客户的交易习惯和投资方式，决定沟通内容和服务重点。

| 类型 | 判定标准 | 核心特征 |
|------|---------|---------|
| **高频交易型** | 月换手率≥200%，或月交易笔数≥30笔 | 追求短期收益，关注市场热点和个股机会 |
| **中频波段型** | 月换手率50%-200%，或月交易笔数10-29笔 | 有一定择时能力，关注行业趋势和板块轮动 |
| **低频长期型** | 月换手率10%-50%，或月交易笔数1-9笔 | 偏向长期持有，关注企业实际质地和估值 |
| **超低频保守型** | 月换手率<10%，或月交易笔数0笔但资产>0 | 几乎不交易，以现金管理或被动持有为主 |
| **零交易型** | 月交易笔数0笔，且账户无资产 | 未激活或已流失 |

**持仓风格标签（辅助，不独立成维度）：**
- 大盘蓝筹型：蓝筹个股成交占比≥60%
- 成长赛道型：产业大盘成长成交占比≥60%
- 小盘题材型：中小盘成长/题材个股成交占比≥60%
- 红利防御型：红利个股成交占比≥60%
- 可转债型：可转债成交占比≥30%

**触发动作：**
- 低频长期型→高频交易型（交易频率连续2月提升）：自动触发"交易活跃度提升关怀"
- 高频交易型→低频长期型（交易频率连续3月下降）：自动触发"活跃度下降关注"
- 持仓风格标签变化：自动触发"持仓风格变化提醒"

### 3.4 维度3：当前状态

**定位：** 客户当前的收益状况和持仓健康度，决定当前最需要什么服务。

| 状态 | 判定标准（近3个月收益率） | 核心诉求 |
|------|------------------------|---------|
| **大幅盈利** | 收益率>15% | 止盈建议、利润保护、再配置建议 |
| **稳健盈利** | 0<收益率≤15% | 维持策略、产品渗透、提升服务体验 |
| **盈亏平衡** | -5%≤收益率≤0 | 维持信心、市场解读、避免恐慌操作 |
| **小幅亏损** | -15%<收益率<-5% | 亏损归因、持仓诊断、修复建议 |
| **深度亏损** | 收益率≤-15% | 情绪安抚、深度诊断、资产修复方案 |

**持仓集中度标签（辅助）：**
- 集中型：单一标的持仓占比>50%
- 适度集中：单一标的持仓占比30%-50%
- 分散型：单一标的持仓占比<30%

**触发动作：**
- 大幅盈利→深度亏损（单月跌幅超20%）：自动触发"剧烈波动关怀任务单"给客户经理
- 深度亏损持续3个月未改善：自动触发"高优先级安抚任务单"
- 持仓集中度>50%且该标的近月跌幅>10%：自动触发"集中度风险提示"

### 3.5 维度4：生命周期

**定位：** 客户与公司的关系阶段，直接决定服务策略和触发动作。

| 阶段 | 判定标准 | 自动化服务占比 | 人工叠加触发条件 |
|------|---------|--------------|----------------|
| **潜在客户** | 未开户，但在线索池 | 100%自动化（线索培育） | 线索活跃度达标→分配客户经理 |
| **新客** | 开户≤30天 | 90%自动化 | 开户7天未入金→客户经理跟进 |
| **尝鲜客户** | 开户>30天，有首笔交易但近30天无交易 | 80%自动化 | 连续45天无交易→客户经理唤醒 |
| **活跃客户** | 近30天有交易 | 70%自动化 | 资产升级/状态异常→客户经理介入 |
| **沉睡客户** | 资产>0，近90天零交易 | 60%自动化 | 沉睡超180天→客户经理挽回 |
| **忠诚客户** | 开户≥1年+月均资产≥10万+近12个月有交易+累计创收≥500元 | 50%自动化 | 定期专属服务+转介绍激励 |
| **流失客户** | 已销户，或资产=0且连续180天零交易 | 归档/批量挽回 | 高价值流失→客户经理挽回 |
| **回流客户** | 曾经流失/沉睡，近30天重新入金或交易 | 70%自动化 | 回流后30天→客户经理关怀 |

**触发动作（生命周期状态变化自动触发）：**

| 变化 | 自动触发动作 | 任务单对象 |
|------|------------|----------|
| 潜在客户→新客 | 自动发送"开户欢迎+新客引导" | 系统自动化 |
| 新客→尝鲜客户（完成首单） | 自动发送"首单确认+持续服务介绍" | 系统自动化 |
| 活跃客户→沉睡客户 | 自动发送"沉睡唤醒信息"+30天后客户经理任务单 | 系统→客户经理 |
| 活跃客户→忠诚客户 | 自动发送"忠诚客户升级通知"+专属服务介绍 | 系统→客户经理 |
| 任意→流失客户 | 自动归档+高价值客户分配挽回任务单 | 团队长→客户经理 |
| 流失/沉睡→回流客户 | 自动发送"回流欢迎+现状回顾" | 系统自动化 |

## 四、第二层：服务模型

### 4.1 服务模型A：自动化信息服务

**定位：** 由系统全自动执行，无需人工介入，覆盖全部客户。

| 服务项 | 触发条件 | 内容来源 | 发送渠道 | 发送对象 |
|--------|---------|---------|---------|---------|
| 每日市场早报 | 交易日早8:30 | 市场数据+研报摘要 | APP推送/短信 | 全部客户 |
| 持仓异动提醒 | 持仓个股涨跌幅≥5% | 实时行情数据 | APP推送 | 持仓客户 |
| 重大事件提醒 | 持仓个股发布财报/公告 | 公告数据+AI摘要 | APP推送 | 持仓客户 |
| 账户月报 | 每月1日 | 账户数据+AI分析 | APP消息 | 全部客户 |
| 风险等级变化通知 | 风险测评结果变化 | 测评系统 | APP消息+短信 | 对应客户 |
| 产品到期提醒 | 持有产品到期前7天 | 产品数据 | APP消息+短信 | 持仓客户 |
| 生日/节日关怀 | 系统日期匹配 | 模板消息 | 短信/企微 | 对应客户 |

### 4.2 服务模型B：自动化产品匹配服务

**定位：** 基于客户分析模型标签，系统自动推荐匹配产品，客户自助决策。

| 匹配类型 | 触发条件 | 推荐逻辑 | 客户操作 | 合规边界 |
|---------|---------|---------|---------|---------|
| 新客首单推荐 | 新客开户7天内 | 低风险产品（货基/短债）优先 | 客户自助购买 | 仅限R1-R2产品 |
| 存量配置建议 | 每季度+客户资产变化超20% | 基于资金体量+交易倾向+当前状态 | 客户自助查看，一键购买 | 严格适当性匹配 |
| 亏损修复产品推荐 | 当前状态=深度亏损 | 固收+/低波产品为主 | 客户自助查看 | 禁止承诺保本保收益 |
| 高客专属产品 | 资金体量=S级 | 私募/专户/定制产品 | 预约+客户经理确认 | 必须人工确认 |

**合规要求：**
- 所有自动化推荐必须标注"AI生成，仅供参考，投资有风险"
- 涉及高风险产品（R4-R5）的推荐，必须转人工确认后才能触达客户
- 禁止自动化推荐具体个股

### 4.3 服务模型C：人工叠加服务标准

**定位：** 由模型触发任务单，客户经理执行，覆盖20%重点客户。

| 服务类型 | 触发条件 | 任务单内容 | 执行标准 | 时限要求 |
|---------|---------|-----------|---------|---------|
| **高价值客户定期服务** | 资金体量=S级/A级，按周期触发 | 持仓复盘+市场解读+产品配置建议 | 每季度至少1次深度沟通 | 任务单下发后7天内完成 |
| **大额亏损安抚服务** | 当前状态=深度亏损，且资产≥5万 | 情绪安抚+持仓诊断+修复方案 | 24小时内首次触达 | 触发后24小时内 |
| **沉睡客户唤醒服务** | 生命周期=沉睡，且资产≥5万 | 了解原因+推送激活方案+邀约 | 3次触达（间隔7天） | 首次触发后30天内完成 |
| **流失客户挽回服务** | 生命周期=流失，且历史最高资产≥50万 | 了解流失原因+针对性挽回方案 | 1次电话+1次面谈（如接受） | 分配后14天内完成 |
| **产品配置沟通服务** | 客户点击高客专属产品/复杂产品 | 适当性确认+风险揭示+方案讲解 | 双录合规+客户签署确认 | 客户预约后3天内 |
| **投诉与异常处理** | 客户投诉/系统标记异常 | 核实情况+处理方案+反馈客户 | 投诉24小时内响应 | 触发后24小时内 |

**任务单格式：**

```
任务单编号：XXXX
客户姓名：XXX
客户标签：资金体量=A级 / 交易倾向=低频长期型 / 当前状态=深度亏损 / 生命周期=活跃客户
触发原因：近3个月收益率=-22%，持仓集中度=集中型（单一标的占比65%）
任务类型：大额亏损安抚服务
优先级：高
执行人：客户经理XXX
执行步骤：
  1. 调取客户分析报告（时限：任务下发后2小时内）
  2. 准备沟通要点（时限：任务下发后4小时内）
  3. 执行首次触达（时限：任务下发后24小时内）
  4. 记录触达结果（时限：触达后2小时内）
沟通要点：
  - 客观展示亏损归因（市场因素60%+集中度风险40%）
  - 推送持仓诊断报告
  - 提供资产修复方案（分散配置+定投计划）
  - 标准风险提示（禁止承诺回本）
输出要求：触达记录+客户反馈+后续计划
```

### 4.4 服务模型D：团队管理服务

**定位：** 为团队长提供团队级数据穿透和管理工具。

| 管理项 | 内容 | 频次 | 输出形式 |
|--------|------|------|---------|
| 团队客户健康度看板 | 客户分层分布+生命周期变化+异常客户清单 | 实时 | 工作台仪表盘 |
| 客户经理工作量统计 | 任务单完成率+触达次数+客户满意度 | 每周 | 周报 |
| 团队业绩归因分析 | 创收构成+客户价值变化+产品渗透率 | 每月 | 月报 |
| 高风险客户预警清单 | 深度亏损+沉睡+流失预警客户汇总 | 实时 | 实时预警 |
| 服务质量抽查 | 随机抽取录音/记录，评估合规与质量 | 每月 | 抽查报告 |

## 五、第三层：动作模型（七事件格式）

### 5.1 动作模型1：客户触达动作

```
事件名称：客户触达
  触发条件：
    - 条件A：模型触发任务单（高优先级）
    - 条件B：周期性触达计划（中优先级）
    - 条件C：客户主动发起（最高优先级）
  执行步骤：
    1. 调取客户分析标签（工具：客户分析系统 / 时限：触达前30分钟）
    2. 确认沟通要点（工具：沟通要点模板 / 时限：触达前15分钟）
    3. 选择触达渠道（工具：企微/电话/面谈 / 决策依据：客户偏好标签）
    4. 执行触达（工具：对应渠道 / 时限：按任务单要求）
    5. 记录触达结果（工具：CRM系统 / 时限：触达后2小时）
  输出标准：触达记录包含-时间/渠道/时长/核心内容/客户反馈/下一步计划
  异常处理：
    - 客户拒接→3日后二次触达（换渠道）
    - 客户转户意向→标记流失预警，升级团队长
    - 客户投诉→触发投诉处理动作
  时限要求：按任务单要求（紧急24小时/常规72小时）
  验收标准：系统留痕完整+客户反馈已记录+下一步计划已明确
```

### 5.2 动作模型2：持仓复盘动作

```
事件名称：持仓复盘
  触发条件：
    - 条件A：定期复盘（每季度/客户资产变化超20%）
    - 条件B：客户主动要求
    - 条件C：当前状态=深度亏损，触发安抚任务单
  执行步骤：
    1. 调取持仓全景数据（工具：账户系统 / 时限：30分钟）
    2. AI生成持仓分析报告（工具：分析模型 / 时限：10分钟）
    3. 客户经理解读报告核心结论（工具：面谈/电话 / 时限：60分钟）
    4. 确认客户意向并记录（工具：CRM系统 / 时限：复盘后2小时）
  输出标准：持仓复盘报告（含结构分析+盈亏归因+集中度风险+配置建议）
  异常处理：
    - 客户拒绝调仓→记录原因，设置下次跟进时间
    - 客户要求立即大额调仓→校验适当性+双录确认
  时限要求：触发后48小时内完成复盘
  验收标准：报告已推送+客户已确认收到+反馈已记录
```

### 5.3 动作模型3：产品配置动作

```
事件名称：产品配置
  触发条件：
    - 条件A：客户分析模型标签变化，自动触发产品匹配
    - 条件B：客户主动表达配置需求
    - 条件C：持仓复盘后建议配置调整
  执行步骤：
    1. 读取客户风险等级与适当性（工具：适当性系统 / 时限：5分钟）
    2. AI生成产品配置方案（工具：产品匹配模型 / 时限：10分钟）
    3. 客户经理审核方案（工具：工作台 / 时限：30分钟）
    4. 向客户讲解方案与风险揭示（工具：面谈/电话+双录 / 时限：60分钟）
    5. 客户确认与下单（工具：交易系统 / 时限：客户确认后即时）
  输出标准：配置方案书+风险揭示书+客户确认记录
  异常处理：
    - 客户风险等级与产品不匹配→拒绝推荐，引导重新测评
    - 客户犹豫不决策→设置跟进计划，7日内再次触达
  时限要求：触发后72小时内完成方案讲解
  验收标准：适当性匹配合规率100%+双录完整+客户确认已归档
```

## 六、自动化与人工叠加的边界设计

### 6.1 自动化服务清单（无需人工）

| 服务项 | 覆盖客群 | 触发条件 | 输出渠道 |
|--------|---------|---------|---------|
| 客户标签自动更新 | 全部客户 | 数据变化（交易/资产/收益） | 系统后台 |
| 市场信息推送 | 全部客户 | 固定周期/事件触发 | APP/短信 |
| 持仓异动提醒 | 持仓客户 | 持仓标的波动达标 | APP推送 |
| 标准化投后报告 | 全部客户 | 固定周期 | APP消息 |
| 沉睡自动唤醒 | 沉睡客户 | 进入沉睡状态 | APP/短信 |
| 基础产品匹配推荐 | 全部客户 | 标签变化/周期触发 | APP消息 |

### 6.2 人工叠加触发条件（必须客户经理介入）

| 触发条件 | 优先级 | 任务单类型 | 响应时限 |
|---------|--------|-----------|---------|
| 资金体量=S级，任意状态变化 | 最高 | 专属服务任务单 | 24小时 |
| 当前状态=深度亏损，资产≥5万 | 高 | 安抚任务单 | 24小时 |
| 生命周期=流失，历史最高资产≥50万 | 高 | 挽回任务单 | 48小时 |
| 客户主动投诉 | 最高 | 投诉处理任务单 | 24小时 |
| 产品配置涉及R4-R5产品 | 高 | 人工确认任务单 | 72小时 |
| 客户提及转户/销户 | 高 | 流失预警任务单 | 24小时 |
| 持仓集中度>50%且标的跌幅>10% | 中 | 风险提示任务单 | 48小时 |
| 生命周期=新客，开户7天未入金 | 中 | 新客跟进任务单 | 72小时 |

### 6.3 三句话法合规节点

| 服务类型 | 判断 | 智能体动作 | 人工介入要求 |
|---------|------|-----------|------------|
| 自动化信息推送 | 可以 | 全自动执行 | 无需人工 |
| 标准化产品推荐（R1-R2） | 可以 | 自动推荐，客户自助决策 | 无需人工 |
| 高风险产品推荐（R4-R5） | 必须确认 | 生成推荐方案→人工审核→客户触达 | 客户经理必须审核 |
| 资产配置方案 | 必须确认 | AI生成方案→人工审核→双录确认→执行 | 客户经理必须审核 |
| 投资建议/个股推荐 | 不 | 直接拒绝，标记原因 | 升级合规处理 |
| 承诺保本保收益 | 不 | 直接拒绝，标记原因 | 升级合规处理 |
| 客户投诉处理 | 必须确认 | 记录投诉→分配人工→处理结果归档 | 必须人工处理 |

## 七、与v3.0的核心变化对照

| 维度 | v3.0 | v4.0 |
|------|------|------|
| **模型体系** | 五大模型（按业务目标分） | 三层模型（客户分析/服务/动作） |
| **角色定义** | 无明确角色 | 三类角色：投资者/客户经理/团队长 |
| **客户分析维度** | 28个分类（堆砌） | 4个本质维度（资金/交易/状态/生命周期） |
| **服务方式** | 未区分自动化与人工 | 80%自动化+20%人工叠加 |
| **新客发展** | 时间线性流程（首日→首周→首月→首季） | 生命周期维度+对应动作模型 |
| **研究员模型** | 两轮+三轮对抗+博弈裁决（复杂） | 简化为AI生成多空摘要（简化） |
| **产业链模型** | 要求实时产业链数据（落地难） | 删除，依赖研究所研报摘要 |
| **员工动作** | 混杂能力/渠道/流程/合规 | 纯化为七事件格式动作模型 |
| **合规设计** | 仅提及"符合监管规范" | 三句话法具体节点+人工确认分级 |
| **落地导向** | 部分阈值理想化 | 按80/20原则设计，强调可执行 |
