# 技术底座平台调研报告：腾讯 / 阿里 / 字节 / Bisheng

> **调研时间**：2026-09-09  
> **调研范围**：四大技术底座平台的智能体/Agent能力、企业部署选项、开放程度  
> **数据限制**：搜索工具（Brave API）未配置，部分信息基于公开文档抓取 + 已知知识整理。标注 "【推断】" 的为基于趋势和公开信息的合理推断，非官方确认。

## 一、腾讯

### 1.1 产品矩阵

| 产品 | 定位 | 与企业底座的关系 |
|------|------|-----------------|
| **混元大模型** | 自研千亿参数大模型 | 底座核心模型层 |
| **腾讯云 TI-ONE** | 大模型训推平台（原TI平台升级版） | 模型训练/精调/部署基础设施 |
| **腾讯云 TI 平台** | 全栈AI开发服务平台（经典版） | 数据处理+训练+推理全流程 |
| **腾讯元宝** | C端AI助手应用 | 前端应用层，非底座 |
| **腾讯元器** | 智能体创作与分发平台 | 低代码Agent构建平台 |

### 1.2 智能体/Agent 能力

- **腾讯元器**：支持通过插件、工作流、知识库构建智能体，可发布到微信生态
- **混元大模型**：支持 Function Calling、多轮对话、代码生成
- **TI-ONE**：支持模型精调后部署为在线推理服务，支持流式输出
- **【推断】**：腾讯目前无公开的多智能体编排框架（Agent Teams / 智能体组网），主要停留在单Agent+工具调用阶段

### 1.3 企业部署选项

| 部署模式 | 支持情况 | 说明 |
|---------|---------|------|
| 公有云 SaaS | ✅ | 腾讯云 TI-ONE / 元器直接调用 |
| 私有化部署 | ✅ | TI 平台支持私有化部署 |
| 专属云 | ✅ | 腾讯云TI平台支持专属云 |
| 混合云 | 🟡 | 需自行架构 |

### 1.4 开放程度

- **模型 API**：混元大模型通过腾讯云 API 开放，支持多种调用方式
- **插件生态**：元器支持自定义插件，但生态相对封闭（主要服务微信生态）
- **开源**：混元部分模型（如 Hunyuan-DiT）开源，但底座框架未开源
- **数据接入**：支持 COS 对象存储等腾讯云生态数据源

### 1.5 与金融/证券场景适配度

- **TI-ONE 金融场景**：官方文档明确列出"金融"为应用场景之一
- **优势**：腾讯云在金融云领域有较深积累，合规和审计基础设施较成熟
- **劣势**：Agent 编排能力较弱，缺乏多智能体协作和企业级工作流引擎

## 二、阿里

### 2.1 产品矩阵

| 产品 | 定位 | 与企业底座的关系 |
|------|------|-----------------|
| **通义千问** | 自研大模型系列（Qwen） | 底座核心模型层 |
| **阿里云百炼** | 大模型服务平台 | 模型调用 + Agent 构建 + 应用开发 |
| **PAI（机器学习平台）** | 全托管ML平台 | 模型训练/部署基础设施 |
| **PAI-EAS** | 弹性算法服务（模型在线推理） | 推理服务托管 |
| **ModelScope（魔搭）** | 开源模型社区 | 模型开源生态 |
| **钉钉 AI 助理** | 办公场景Agent | 应用层 |

### 2.2 智能体/Agent 能力

- **百炼平台**：
  - 支持 Agent 应用构建（知识库、插件、工作流）
  - 支持多Agent协作（应用间调用）
  - 支持长流程任务处理
- **PAI-EAS**：
  - 支持 LLM 部署为在线推理服务
  - 支持流式输出（Streaming）
  - 支持 RAG 对话系统部署
- **【推断】**：阿里云在 Agent 编排方面有布局，但相比微软 AutoGen、CrewAI 等开源框架，企业级多智能体编排能力仍在发展中

### 2.3 企业部署选项

| 部署模式 | 支持情况 | 说明 |
|---------|---------|------|
| 公有云 SaaS | ✅ | 百炼 / PAI-EAS |
| 私有化部署 | ✅ | PAI 支持私有化，百炼部分能力可私有化 |
| 混合云 | 🟡 | 需结合阿里云专有云架构 |
| 开源自建 | ✅ | Qwen 模型开源，可基于开源模型自建 |

### 2.4 开放程度

- **模型开源**：通义千问（Qwen）系列全开源，社区活跃度高，ModelScope 生态丰富
- **百炼平台**：API + 控制台，支持自定义插件和知识库
- **框架开源**：部分工具开源（如 ModelScope、DashScope SDK）
- **MCP/A2A**：【推断】阿里云未明确表态支持 MCP 或 A2A 协议

### 2.5 与金融/证券场景适配度

- **RAG 能力**：PAI-EAS 官方提供"大模型RAG对话系统"场景案例，支持知识库加密
- **优势**：模型开源可私有化部署，适合金融数据敏感场景；云基础设施成熟
- **劣势**：Agent 编排和工作流能力相对基础，复杂业务逻辑编排需自建

## 三、字节跳动（火山引擎）

### 3.1 产品矩阵

| 产品 | 定位 | 与企业底座的关系 |
|------|------|-----------------|
| **豆包大模型** | 自研大模型（云雀模型） | 底座核心模型层 |
| **火山引擎** | 字节跳动企业级云服务平台 | 整体底座基础设施 |
| **扣子（Coze）** | AI 应用/智能体开发平台 | 低代码Agent构建平台 |
| **火山方舟** | 大模型服务平台 | 模型精调 + 推理服务 |

### 3.2 智能体/Agent 能力

- **扣子（Coze）**：
  - 支持工作流编排、插件开发、知识库、多Agent模式
  - 支持发布到豆包、飞书、微信、公众号等多端
  - 支持 Bot 调用 Bot（简单多Agent协作）
- **火山方舟**：
  - 支持模型精调、推理加速
  - 支持模型评估和对比
- **【推断】**：字节在 Agent 产品化方面较为激进（扣子是国内最早一批Agent平台之一），但企业级多智能体组网、复杂编排能力仍有差距

### 3.3 企业部署选项

| 部署模式 | 支持情况 | 说明 |
|---------|---------|------|
| 公有云 SaaS | ✅ | 扣子 / 火山方舟 |
| 私有化部署 | 🟡 | 火山引擎支持混合云，但Agent平台私有化程度有限 |
| 混合云 | 🟡 | 需商务沟通 |

### 3.4 开放程度

- **扣子平台**：插件生态开放，支持自定义API插件、数据库插件
- **模型 API**：豆包大模型通过火山引擎API开放
- **开源**：底座框架未开源，模型未开源（闭源）
- **生态集成**：与飞书深度集成，对外部系统集成支持有限

### 3.5 与金融/证券场景适配度

- **优势**：扣子工作流编排能力较强，适合快速原型验证；火山引擎云基础设施性能优秀
- **劣势**：模型闭源，金融合规场景下私有化部署受限；缺乏金融级审计、权限细粒度管控

## 四、Bisheng（毕昇）

### 4.1 产品定位

> **开源 LLM 应用开发平台，主攻企业场景。**  
> GitHub: https://github.com/dataelement/bisheng  
> 已有大量行业头部组织及世界500强企业在使用。

### 4.2 产品矩阵

| 模块 | 定位 |
|------|------|
| **Bisheng Workflow** | 应用编排框架（工作流引擎） |
| **Lingsight（灵思）** | 通用Agent（基于AGL框架） |
| **RAG 系统** | 知识库 + 高精度文档解析 |
| **统一模型管理** | 多模型接入与管理 |
| **Evaluation / SFT** | 模型评估与微调 |
| **Dataset Management** | 数据集管理 |
| **Enterprise System** | 企业级权限、SSO、审计 |

### 4.3 智能体/Agent 能力（**最详细，因为开源可验证**）

- **Bisheng Workflow**：
  - 独立完备的应用编排框架，一个框架覆盖各类任务（区别于同类产品分 chatflow/workflow）
  - **Human in the loop**：支持用户在Workflow执行中间干预和反馈（包括多轮对话）
  - 支持成环、并行、跑批、判断逻辑及任意自由组合
  - 支持多类型输入输出、报告生成、内容审核等复杂场景
  - 画圈成环、并列即并行、多选即批量（符合直觉的图形化编排）
- **Lingsight 灵思**：
  - 基于 AGL（Agent Guidance Language）框架
  - 将领域专家偏好、经验、业务逻辑嵌入AI
  - 具备"专家级理解"的通用Agent
- **多智能体协作**：文档明确列出"多智能体协作"为企业应用场景之一

### 4.4 企业部署选项

| 部署模式 | 支持情况 | 说明 |
|---------|---------|------|
| 私有化部署 | ✅ | Docker Compose 一键部署，官方主推 |
| 高可用部署 | ✅ | 官方提供高可用部署方案 |
| SaaS | 🟡 | 开源为主，SaaS版本有限 |

**硬件要求**：
- 最低：CPU >= 8 Core, RAM >= 32 GB
- 推荐：18虚拟核, 48G RAM
- 默认附带：ES、Milvus、Onlyoffice

### 4.5 开放程度（**四者中最高**）

- **完全开源**：GitHub 开源，Apache/MIT 类协议
- **模型接入**：支持多模型统一接入（不限定单一模型厂商）
- **插件/组件**：数百个组件、数千个参数可调
- **技术栈**：基于 LangChain + LangFlow + Unstructured + LLaMA-Factory
- **自托管**：数据完全自有，适合金融合规场景

### 4.6 企业级特性（**四者中最完整**）

- 安全审查
- 基于角色的细粒度权限管理（RBAC）
- 用户组管理
- 分组流量控制
- SSO/LDAP 集成
- 漏洞扫描修复
- 高可用部署方案
- 监控、统计

### 4.7 高精度文档解析（独特优势）

- 5年海量数据沉淀的文档解析模型
- 高精度印刷体、手写体、生僻字识别
- 表格识别、版式分析、印章识别
- **支持免费私有化部署**

### 4.8 与金融/证券场景适配度

- **明确金融场景支持**：文档审核、规范制度更新差异比对、非结构化数据治理、知识挖掘、数据分析
- **优势**：
  - 完全开源 + 私有化部署 = 数据不出域，满足金融合规
  - RBAC + SSO/LDAP = 满足金融企业身份管理
  - 高精度文档解析 = 适合招股书、研报、合同等金融文档处理
  - Human in the loop = 满足金融"必须确认"类合规要求
- **劣势**：
  - 社区驱动，商业化支持有限
  - 大规模金融生产环境的稳定性需自行验证
  - 无原生金融数据接口（需自行对接Wind/同花顺等）

## 六、关键发现与建议

### 6.1 关键发现

1. **Bisheng 是四者中唯一真正面向"企业级Agent底座"设计的开源平台**
   - 不只是模型+API，而是完整的工作流+Agent+权限+审计闭环
   - Human in the loop 机制与"三句话法"中"必须确认"档天然契合

2. **大厂平台的核心价值在模型层和云基础设施，不在Agent编排层**
   - 腾讯元器、阿里百炼、字节扣子都是"低代码Agent构建工具"
   - 它们解决的是"让业务人员快速搭一个Agent"，不是"让企业级多Agent协作组网"

3. **金融合规场景下，开源+私有化是硬性门槛**
   - 字节闭源模型直接出局
   - 腾讯/阿里的公有云Agent平台在金融核心场景难以落地
   - Bisheng 的完全私有化部署是唯一满足"数据不出域"的选择

### 6.2 引入建议

**方案 A：Bisheng 作为工作流/Agent编排层（推荐）**
- Bisheng 负责：工作流编排、多Agent协作、Human in the loop、权限审计
- 大厂负责：模型推理（可调通义/混元/豆包API或私有化部署开源模型）
- 优势：各取所长，合规风险可控

**方案 B：Bisheng 作为完整底座（需评估）**
- 直接用 Bisheng 作为底座框架
- 需自建：模型训练/精调基础设施、数据原子模型层、智能体组网协议
- 优势：完全自主可控；劣势：工程量大，社区支持有限

**方案 C：大厂底座 + 自研Agent编排（保守）**
- 基于腾讯/阿里云平台，自研Agent编排层
- 优势：云基础设施成熟；劣势：Agent层重复造轮子，且受限于平台开放度
